# 发光表面方向采样

本模块保留从世界材质缓存构造的方向混合采样，并增加与真实三角命中配对的面积光 NEE。世界 patch 更新和屏幕 gather 共用这两种估计。方向分布自身只改变抽样概率；面积样本必须与命中 Le 的权重一起调整，不能额外加一份未经配对的发光颜色。

## 信号和执行顺序

每张表面卡捕获后的 `CSBuildAnchors` 已扫描有效像素。新增的发光统计复用这次扫描：收集正发光亮度对应的世界位置范围和亮度，产生包围球与有限、非负的重要性分数。评分是近似的亮度乘面积尺度，只决定概率，不是用于照明积分的物理发光功率。发光贴图和 MPB 通过实际材质捕获进入统计；CPU 不再凭第一个 sharedMaterial 判断整个对象是否能入选。空卡、无发光和非法数据写零，旧页不能沿用旧统计。

同一 graphics queue 的顺序是：材质栅格捕获 → anchor/发光统计 → 卡 metadata ready 上传 → `CSBuildEmissiveProposals` → 世界缓存更新 → 屏幕 gather。分布构建复查卡身份、revision、owner/layout 和 ready，只接受 `identity.w == 1` 的 published 对象。warming 表示可以接受照明，但不会作为当前世界的发光源进入候选。每个相机独立持有分布；构建完成后到本帧消费者结束之间不修改它。

表面描述符为每物理卡 32 字节。分布表固定为 33 × 32 = 1,056 字节：记录 0 保存实际数量，其后最多 32 条记录保存包围球与 CDF 区间。`maxEmissiveProposals` 默认 16，范围 0–32；构建按重要性分数选择前 K 项，并按物理卡顺序稳定处理同分项。先除以最大分数再求和，避免 HDR 分数累加溢出。CDF 使用实际 float 区间宽度作为 PMF，舍入后为零的区间被移除，最后上界为 1。每次构建都清空旧表，预算 0 不保留上一帧的候选。

卡片重复捕获同一发光表面、前 K 截断或不完整材质覆盖，会影响方向分配效率。它们不授权删除余弦分支，也不授权给每个候选单独叠加光照。未入选的方向仍由余弦分支覆盖。

## 完整概率密度

从接收点看包围球时，以球心方向为轴构造平滑的 von Mises–Fisher（vMF）球面分布；接收点位于球内或数值退化时使用均匀球面分布。外部的集中度取 `kappa = 1 / max(1-cos(thetaMax), 1e-4)`，限制在 1–10,000。球的角范围控制分布宽度，不再作为突然截断的 PDF 边界。

复核曾在斜轴、极窄的均匀方向锥方案中复现单精度问题：采样得到的方向因 frame/dot 舍入落到自身 PDF 判定之外，进而错误增大混合权重。因此当前实现使用连续 vMF，并按 [Tokuyoshi 的 AMD 2025 技术报告](https://gpuopen.com/download/publications/A_Numerically_Stable_Implementation_of_the_von_Mises%E2%80%93Fisher_Distribution_on_S2.pdf) 的数学形式以平方弦长计算指数，避免 `dot(direction,axis)-1` 相消；采样保留偏离轴线的中间量计算正弦。公式独立实现，没有引入论文代码库或第三方二进制。单精度数值误差仍须量化，CPU float32 模拟不能代替显卡指令与 fast-math 验收。

设发光分支权重为 `e`，有效历史方向引导权重为 `g`，则：

```text
p_emissive(w) = sum_j [(CDFupper_j - CDFlower_j) * p_vMF_j(w)]
p(w) = (1-e)*(1-g)*cosinePDF(w)
     + (1-e)*g*guidePDF(w)
     + e*p_emissive(w)
D_sample = Li(w) * max(dot(N,w),0) / (pi*p(w))
```

这里求和包含所有重叠方向分布，不能只使用抽中的那一项。分支选择概率和采样密度必须来自同一张表。每次抽样后仍执行原来的最近屏幕/世界命中选择，求一次 `Li`；`ProxyRadiance` 和屏幕材质中的 emission 已属于该值。下半球样本保留零贡献，并计入原样本总数；不进行条件重采样。

这采用 [PBRT 第四版 §2.2.3 的 single-sample MIS 模型](https://pbr-book.org/4ed/Monte_Carlo_Integration/Improving_Efficiency)：选择一个策略后，按完整混合密度加权。该数学结论针对给定的入射光评估器；本包现有 SDF、屏幕命中、有限材质卡片、历史反馈和可选 radiance clamp 的误差不会因此消失。

`emissiveSamplingWeight` 默认 0.5，限制到 0–0.8；历史引导仍限制到 0–0.8，因此有效余弦权重至少为 0.04。无有效发光表时恢复原有两路抽样。分布重排不是照明变化，不触发新的全局 epoch 或缓存清空；真实材质/几何变化继续使用既有失效规则。配置修改仍遵循 Feature 现有设置变更处理。

世界缓存更新与屏幕 gather 使用不同的种子域标记，消除相同索引/帧号完全复用随机流的已知情况。屏幕 gather 会读取刚更新的世界缓存引导，因此不能故意重播生成该引导的同一条随机序列；域标记也不等于严格统计独立性的证明。

## 预算与验证边界

默认 384 卡增加 12 KiB 描述符，以及每相机 1,056 字节分布。描述符计入表面缓存字节预算。有效预算大于零时，候选构建每帧扫描物理卡，前 K 选择最坏为 `O(cardCapacity*K)`；权重或预算为零时只清表并提前返回。每个有效发光引导样本求完整 PDF 时最多遍历 K 个球面分布，包含指数运算。诊断中的 proposalBudget 是有效配置预算，不是回读得到的 GPU 候选数量，也不是实测 GPU 毫秒预算。主方向样本数保持原设置，后续阴影、可见性和屏幕步进成本仍可能随命中变化。

离线检查包括实际 C# 资源协调器的录制式测试、候选选择与 CDF 的独立排序/float32 数值参考、三路密度积分与相同样本数的估计对照，以及真实 HLSL 的 DXC 编译。具体结果以统一离线报告及其源码哈希为准。

Unity/GPU 必须另外检查：发光贴图和动态 MPB、关灯后描述符清零、页复用、HLOD 新旧表示切换、候选数量切换、同队列栅格/UAV/SRV 顺序、多相机隔离，以及小亮面、被遮挡发光面、接收点位于包围球内时的图像与成本。亮度均值应与关闭本功能的高采样参考一致；方差和 GPU 时间须分别测量，不能把 CPU 数值夹具的方差改善当作实际帧率收益。

## 精确三角面积样本

`HybridLumenGIAreaEmission` 从同一份已准备三角顶点和实例变换构建世界面积 CDF，保留 owner、stable ID、owner/geometry revision、instance、submesh、primitive 和材质批次代次。它不使用 CPU 平均发光颜色代替实际 UV 材质。默认最多 16,384 个候选，可设零关闭；容量未选中的三角保留原方向估计。

每个方向样本配一个独立面积样本，即使方向落在接收半球之外也不省略面积样本。令完整方向混合密度为 `pB`、同一带偏移射线起点处的面积转立体角密度为 `pL`，两项为：

```text
direction Le weight = pB / (pB + pL)
area contribution   = Le * receiverCosine / (pi * (pB + pL))
```

方向命中中的反射/direct/cache 部分保持原权重，只配对 Le。采样点继续使用真实 UV、纹理、Cull、alpha 和最近遮挡查询；面积点落入透明孔或被遮挡时计零，不能重采样。材质、数值或身份未知会拒绝本次估计。开启面积配对时关闭独立方向 luminance clamp，避免非线性操作破坏两项的积分关系。

DXR 与精确软件三角路径共用来源属性和材质求值。软件 BVH 接纳某个 owner 后用其完整三角集合替代该 owner 的 SDF 命中；准备不完整则整表退回 SDF。SDF/解析命中不猜 primitive，光 PDF 为零。屏幕路径仍使用相同最近命中判定：屏幕命中胜出时方向 Le 保持原权重，对应面积项为零，从而避免重复计能。

新增专项执行实际 C# CDF/BVH 构建和 HLSL 的面积 PDF、MIS、stackless BVH/三角求交，并使用独立积分与几何参考。它们不构成完整 Unity 材质、屏幕可见性、DXR 或帧图执行证据；最终统一报告只在源码冻结后生成。
