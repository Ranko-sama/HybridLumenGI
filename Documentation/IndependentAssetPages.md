# Independent asset pages

This is an implemented Unity runtime path, separate from the existing optional additive-scene driver. It uses local `AssetBundle.LoadFromFileAsync` and typed `LoadAssetAsync` requests for mesh, mesh-SDF, surface-chart, material and texture pages. It does not require Addressables. Development and validation run locally; see [DevelopmentProgress.md](DevelopmentProgress.md) for the recorded runtime evidence and remaining acceptance boundaries.

AssetBundle pages and GPU hit-material texture pages are separate layers. The first owns file IO and loaded Unity objects; `HybridLumenGIRayTexturePool` owns reusable GPU texture data, progressive copy admission and pending GPU readers. An asset page is not released merely because its file IO or a material-copy command finished. The renderer feature's default retirement registration connects the two layers; applications do not need to manufacture unload acknowledgements for the exported rig. The older additive-scene loader still has its separate explicit application acknowledgement.

## Build and use

Export from the authoring MeshRenderer before Unity combines it into a static batch. A static editor flag alone is fine. In Unity 6000.0.85f1 page export rejected an actual combined renderer. [Local Editor result](<I:/Unity test/Comparison/ExportGeometry110/result.json>)

A static URP Lit renderer can supply its base texture coordinates through `additionalVertexStreams`. The exporter accepts one readable two-component Float32 UV0 override per source vertex on a readable mesh. It copies the mesh for that renderer, rebuilds the chart capture mesh with the effective UVs, and reuses the baked distance texture because the geometry is unchanged. Each existing SDF and chart asset must match the base mesh. In a unified sample, the far aggregate takes the same UVs as the near pages. The source mesh, extra stream and authoring scene keep their own bindings.

For an additional stream containing positions, normals, other vertex attributes, or a different vertex layout, merge the intended streams into an authoring mesh and rebake its dependent assets before exporting.

In Unity 6000.0.85f1, the base UV at the centre of a White receiver triangle selected a blue texel with RGB (20, 65, 210). With the UV0 override, the same triangle selected red (225, 35, 12) on both the rendered mesh and its chart capture mesh. These reads came from reopened standalone pages, unified near-detail pages and the unified far aggregate. The sibling renderer sharing the original mesh kept its own UVs. These are texture reads from the built bundles. [Triangle, texels and source bindings](../LocalComparison/Review/static-uv0-export.json)

1. In the local Unity project, select the authored static MeshRenderer proxies, including their HLOD parents. Bake their mesh SDF and surface charts using the existing tools when required. Each mesh must have one non-null material per submesh. Static ordinary opaque URP Lit overrides can be captured from Renderer or material-slot MaterialPropertyBlocks into independent per-slot material assets; see the scope below. Applications may still apply runtime MPBs after page binding.
2. Run **Tools → Hybrid Lumen GI → Export Selected Proxies As Asset Pages**. The exporter builds LZ4 bundles for the active Unity build target into a new `Assets/StreamingAssets/HybridLumenGIAssetPages/<unique run>/` folder and saves a manifest under `Assets/HybridLumenGIAssetPages/<unique run>/Manifest.asset`. Existing authored assets are preserved.
3. An inactive independent rig is created. Its hierarchy reproduces the source transforms, including nonuniform parent scaling, but its renderer mesh/material/SDF/chart bindings start empty. Disable the original representations, enable the new rig and enter Play Mode. Preserve the project's existing baked lighting data if copying baked lightmap assignments; static-batch geometry/root bindings are not copied into the independently streamed renderer.
4. Keep only one asset-page driver active. To switch exported rigs, disable the old rig, then enable the next one. The new driver waits for the old driver's I/O and reader leases to drain. Use `SetBudgets` or the Inspector to configure file admission, concurrency, resident logical bytes and upload admission. Set representation load/unload distances for the GI near/far range. The export defaults are 200/240 units for aggregates and 60/90 for details.
5. Ship the generated StreamingAssets bundles with the Player. Rebuild for a different target or changed asset contents. The runtime validates exact file size and the bundle CRC. This provider expects local filesystem StreamingAssets (the current Windows/DX12 integration); Android APK URLs, WebGL/network delivery require a different provider.

The runtime manifest stores page identities/paths/costs/dependencies without direct references to the full original resource graph. The exporter clones each referenced resource into a separately addressable asset, remaps mesh/SDF/chart/material texture references, and derives the page dependency graph from Unity's actual bundle build. Material cloning preserves authored keywords, texture scale/offset and material properties. The exported rig targets authored static MeshRenderer sources, including opaque alpha-clipped materials admitted by the exact tracing path. `HybridLumenGIDeformedMesh` supplies runtime skinning/readable snapshots separately; exporting this rig does not serialize an animation or add general deformation-aware history. Runtime-generated RenderTextures are not serialized as authored file pages; their existing GPU material path remains separate. Each SDF texture is a whole resource page, not sparse on-disk brick streaming.

### Static URP Lit overrides

The static override snapshot covers the fixed inputs in [HybridLumenGIMaterialSource](../Runtime/HybridLumenGIMaterialSource.cs): its captured scalar properties, `_BaseColor`, `_SpecColor`, `_EmissionColor`, supported maps, and `_BaseMap_ST`/`_DetailAlbedoMap_ST`. A nonempty material-slot block replaces the whole Renderer block, preserving Unity's precedence. Slots sharing one source material can therefore export different material pages without changing the source material or Renderer. Override textures enter the existing dependency graph.

Non-HDR shader-space colors are converted to Material authoring space for the current project color space; HDR shader-space values and alpha are retained. Keywords and raster state remain those of the source Material: an MPB `_Cull` does not change the exported Cull mode. The material inputs present at export time are saved; subsequent MPB changes require re-export or application-side updates after binding.

This exports the fixed material inputs, not the MPB object or arbitrary custom properties, arrays, buffers, globals, animation, or a general ShaderGraph state. A non-URP-Lit/transparent source with MPBs, incompatible captured value types, and RenderTexture page inputs are rejected before output creation. The aggregate-generation sample retains its separate input restrictions. [The actual export/reload result](../LocalComparison/Review/asset-page-mpb-persistence-01/result.md) covers the saved slot mappings, texture/ST values, native color inputs and source preservation; it is not full Lit rendering or GI quality acceptance.

## Additional distance-demand viewpoints

Each representation retains its existing explicit `observer`, falling back to `Camera.main`. Its default-empty **Additional Observers** field adds application-selected viewpoints to that input. Use `representation.SetAdditionalObservers(auxiliaryCamera.transform)` to enable cold loading near a secondary view while the primary view is far away. The application decides which views should demand residency; the component does not enumerate cameras or infer camera eligibility.

The setter copies the array, retaining live Transform references. Call it when membership changes; moving those transforms needs no repeated setter call. Null/empty clears only the additional viewpoints. Destroyed/null transforms are ignored; if no valid viewpoint remains, the previous wanted state is retained, matching legacy behavior. Distance is the minimum distance to the representation's world bounds across the legacy and additional points, with the existing group load/unload hysteresis. `SetWanted` still overrides distance demand until `UseDistanceRequests` is called.

All views share one complete page-group request and the same budgets. When every valid point moves outside the unload range, an unbound representation withdraws its request; a bound representation only requests unloading. Its bindings and leases remain until the existing consumer and completion gates authorize retirement. Additional viewpoints do not create separate ownership or unload acknowledgements. This API applies to independent asset-page representations; the optional additive-scene loader is unchanged.

## Publication and lifetime

- `HybridLumenGIAssetPageStreaming` owns non-cancellable native request handles until actual completion. Cancelling demand never drops a pending operation. Load failures retry with backoff; failed/unknown release completion retains its reservation. Generations never wrap into reused page identities.
- New bundle and asset loads require live demand for the page or a parent that depends on it. A dependency held solely by a pending operation or retirement keeps its existing reservation until safe release. Another live group can still request that dependency. [Controlled scheduling comparison](../LocalComparison/Review/withdrawn-dependency-io-256/result.md)
- The driver admits complete representation groups and their shared dependency closures before starting IO. Existing, pending and retiring reservations count against the limit. This prevents two partial mesh groups from consuming all space before either can load its material pages. Shared dependencies are charged once; waiting groups gain age priority.
- `HybridLumenGIStreamedRepresentation` acquires all required page leases, verifies types/source mesh identity/submesh slots and binds the entire group on the main thread. Loaded resources begin ordinary GI warming; loading never claims that a surface atlas, SDF atlas or HLOD is ready.
- For an authored HLOD tree in the default exported rig, enabled bindings identify the full leaf set across staggered loads. Each eligible Base camera in range shows its own latest complete GI publication in ordinary URP rendering. A complete old set can stay visible while a replacement warms. The first cull beyond the GI far boundary hides that camera's old group, even if its pages are still bound. At cull, selected bindings must also match their prepared instances and generations and still belong to the current authored set. A newly completed publication can appear at the next cull for that camera. [Group publication contract](HlodStreaming.md#atomic-hlod-transactions)
- In an automatically managed HLOD tree, a binding with both an available parent and a declared child keeps its place in the tree and yields automatic page demand. This leaves residency for the root and leaves. A resident intermediate withdraws through the existing consumer and retirement gates. Distance demand resumes when a topology update makes it a root or leaf. Explicit `SetWanted` and application-managed raster visibility use their own demand rules. [Controlled binding and retirement sequence](../Tests/StandaloneStreamedRepresentation/Program.cs.txt)
- `HybridLumenGIResourceRetirement.Register(Func<HybridLumenGIProxy,bool>)` aggregates the renderer feature's active camera scenes. A requested unload waits while an eligible camera has that proxy published or warming; an inactive feature no longer retains obsolete scene ownership through its callback. A camera that changes from Base to Overlay also stops retaining its old GI scene, matching pass admission; URP Scene View retains its forced-Base semantics. See the [bounded eligibility fix](../LocalComparison/Review/overlay-camera-page-retention-01/result.md). Once no consumer needs it, `ReportUnloadSafe(Generation, ICompletion)` detaches the renderer and proxy. Disabled/destroyed representations are also retained in the retirement registry until safe completion. This eligibility check does not bypass final-context completion or release another camera's live pages.
- A Base camera that switches URP renderers stops retaining pages from its previously prepared renderer. A second camera using the original renderer can continue to retain them. The final withdrawal still goes through the context fence. [Two-camera DX12 observation](../LocalComparison/Review/renderer-switch-retirement-152/result.md)
- Ordinary demand withdrawal uses `endContextRendering` when rendering continues. In a frame without that context, the frame-end idle check can detach an enabled binding once all registered consumers release it. A pending withdrawal is checked again if a consumer leaves later. A renewed manual request protects a still-bound group before its next `Update`. Explicit disable or destroy also requests retirement at a proven idle boundary. Both context and idle paths retain leases until the submitted graphics fence completes. Unknown submissions retain ownership. [Ordinary withdrawal after the last context](../LocalComparison/Review/idle-demand-retirement-153/result.md)
- When an automatic Base camera skips GI because its screen textures exceed budget, its current pre-cull selection still retains any managed HLOD pages used by ordinary rendering. Other cameras keep their own consumer decisions. Once the last reader leaves, the existing context fence gates lease release. [Dual-camera budget rejection and re-entry](../LocalComparison/Review/screen-budget-page-retirement-284/result.md)
- Parent pages retain dependencies until native release completes. Actual texture-page retirement invalidates the material-pool source only after no parent page needs it, polls the pool's pending GPU readers/readbacks, and waits for `IsSourceReferenced` to become false. A shared texture is therefore not invalidated when only one instance leaves.
- The provider uses `AssetBundle.UnloadAsync(false)`, then explicitly unloads its owned page object after the above gates. It never forces `Unload(true)` across live consumers. A hidden main-thread pump retains an owner destroyed during asynchronous work; a replacement driver cannot silently adopt its native resources.
- A bound representation continues to update demand after the driver is destroyed. It can keep serving an active consumer and can enter ordinary retirement when demand is withdrawn. Once the former owner has drained, a new driver can initialize through the usual configuration and activation entry points. Release127 verifies this transition in the actual C# components with adapted IO and completion. [Demand withdrawal and ownership](../LocalComparison/Review/streamed-driver-withdrawal-144/release-notes.md)
- A destroyed driver has zero load allowance and a bounded release allowance, including when its live start budget was paused. Earlier operations and consumer tickets still complete through the existing gates. The Release131 C# regression uses `startsPerStep=0` and an outstanding bundle request with adapted IO and completion. [Paused driver regression and delivery](../LocalComparison/Review/paused-page-driver-148/release-notes.md)
- A disabled driver uses the same release allowance and suspends its outstanding demand. If a bound representation still needs a lease, it keeps that lease until the existing withdrawal and completion gates allow release. A successor waits until the previous driver's page accounting has drained. Re-enabling the original driver after the successor's drain restores its request admission. [Sequential rig switch](../LocalComparison/Review/sequential-page-drivers-283/result.md)
- `Retire(Action destroyOwned, ICompletion prerequisite = null)` provides the same final-context fence for replaced owned snapshots. Call it only after removing the old object from all future readers. External consumers of loaded objects must retain their own page lease until their completion ticket passes; copying a raw Mesh/Material reference elsewhere is not an ownership transfer.

Release126 has a bounded DX12 Editor observation of the idle branch. A bound coarse representation was disabled after the last camera context returned. Its actual idle fence passed and all six page references drained, with zero new rendering contexts. The observation covers this single group and the native retirement path. In-flight use of the specific assets, other workloads and Player coverage remain separate. [Native retirement record](../LocalComparison/Review/streamed-idle-native-143/result.md)

For managed HLOD visibility, keep the Hybrid Lumen GI feature active on each participating Base camera's renderer. Include the desired viewpoints in page demand and allow enough camera states in `maxCameras`. To adopt this on a previously saved rig, re-export or call `UseHlodPublicationForRendering(true)` on every authored member before activation. Application-owned raster visibility can select `false` for the whole group. The unified sample configures its own visibility controller at generation time.

## Budget interpretation

| Control | What is reserved/admitted |
| --- | --- |
| `ioBytesPerStep`, `maxIoBytesInFlight` | Exact built file bytes when a bundle request starts and while it remains pending |
| `maxBundleBytes` | Sum of built bundle-file sizes owned by the scheduler, including pending/retiring bundles |
| `maxResidentBytes` | Declared per-resource native residency estimate, reserved before asset loading and retained until release completes |
| `uploadBytesPerStep` | Declared mesh/texture upload cost for admitted asset requests |
| `concurrentOperations`, `startsPerStep` | Outstanding native operations and attempts admitted in one pump |

Mesh cost uses observed native memory and actual vertex strides/index counts. Other resources use Unity's editor native-memory estimate. These controls do **not** measure peak driver allocation, Unity decompressor temporaries, embedded shader/native caches, allocator fragmentation, exact GPU execution time or extra copies created inside the engine. GPU texture arenas, SDF/surface atlases and RTAS have their separate existing budgets. Target GPU timing and peak memory must be measured in the local Player; there is no claim that these admission estimates constitute a hardware VRAM hard limit.

Every page stage that still needs to start must fit its IO or upload allowance. A loaded bundle can proceed with the remaining asset upload, and a ready shared page can be reused after the start allowances decrease. The complete group and dependencies still count against bundle and resident capacity. A retiring page must qualify for a fresh load before rejoining demand. HLOD staging also requires enough space for the still-used old group and the complete target group. A pending group does not authorize eviction of visible or unproven resources. Raise the appropriate admission limit or author smaller independently useful representations when a group cannot fit; the provider does not automatically subdivide a mesh/SDF/material into smaller file pages. `BudgetBlockedGroups` exposes group-level admission pressure. [Scheduler comparison](../LocalComparison/Review/exact-footprint-and-page-admission-155/result.md#收紧启动预算后的资源页准入)

During load backoff, a group with a failed required page waits to claim new capacity until the next scheduler step reaches the retry time. Its request and ordering remain available for that step. Existing reservations, including shared pages and resources held by readers, still count. The public `TryAdmitGroup` query continues to report capacity fit for future admission. [Driver and scheduler regression](../Tests/StandaloneStreamedRepresentation/Program.cs.txt)

A bundle retained after an asset load failure can retire during load backoff once it has no admitted demand or readers. Its reservation remains charged until release completes, and the next load keeps the original retry time. Release failures have their own backoff. [Controlled completion comparison](../LocalComparison/Review/shared-budget-retirement-244-245/result.md)

Admitted groups carry their existing wait-adjusted priority through to page starts. Shared pages use the highest applicable group priority, including inherited dependencies. An outstanding operation keeps its page alive while the page follows any current admitted demand. Repeated new arrivals can yield to an older request once its rank catches up and a start fits the quotas. [Driver comparison](../LocalComparison/Review/streamed-page-priority-156/result.md)

When a higher-ranked file read passes the other start checks and only lacks in-flight byte headroom, later file reads wait for pending reads to drain. Eligible asset loads can still start. The scheduler evaluates the gate each step from current demand and budgets, so a wait can temporarily leave a concurrency slot idle. [Controlled driver comparison](../LocalComparison/Review/asset-bundle-headroom-223/result.md)

The exact software triangle BVH, area-emitter table, deformation snapshots and RTAS are consumers/additional representations, not assets generated by this exporter. They retain their own geometry/work/memory budgets. Persistent software BVH buffers reuse an unchanged prepared geometry version; admitted deformation snapshots replace mesh/SDF/charts together and retire their predecessors through the same final-context coordinator. Area NEE consumes the prepared exact triangle/material identities; completion of a file page does not by itself make that page an eligible light sample. See [Implementation.md](Implementation.md) for these boundaries.
