# 本机运行修复 local-runtime-fix02

2026-10-27。基于 integration-15，限定修复默认精确软件编译超时和封闭黑室漏光。Unity 6000.0.85f1 / URP 17.0.4 / Windows DX12 / RTX 2080 Ti / Linear / 640×360。旧 ZIP/RAR 保留不变，本轮未重新打包或扩大功能范围。

## 修改

- 回收已在本机验证的 Unity 6 API 修复：renderingLayerMask 的显式 uint 转换、局部变量重名、整数纹理 LoadStore 能力检查、RenderGraph 离屏投影与抖动矩阵。
- `TraceSceneQuery` 的三个详细遍历调用点合并为单一调用点的两段循环，缓存四邻域可见性查询保留循环，不再展开四套完整遍历。保留近远场顺序、重叠、足迹和查询材质语义；没有关闭优化、提高 Unity shader timeout 或退回 SDF 来冒充默认路径成功。
- 缓存连接改从当前查询表面射向缓存锚点，两端均按几何法线偏移，并检查完整线段。独立捕获的 surface cards 会包含埋入相交墙体的点；原先从这些点向外发射会从被 Cull 的背面逃出，错误地把外部缓存亮度传入室内。修复保留 Cull、alpha、重要性采样和多次反弹。

实际 GPU 读回中，屋顶内面 card93/patch1 的锚点为 `(11.971396, 4, -2.0143013)`，位于左墙 `x=[11.85,12.15]` 内，却有约 `(0.7403,0.7472,0.7404)` 的缓存值。反向连接会先遇到墙体正面。一次 `bounceFeedback=0` 诊断把黑室变黑，用于缩小排查范围；正式结果恢复 `bounceFeedback=1`，未靠关闭反弹交付。

默认精确 `CSTrace` 与 `CSUpdateCache` 均在 Unity 成功编译，输出约2.25MB和0.81MB。前者此前触发约10分钟编译超时；后者此前约3.92MB。本轮修复后首次目标相机 receipt 在约249秒到达，随后完成序列。这是编译及驱动初始化的启动成本，不是单帧 GPU 时间。

仅扩展并运行已有 `Tests/transport-normal-reference.mjs` 中的定向回归，覆盖埋入锚点、正反连接、无遮挡连接和末端薄壁；未重跑整套离线验证。Astra Max 对编译循环与缓存连接改写进行了只读增量审查，未发现语义阻断。
