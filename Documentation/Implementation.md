# HybridLumenGI — integration and implementation

This is an experimental Unity 6 / URP 17 source candidate. It is not a production-certified or feature-equivalent replacement for UE5 Lumen. The current machine has no Unity Editor; engine compilation, Unity GPU execution and rendered acceptance remain unverified. See [ProductionPlan.md](ProductionPlan.md) for the architecture and release gates, and [FriendHandoff.md](FriendHandoff.md) for the import handoff. Use the unified verification report and package source hashes to identify the exact tested candidate.

The current source includes CPU source receipts, optional pixel identity and bounded object-motion history, exact software triangle tracing, area-emitter NEE/MIS, reusable GPU material texture pages, independently loaded AssetBundle resources and budgeted deformation snapshots. These are implemented paths with explicit admission/fallback rules, not evidence of production acceptance. Use the report and source hashes shipped with the candidate: historical integration-13/14 results certify only those archived sources, and working `Tests` reports may be replaced during promotion. See [OfflineValidation.md](OfflineValidation.md) and the [baseline audit](TaskBaselineAudit-2026-10-27.md) for evidence and task scope. A friend-test candidate is distinct from successful Unity import/Player execution and final production release. WARP helpers and recorded Unity adapters do not render the Unity scene.

## Import

Copy the folder into `Assets/HybridLumenGI` in an existing Unity 6 URP project. This research build requires **DX12, Linear color space and Render Graph**; other graphics APIs are explicitly disabled. Standalone FXC validation exposed a compiler issue, so DX11 compatibility is not claimed; compute shaders request DXC. Add `HybridLumenGIRendererFeature` to the active Universal Renderer Data once. Its shader resources load automatically. The feature requests depth, normals and motion vectors; it no longer samples the opaque scene color, so Opaque Texture is not required by this feature.

Only base Game cameras and optionally Scene View cameras run it. Overlay cameras, stereo/XR and texture-array targets are skipped. This is an explicit unsupported boundary, not validated XR support. Histories and scene/cache resources belong to each camera and are evicted when inactive or when the camera count cap is reached.

Use the feature's material layer mask to include standard opaque URP Lit materials. Custom Shader Graph, displacement, terrain and decal semantics need their own surface capture path. The override shader's original-material keyword propagation must be checked in the actual Editor and Player. Do not assume a matching shader tag proves material compatibility.

The default **Additive** composite multiplies filtered indirect irradiance by captured diffuse reflectance and material occlusion. Existing native diffuse GI remains, so ambient/probe lighting and lightmaps can double-count illumination. For a controlled additive measurement, disable those contributions, other GI systems and exposure changes.

The opt-in **Replace Native Diffuse GI** mode captures the native diffuse term and applies a signed HDR delta, including native indirect AO and fog transmittance. It requires an ordinary Universal Renderer in Forward/Forward+, a signed floating-point camera target, MSAA off and selected opaque materials using the exact `Universal Render Pipeline/Lit` shader. The feature rechecks ordinary Renderer components every camera/frame; this is a real CPU scan and allocation cost. Failure of the camera qualification skips the HLGI pass and preserves native lighting. APV, Subtractive, transparent and debug-override shader paths invalidate capture; unsupported pixels keep the original result. Deferred, Complex Lit, Shader Graph, Terrain, BRG/DOTS and custom rendering are outside this replacement contract.

Replacement keeps native realtime direct, reflection/specular, emission and fog color, but lightmaps can contain baked direct illumination inseparable from the removed diffuse term. It cannot promise to preserve that baked direct contribution. An intensity of zero in replacement mode removes the captured native diffuse term; it is not an off switch. Source-material local keywords, property blocks, lightmap/probe bindings and SSAO/decal ordering still require Unity parity tests. See [NativeDiffuseComposition.md](NativeDiffuseComposition.md) for the bounded support matrix and pinned URP source audit.

## Scene representation

Finite mesh-SDF queries distinguish a completed miss from an unfinished interval. Exhaustion inside that interval carries a local unresolved record with a conservative domain-entry lower bound, not an invented intersection or surface identity. It cannot authorize known visibility, environment radiance or a farther surface; a proven nearer surface may still win. Unknown cache connections invalidate the numeric interpolation instead of dropping that tap and reweighting others; pure guide use may return no guide. Screen candidates equal to an unresolved lower bound do not prove they precede it. Trace budget, voxel resolution and step/bias controls remain unchanged. This is a query-completion contract, not proof of physical SDF accuracy, convergence or rendered quality; see the source-bound iteration42 evidence in [DevelopmentProgress.md](DevelopmentProgress.md).

Use **Tools > Hybrid Lumen GI > Setup & Proxies** to register relevant renderers. Each `HybridLumenGIProxy` has a stable runtime identity and revision, optional authored HLOD parent, optional mesh SDF and an analytic box/sphere fallback. Registered means eligible, not guaranteed resident: capacity and distance budgets apply.

Use **Tools > Hybrid Lumen GI > Bake Mesh Distance Field** for readable MeshFilter geometry. It produces an asset containing object-space RFloat distances at 16/32/64 cubed resolution and a versioned fingerprint of source positions/triangle indices. Closed welded topology uses signed distances; nonclosed geometry uses an explicitly approximate unsigned shell. The BVH baker supports cancellation, preserves existing assets and rejects geometry changed during baking. **Existing SDF assets without the fingerprint require rebaking to a new asset path.** Runtime rejects mismatching or unreadable source geometry instead of trusting the Mesh reference; retain Read/Write on the source mesh. Instance transforms reuse asset voxels. Dynamic sources can use the explicit snapshot component described below; an authored SDF does not automatically deform with its mesh.

Call `MarkDirty()` on the main thread after in-place vertex/index edits even when bounds/count are unchanged. It notifies all active proxies referencing the same Mesh, including different SDF assets and chart-only instances; each receives geometry-content and transport revision changes. Code without a proxy can call `HybridLumenGIMeshSource.NotifyGeometryChanged(mesh)`; the shared weak-key source service uses actual Mesh references and fresh version objects, not recyclable numeric IDs. SDF validation shares that version, and proxies consume an external version once at a main-thread refresh without broadcasting it again. The service itself does not inspect content. Disabled instances refresh their revision on re-enable. Scene preparation calls the idempotent `RefreshSignatureForRender()` to catch changes after `LateUpdate`, with no extra revision for an unchanged second camera. Proxy `OnValidate` only queues an atomic flag; main-thread refresh/re-enable or explicit `MarkDirty()` consumes Inspector changes, avoiding Unity API and registry access on a loading thread. Pure rigid or uniform-material changes detected during rendering affect only transport revision; queued Inspector changes remain conservative. Content changes retain their own classification when combined with motion/material changes, so the hardware path cannot mistake edited geometry for a transform-only update. These notifications invalidate content; the separate snapshot component performs deformation capture.

`HybridLumenGIDeformedMesh` captures SkinnedMeshRenderer poses with `BakeMesh`, or readable producer snapshots supplied through `RequestCapture`. Copied arrays feed background SDF/chart work; a complete immutable mesh/SDF/chart snapshot is published together. Proxy, surface cache, SDF validation and exact software/DXR geometry use the same `GetSourceMesh` identity. Capture vertex quota, worker count, upload admission and shared logical memory reservation are independent; cancelled workers and old snapshots retain their charges until they actually complete or retire. Failed capture attempts still consume their frame quota and retry interval. New requests supersede pending generations, and publication failure retains the previous snapshot. Replaced resources use the final-context retirement fence. The visible renderer keeps its original source. Snapshot cadence can lag animation; GPU/custom vertex-buffer writes require an explicitly supplied readable snapshot, authored HLOD aggregates are not regenerated, and this path does not add general deformation-aware screen-history reprojection.

The runtime SDF atlas shares volume data between instances, enforces voxel capacity/upload limits and provides software intersection with a conservative sampling error. Missing/pending/over-budget or rejected source assets use analytic fallback; a configured rejected SDF does not pass HLOD SDF readiness. `rejectedSdfSources` diagnoses source-validation rejection separately from pending uploads. Source fingerprint results are cached and invalidated through a weak-key shared-Mesh token, so rigid motion does not trigger full geometry hashing. Thin features smaller than the voxel/error shell cannot be guaranteed. A stackless instance BVH rejects irrelevant bounds before actual mesh SDF or analytic intersection. Bounds alone are never a BVH hit. See [SdfAtlasResidency.md](SdfAtlasResidency.md) for migration and invalidation rules.

The optional global distance field uses two to four camera-relative toroidal clipmap levels with bounded dirty-brick updates. It stores conservative unsigned distance lower bounds for empty-space skipping beyond the near detail interval. Unknown, dirty or mismatched generations fall back to detailed tracing; the field never supplies final hit attributes. Enclosing renderer bounds clamp the lower bound, so it does not accelerate empty cavities inside those bounds. Only published instances participate. Updates, generation publication and consumers currently use the same graphics queue; async compute needs synchronization that is not implemented. See [GlobalSdf.md](GlobalSdf.md). Neither GPU performance benefit nor native command ordering has been validated on this machine.

## HLOD publication and scene loading

The scene table distinguishes absent, published and warming instances. A HLOD transaction retains the old published group while the complete target group reserves slots, uploads geometry and warms its material/lighting data. The instance BVH, hardware backend and global distance field trace only published instances. When every target member is ready, one scene update removes the old group and publishes the new group. Old and target representations must fit together during staging; insufficient instance or material-card capacity stalls the transition. Assign authored geometry/material aggregates, not solid bounding boxes around open buildings.

`HybridLumenGIHlodReadback` requests asynchronous GPU readback after cache updates and checks the actual variable card index set, per-card generations, owner layout, identity/revision, atlas, cache epoch and patch grid. Covered patches need a cache accumulation count of at least two by default. Every required baked chart must have a covered patch; the legacy six-view fallback requires only object-level nonempty coverage and makes no completeness claim. A tiny or fully alpha-clipped chart with no captured texel cannot authorize publication. Geometry/material sources are rechecked, including changes to an SDF while readback is pending. Readiness establishes initialization, not complete geometric coverage or lighting convergence. Missing readback support, persistent errors, invalid source assets or insufficient budgets leave the target warming; there is no timeout that publishes uninitialized data. Material-only edits can retain unchanged geometry, but transform/topology/manual edits immediately remove stale occluders, even if that leaves a temporary gap. Continuously changing targets may never yield a consistent ready snapshot, and detail deformation does not regenerate an authored aggregate.

Scene residency itself selects already loaded proxies. File IO is a separate, implemented **explicit manifest** path: create **Assets > Create > Hybrid Lumen GI > Scene Streaming Manifest**, add exact `Assets/.../*.unity` paths to Build Settings, and assign the asset and observer to `HybridLumenGIChunkStreamer` on a persistent bootstrap object. It uses additive `SceneManager.LoadSceneAsync` and `UnloadSceneAsync`, distance hysteresis, owned-resident and concurrency limits, per-frame start limits and failure backoff. A scene-count cap is not a byte budget. Native loads cannot be cancelled and may still incur activation spikes.

Applications must link newly loaded detail proxies to a persistent authored parent through `SetHLODParent`; the loader does not discover cross-scene HLOD membership. Before unloading, application orchestration must call `ReportUnloadSafe(id, generation, true)` after replacement publication and after **all cameras** stop depending on the chunk. This gate defaults to false and has no automatic bridge from renderer diagnostics. The driver never adopts externally loaded scenes for unloading and does not silently unload scenes when disabled or destroyed. Addressables, automatic aggregate production and disk-level sparse SDF streaming are not implemented. See [HlodStreaming.md](HlodStreaming.md) for ownership, generations and transaction details. Actual Unity scene IO and rendered transitions remain untested.

Independent asset paging is also implemented and does not require loading a whole scene. **Tools > Hybrid Lumen GI > Export Selected Proxies As Asset Pages** builds separate local LZ4 bundles for mesh, SDF, charts, material and texture resources, plus a string-only dependency manifest and an inactive streamed rig. `HybridLumenGIAssetPageStreamer` performs actual asynchronous bundle/asset IO. It admits complete representation/dependency groups against separate file, in-flight IO, resident-resource, upload and concurrency limits, retains cancelled operations until completion, and accounts for failed or pending retirement. `HybridLumenGIStreamedRepresentation` binds only complete groups; native asset readiness does not authorize HLOD publication. Unlike the optional scene loader above, its standard flow automatically consults every active renderer-feature camera before detachment and waits for an `endContextRendering` fence, followed by texture-pool retirement where needed. Whole authored SDF volumes are individually paged; this is not on-disk sparse-brick paging. The exporter is for authored static MeshRenderer rigs, while deformation snapshots are generated separately at runtime. See [IndependentAssetPages.md](IndependentAssetPages.md) for setup, ownership and budget limits.

## Lighting and cache

The transport convention is `D = E/pi`, `Lo = emission + diffuseReflectance × (Ddirect + Dindirect)`. Cosine-weighted BRDF sampling estimates D by averaging incident radiance. Current direct-light support is realtime or Mixed directional/point/spot lights, a bounded deterministic list, distance/spot attenuation and scene-representation visibility; Baked-only lights are excluded. GameObject culling and separate illumination/shadow rendering layers are supported as described below. Lights created after the current reference scan are discovered by the next rendered engine frame. Cookies, IES, Unity area-Light components and complete Mixed Lighting remain outside this light-record contract. Exact emissive mesh triangles have the separate NEE path described below.

Use **Tools > Hybrid Lumen GI > Bake Surface Charts** on a readable static MeshRenderer source. `HybridLumenGISurfaceCharts` stores deterministic connected triangle groups, source-submesh identity, projections, a source-content fingerprint and a capture mesh with one submesh per chart. The baker limits normal variation and rejects positive-area projection overlap; its advisory card budget never truncates the triangle set. Runtime capture draws only the assigned chart triangles, so other source-mesh surfaces do not hide a concave interior chart. Rigid transforms reuse the asset; changed authored vertex/index content requires rebaking and `MarkDirty()`/asset reassignment. The deformation component instead produces matching runtime charts for each admitted snapshot.

The atlas uses a bounded variable card pool, explicit owner ranges and card-index indirection. An owner receives its complete requested set or no set. A configured invalid/stale asset or unsupported chart material rejects the owner instead of silently substituting six views or dropping charts. Only an absent asset selects six orthographic first-layer views, explicitly approximate for concave interiors. Captures store texture-derived diffuse reflectance/AO, emission, positions, shading normals and quantized geometric normals. Static sources on active GameObjects can warm while disabled or force-hidden. Skinned sources need a published deformation snapshot and its matching runtime charts; static baked charts cannot follow skinning directly. Missing lookup coverage may still use the transport's instance-average fallback, but that never counts as chart coverage or HLOD readiness. See [SurfaceCache.md](SurfaceCache.md).

Each resident card has a configurable 1x1 to 4x4 irradiance patch grid (default 4x4). After each capture, a compute pass scans every patch cell for a real covered texel and stores the nearest-to-center valid anchor; an empty cell remains invalid. This removes the fixed-center miss without inventing geometry. Position/normal/page checks and short visibility rays restrict bilinear cache interpolation. Jacobi iteration reads only the old cache while writing the next cache, allowing progressive higher bounces. CPU scheduling follows explicit card owners, enforces a patch budget and reserves at least a quarter for oldest entries; dirty priorities persist until service. It schedules after material/anchor capture so moving cards can receive rays in the same frame. Changing the grid rebuilds the atlas and anchors and invalidates old readbacks.

Sampling mixes the cosine BRDF, previous-cache radiance guide and smooth emissive directional proposals. Emissive statistics come from actual GPU emission-atlas texels, including captured textures and property blocks. On the same graphics queue, capture/anchor statistics precede proposal construction, which precedes cache updates and gather. Only current, ready cards of published owners enter the proposal table; warming owners cannot become proposal sources. Every sample uses the complete mixture PDF; receiving lower-hemisphere samples contribute zero without rejection/resampling. Proposal changes alone do not invalidate lighting or advance the cache epoch. See [EmissiveSampling.md](EmissiveSampling.md) for the directional proposal design. AO affects indirect response, not direct light or emission.

Area-emitter NEE is now paired with direction sampling in both world-cache updates and screen gather. `HybridLumenGIAreaEmission` builds a bounded distribution over prepared exact emitter triangles, weighted by world area with the represented CDF interval probability. The sampled endpoint is tested through the active exact software/DXR query, including original UV material, alpha/Cull and the nearest blocker. The area PDF converts to solid angle at the same biased origin; balance MIS combines it with the complete direction-mixture PDF. Only emitted radiance is paired, so reflected/direct/cache radiance keeps its direction weight and emission is not added twice. Screen gathering applies its same screen-versus-world winner to both techniques. Capped or unlisted triangles retain direction weight one; SDF/analytic/screen endpoints are not assigned invented triangle PDFs. Unknown coverage or stale identities reject the estimate rather than masquerading as a transparent or measured-black result. The default emitter cap is 16,384 triangles; zero disables area NEE. This does not implement ReSTIR or a power-texture-optimized light tree, and rendered variance/convergence remain unmeasured.

Geometry changes supply old/new spatial domains. A changed surface or identity rejects affected history; nearby transport and changed local lights shorten history and increase update priority. Directional-light changes mark lighting globally reactive without discarding the entire multibounce solution. Material/texture/property-block changes also produce reactive domains. Cache identity/page changes still clear their own patches. A pure HLOD publication makes surrounding lighting reactive while retaining the prepared target lighting; real geometry changes remain hard invalidations. Settings, capacity and backend changes retain conservative full reset. This is bounded reactive adaptation, not a complete per-ray dependency graph: indirect lighting outside a finite change domain converges through subsequent iterations, and stale-light decay needs runtime measurement.

## Direct lighting policy

Direct lighting now uses 80-byte light records with shadow strength, GameObject culling mask, separate URP illumination/shadow rendering masks and an explicit layer-enable flag. Zero is a valid empty mask, not a feature-enable sentinel: disabling rendering layers skips that dimension while GameObject culling still applies. Illumination reads `UniversalAdditionalLightData.renderingLayers` with URP defined-layer filtering. Shadow layers read the effective native `Light.renderingLayerMask`: URP normally synchronizes the illumination/custom-shadow selection into it, but a later direct native override takes precedence. A shared light-reference scan includes inactive lights once per rendered engine frame; later cameras reread current properties, so already-known lights activated in that frame can participate. Newly created lights enter by the next rendered frame. CPU scan/allocation and per-camera packing costs require measurement.

The scene retains its 80-byte proxy record and adds a 16-byte uint policy per slot for object-layer bit, rendering mask, shadow mode and reserved zero. Pure policy changes are `ChangeKind.Lighting`, update transport identity and local lighting response, retain resident geometry and reject old HLOD receipts. They do not require DXR triangle-attribute uploads. Screen receivers add an 8-byte full-resolution `R32G32_UInt` policy target. Up to 32 disjoint, single-GameObject-layer RendererLists supply the layer index, while the shader reads the full per-draw/instance rendering mask. Native and ordinary capture use exact uint MRT outputs, with instance setup before lookup. Actual Unity binding and the extra RendererList cost remain unverified.

Shadow queries are distinct from ordinary GI/surface visibility. A light with no shadows or zero strength skips its shadow query; an occluded light is attenuated by `1 - strength`. Off casters are skipped only by shadow queries. Exact software and DXR queries filter eligible casters and material coverage before commitment, continuing past a known rejected candidate; TwoSided bypasses material Cull only for shadow rays. On/ShadowsOnly retain effective submesh Cull. SDF/analytic shadow queries support owner masks/Off but cannot reproduce exact triangle Cull or alpha holes and remain conservative. Exact-hit materials carry their receive-shadows state. Soft modes still produce hard visibility; shadowmask, full Mixed Lighting and cookie/IES are not implemented, and native receiveShadows/alpha-tested parity still needs Unity acceptance. This is not full URP Lit equivalence. See [DirectLighting.md](DirectLighting.md) for source references and required test cases. Validation is tied to each candidate's exact source hashes; Unity, Player and physical-GPU validation remain unexecuted.

## Reconstruction

The screen gather uses depth/normal/material textures and world occluders. It never feeds the already lit camera color or filtered screen history into multi-bounce transport. Screen radiance is computed from captured emission and diffuse direct response. Per-camera temporal accumulation uses motion vectors, GPU projection/jitter, previous geometry/material, confidence, neighborhood clipping and luminance moments. Invalid history is explicitly initialized to avoid propagating uninitialized NaNs. Low-resolution D is filtered with normal/depth/material/variance weights before the full-resolution bilateral resolve applies the receiver material.

History receipts now bind the full-resolution and GI dimensions, the exact finite pixel viewport, and an optional projection-convention key through `FrameContext`. Camera movement and per-frame jitter are not context changes. Even a full width change from 1920 to 1921 with GI width still 960 rejects the old source. Each camera additionally checks actual camera and render-target references, so a reused native numeric ID or a same-size replacement target cannot inherit another object's history. Repeated rendering in one engine frame, skipped frames, invalid context and failed recording start fresh; only the successfully recorded preceding engine frame is reusable.

The previous VP, inverse VP, jitter, camera position and rotation are committed together only when the current receipt completes after successful composite recording. Graph construction no longer publishes those camera fields, and stale or failed callbacks cannot overwrite them. This describes ordered command recording, not completion of GPU execution. Image allocation/read-write scheduling remains distinct from permission to reuse its contents.

Each GI texel represents one selected full-resolution depth texel. Depth, motion, reconstruction and prior-history lookup now use that full texel's exact sample center; temporal lookup chooses among actual stored centers, and bilateral upsampling derives its interpolation footprint from the same centers. This avoids treating quantized depth as if it had been sampled at an ideal low-resolution center, including odd dimensions and noninteger scale ratios. The sample-center correction itself adds no GPU textures; optional object history below has separate allocations. When no trustworthy GI sample resolves a receiver, native replacement preserves its original lighting rather than subtracting native GI as if a missing estimate were measured black.

The optional `receiverSourceTracking` setting defaults to **false**; enabling `receiverObjectHistory` also enables this CPU tracking. When either is enabled, ordinary opaque Lit MeshRenderer sources are discovered independently of proxy/GPU residency. CPU records retain actual renderer/Mesh identity, submesh, separate geometry/material generations and the observed object matrix. `receiverSourceCapacity=1024` limits submesh records, not renderer count. `receiverFingerprintBudgetMiB=16` limits logical mesh bytes for each preparation and each pre-capture revalidation separately; it is not a combined frame budget, CPU-time deadline or peak-memory cap. Shared meshes are fingerprinted once within each call. This adds scene discovery, material observations, full readable-mesh hashing and CPU allocations, potentially twice per camera render; measure these costs before enabling it at scale.

Successful source observations produce a pending per-camera snapshot. A fresh source scan and revalidation immediately before capture must match it, and publication follows successful capture/composite command recording plus completion of the exact screen-history receipt. Failed, repeated, superseded or foreign receipts cannot publish an old source snapshot. First successful mesh fingerprinting and later detected edits advance the shared Mesh version, forcing earlier SDF/chart positives to revalidate. This can detect unnotified same-count/bounds edits only for sources admitted to readable-mesh verification. Over-budget, unreadable or unsupported sources remain untracked; they retain the current GI path instead of gaining an inferred identity. Skinned, LOD membership, static batching and additional vertex streams are outside this source-identity contract.

Material source snapshots compare effective shader values, texture references/update counters and source render state. A nonempty submesh MPB replaces the renderer MPB; MPB `_Cull` does not change the source material's raster Cull. RenderTexture/CustomRenderTexture inputs are not reusable source-history evidence because GPU writes need not advance `updateCount`; they remain eligible for current material capture. Unreported Texture2D GPU/native writes, globals, probes and later render callbacks still require producer-owned invalidation. CPU receipts alone do not identify a screen pixel. The separate `receiverObjectHistory` option defaults to false and connects IdentityFrame, IdentityPass and CSTemporalIdentity. It is gated to DX12, non-XR, single-sample, full normalized viewport and the required integer/UAV formats. Frozen source coverage drives explicit submesh draws with fixed Cull passes; exact fragment/camera/capture depth equality and alpha precede a sticky atomic claim. Any second valid fragment, including the same owner, becomes a conflict. Conservative unknown rectangles, GPU DEBUG_DISPLAY and alpha-to-coverage rejection keep unsupported coverage unknown. Separate resolve stores key plus draw-local primitive at each actual GI/full sample center. Only matching f-1 receipts and identities with positive-similarity relative transforms can use predicted old position/normals; motion is used only when it agrees with pose within one full pixel per axis. A valid current Renderer group can exempt its own pure-pose change, while other occluders and strong/unknown changes remain hard rejections. Failed identity/history keeps current GI. Changing nonuniform scale, shear, reflection sign, Skinned and general deformation remain unsupported by this object-history reprojection, even when the separate deformation snapshots are available to world tracing. See [GeometryHistoryContracts.md](GeometryHistoryContracts.md) for the ABI, coverage and lifetime contract; Unity raster/ordering and image acceptance are still unverified.

Renderer-feature defaults: half resolution, 2 rays/pixel, 24 screen steps, 128 scene slots, 16 proxy uploads/frame, 384 resident cards in 32x32 tiles (30x30 interior plus border), 24 card captures/frame, 4x4 patches/card, 256 patch updates/frame with 8 rays/patch, 3 spatial iterations and 32 history frames. The feature enables four global-distance-field levels with eight bricks per axis, base voxel size 1 and 16 brick updates/frame. These are starting settings, not a measured quality/performance preset. Debug views: Final, Indirect Only, Confidence, History Acceptance and Diffuse Reflectance.

Emissive sampling defaults to weight 0.5 (range 0–0.8) and the top 16 proposals (maximum 32). Zero weight makes the effective build budget zero: the builder still clears a valid table but skips candidate selection. Proposal count is a work cap, not a measured GPU-time budget.

The screen budget may reduce internal resolution; if optional identity cannot fit at the quality floor, it disables object history and replans baseline current GI. Only a baseline allocation that also cannot fit skips the camera. Native diffuse replacement adds a full-resolution capture target and uses floating-point diffuse data. The material atlas has its own card/draw/byte limits. Static patch/ray caps remain authoritative; optional GPU feedback can reduce patch, capture and brick update quotas within those caps. GPU markers include Material capture, Global SDF dirty bricks, World material capture, Emissive proposals, World cache, Gather, Temporal, Atrous and Bilateral composite. SDF, world atlas, cache, BVH and DXR resources are additional to the screen texture budget. See the memory formula in ProductionPlan.md.

With object history disabled, the receiver-policy-inclusive baseline estimate is `24 * fullPixels + 112 * giPixels` bytes for Additive and `36 * fullPixels + 112 * giPixels` for native replacement. At 1920×1080 with 960×540 GI this is approximately 102.83 MiB and 126.56 MiB. Two RGBA32F temporal moments targets add 16 bytes/GI pixel over the previous half-float pair. Owner policy adds `16 * sceneSlotCapacity` bytes separately; the allocated 32-entry light buffer is 2,560 bytes per camera. Enabled identity adds `16 * fullPixels + 32 * giPixels + 80 * max(1, reservedRowCapacity)` bytes: full-resolution candidate/dummy, two integer histories and object rows. The independent world change-region buffer is 1,088 × 48 = 52,224 bytes. These are logical allocations, not measured driver memory or a peak-memory guarantee.

Surface metadata is 128 bytes per physical card, with separate owner ranges, card indirection, 8-byte patch anchors and 32-byte emissive descriptors. Owner ranges are four uints `(first, count, layoutGeneration, geometryRevision)`; their fourth field now verifies the current geometry version for hit lookup. The per-camera proposal table adds 33 × 32 = 1,056 bytes. The two irradiance buffers use `cardCapacity * grid² * 80 bytes * 2`, independent of proxy count. The CPU primitive-to-chart map uses 4 bytes per source primitive plus outer-array references, with a 16 MiB per-camera cap excluding CLR array headers. It is rebuilt only for verified layout/geometry changes and released on retirement; budget exhaustion leaves the exact binding unknown. Source/capture meshes and engine/driver overhead are additional. See [SurfaceCache.md](SurfaceCache.md) for the current allocation formula.

## Exact software and hardware paths

`exactSoftwareTracing=true` enables a compute triangle BVH when DXR is not selected/available. It uses the same prepared world triangle positions, original submesh/primitive identities, UV materials, coverage and Cull policy as the hardware path. Stackless bounds traversal narrows actual triangle tests; a bound alone is not an exact hit. The CPU layout and GPU node/leaf buffers persist per camera and rebuild/upload on geometry-version changes. Source/material revalidation still occurs. Triangle and software-byte budgets admit whole owners; omitted owners retain SDF/analytic fallback. Replaced buffer capacity remains charged until final-context retirement. Software traversal does not require a hardware ray-tracing-capable GPU, but the feature's current DX12/Linear/RenderGraph platform gate still applies; its speed is not established by offline correctness checks.

Enable Prefer Hardware Tracing on a DX12 device reporting inline ray query support. Admitted readable MeshRenderer sources and published deformation snapshots use actual triangle instances with original submesh/primitive identity and separate geometric/shading normals. Opaque and alpha-clipped stock Lit are admitted; candidate Cull/coverage is evaluated before commitment. Unsupported sources retain software representations with their documented limitations. Geometry tables include 128-byte instance attributes, a 64-byte prepared object transform, 80-byte normal/UV + 96-byte position/tangent + 16-byte chart binding per triangle, and 4 bytes per scene-slot flag. These attributes are separate from RTAS allocation. Preparation/build admission failures select software; actual command execution and device behavior require Unity testing.

RTAS now has shared all-camera admission for memory reservations, build count and triangle/instance work. Deferred demands accumulate bounded work credits; a request beyond the burst capacity falls back explicitly. Reservations use a prebuild estimate and retain the measured `GetSize()` high-water value when available; retired resources remain charged until their final-context destruction. These counters are not GPU milliseconds, and Unity's opaque scratch/native overhead prevents the estimate from being a proven VRAM upper bound.

Triangle-to-chart binding retains the exact card/chart/layout/geometry identity for incoming irradiance lookup. The newer query evaluates the committed UV material from immutable source records and copied textures; a card does not replace that material's reflectance, emission, AO or normal. Unknown coverage/material remains an occluder and rejects the radiance estimate. Effective keyword/MPB values are frozen per original submesh; a nonempty submesh block replaces the renderer block. Alpha-clipped admission and candidate coverage evaluation are implemented in exact software and DXR. This is not a claim of complete Unity Lit parity or successful Unity/DXR execution.

`HybridLumenGIRayTexturePool` retains independently reusable texture pages in shared GPU arenas. Ordinary Texture2D reuse requires matching frozen view/update state, validated metadata and completed readers; source invalidation revokes only affected pages. Pending/readback/quarantined capacity stays in the shared memory budget. A separate all-camera per-frame upload-byte budget allows stable pages to upload progressively; RenderTextures use fresh observations rather than inferred reuse. Supported source formats can pack row-aligned RGBA16F pairs; other layouts use float32 texels, so cost depends on format, mip layout, arena capacity and retained readers. Record `hardwareMaterialStatus`, global allocation/upload bytes and the actual backend; fallback is not successful DXR acceptance. Spatial footprints and observer views propagate through screen/card gather, near/far origin shifts and shadow connections. Full filtered-surface/angular integration remains outside the point-query material contract.

`rawNg` preserves inverse-transpose source winding without determinant or incident-ray flips. Ns retains stock Lit's authored shading direction on Cull Off/Front back faces. Bias is a separate operation toward the sampled/shadow hemisphere; a camera-facing history Ng does not force gather rays onto the wrong side of a visible back face. True chart capture uses its original geometric direction; six-view fallback relies on the default Unity DX12 raster winding plus object mirror sign, so externally un-restored invert-culling is unsupported. Signed SDF, unsigned shell and analytic hits retain their explicitly approximate material resolution; they do not acquire triangle/UV/area-PDF identity. Skinning requires the admitted immutable snapshot path; arbitrary unreadable/GPU-only geometry and unsupported APIs remain outside this exact geometry contract. No Unity or physical-GPU execution has validated this integration.

## Diagnostics, migration and validation

After rendering a supported camera, run **Tools > Hybrid Lumen GI > Validation > Log Runtime Diagnostics**, use the feature's **Log Runtime Diagnostics** context menu, or call `GetDiagnostics()`. Per-camera records expose published/warming instances, blocked staging capacity, BVH nodes, charted versus approximate owners, required cards, card readiness and warm-up capacity pressure, scheduled patches, global-field brick counts, readback outcomes, backend activity and estimated/allocated buffer bytes. Most are CPU resource and scheduling counters, not measured coverage, GPU milliseconds or visual correctness. The current diagnostics additionally report exact-software buffer bytes, area-emitter table bytes, shared material-page allocation/upload usage and RTAS admission/work state. RTAS estimated bytes and the observed `GetSize()` allocation high-water are exposed separately; the latter still does not include every driver/scratch allocation or prove a peak-memory limit. A ready-brick counter indicates work recorded for the ordered graphics stream, not a completed GPU fence.

`proposalCapacity`, `proposalBudget` and `proposalBufferBytes` report fixed capacity, effective configured budget and allocated table bytes. The budget is zero when emissive sampling is disabled; it is not a GPU-selected count. CPU distribution/integration tests and command-recording checks do not establish GPU sampling accuracy, image variance or timing.

`hardwareBindingUploads` counts triangle-binding buffer uploads; `surfaceTriangleMappingCpuBytes` reports the bounded CPU mapping payload separately from GPU resource estimates. Rigid/material-only changes should not keep uploading triangle attributes or unchanged chart bindings; layout or geometry changes must refresh the corresponding identity. Neither counter proves exact-hit coverage or successful GPU execution.

Receiver-source diagnostics add `receiverTrackedSubmeshes`, `receiverUntrackedRenderers`, `receiverFingerprintMeshes`, `receiverFingerprintBytes` and `receiverSourcesPublished`. The mesh count reports successful preparation fingerprints, and bytes report its charged logical budget; neither includes a summed preparation/revalidation frame cost. Published means an accepted CPU command-recording receipt, possibly containing only a subset of sources, not pixel coverage, GPU completion or enabled object-motion history. With both source tracking and object history off, no source snapshot is prepared and the baseline GI pipeline remains enabled.

The renderer settings schema changed from the old prototype. Review settings after importing over an old feature asset; old screen/proxy energy coefficients no longer apply. Existing shader and feature `.meta` GUIDs are retained. Do not import two copies of the source package.

Optional GPU feedback is disabled by default (`adaptiveGpuBudget=false`, `targetGpuMilliseconds=0`); the disabled path does not probe or load the timing DLL. A positive device-specific target enables bounded patch/capture/brick quotas when usable GPU samples are present. With `preferNativeGpuTiming=true`, the optional Windows x64 DX12 plugin uses 128 recyclable submission slots shared across cameras. Each submission binds an owner, configuration/device generations and source frame to six timestamps. Readback and reuse require fence completion; the final resolve runs in a separate Unsafe pass after composite, outside the native raster render pass. Only an opaque integer ID is carried by plugin events, with no movable or prematurely freed payload.

An unavailable native provider falls back to Recorder. Recorder still lacks query identity and an atomic cross-pass snapshot, and its 32 lifetime channels are not reused; exhaustion selects static quotas without stopping GI. A temporarily full native ring remains on the native provider and reports a missing observation. Provider or device-generation changes reset feedback; stale results cannot drive a new configuration or an already changed quota. Short measurement gaps retain the last quotas, while persistent gaps restore static limits.

Both providers now include the four receiver-identity passes when enabled. Native ABI1 retains three intervals and six timestamps: ReceiverCapture spans material capture through identity resolve, followed by transport and composite. Recorder uses three baseline or seven identity-enabled scopes, each paired inside its own pass callback; its sum does not include gaps between those scopes. Clear reads captureDepth and transport reads resolved identity to preserve the measured chain. A frozen per-frame coordinator rejects partial graphs, duplicate/late callbacks and stale tokens. Timing APIs, including seven diagnostic string scopes, cannot abort GI or revoke otherwise valid screen history; genuine rendering failures still do. An unknown marker-recording outcome permanently retires that Recorder channel. Ordinary source rejection does not retire the channel, and a fully executed four-pass identity chain can still be measured; canceled or incomplete graphs invalidate feedback. Actual identity-mode changes reset the budget controller. These measurements exclude CPU preparation, uploads outside the scopes, native query resolve and unmeasured driver/queue costs; they are not a hard deadline or the entire application GPU frame. Diagnostics remain distinct from resource estimates. The source package does not automatically install the DLL, and C++/WARP/mock-command tests do not establish Unity/RenderGraph or physical-GPU correctness. See [GpuBudget.md](GpuBudget.md) and [NativeGpuTiming.md](NativeGpuTiming.md).

Run **Tools > Hybrid Lumen GI > Create Validation Scene Assets** to generate a separate room test without replacing the current scene. See [Validation.md](Validation.md) for the required matrix and [OfflineValidation.md](OfflineValidation.md) for checks executed without Unity. `Tests/Validate-Offline.ps1` runs the reproducible offline suite and records source hashes with individual outcomes; use its report for the candidate's exact verification status. C# syntax checks, algorithm tests with Unity API substitutes, numerical references and selected standalone shader compilations do not establish successful Unity API compilation, shader import, Render Graph execution, image quality, scene loading behavior, GPU timing or actual memory usage.

Run **Tools > Hybrid Lumen GI > Validation > Probe CPU and GPU Color Contract** in the friend's Unity Editor. It records CPU raw/linear material values versus actual URP Lit shader input in `Logs`; use it to validate the new same-submesh constant conventions, and separately check renderer/submesh MPB color/vector behavior. This tool has not been run on the source-only machine. The candidate's unified offline result must match the current source hashes; it does not establish Unity or physical-GPU acceptance.
