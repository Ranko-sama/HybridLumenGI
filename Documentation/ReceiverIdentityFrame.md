# CPU receiver identity-frame inputs

`HybridLumenGIReceiverIdentityFrame.Build` converts a frozen receiver registry snapshot and a per-camera source-history lookup into inputs for a separate identity draw. It does not perform that draw, identify a pixel or complete GPU work. Source revalidation immediately before recording remains the caller's responsibility. The builder never reads live renderer properties, Mesh bounds or material values.

`Rows.Count` equals `source.Records.Count`; record `i` remains at row `i` even when it cannot be drawn. Each sequential row is 80 bytes: a 64-byte `currentToPrevious` matrix, followed by four uints `keyLow`, `keyHigh`, `flags`, `reserved`. The key is the greater of the record's geometry and material generation, split without float conversion. The identity shader stores `Draw.RowIndex + 1`, reserving zero for no owner; the object buffer itself has no sentinel row. Null source produces no rows/draws and a fullscreen unknown rectangle. A GPU uploader must allocate at least one buffer element while keeping the object count zero.

The ABI-compatible name `reserved` at byte offset 76 now stores the **current-frame Renderer group**. Every submesh of the same actual Renderer reference uses that renderer's first source-record index plus one; unsupported draw holes do not shift later groups. Submesh identity keys remain distinct. `GetReceiverGroup(Renderer)` reads a private, immutable reference map and returns zero for a reference not represented in the frame or for a failed frame. Numeric Unity IDs and overridden object equality do not merge references. This group is not persistent across frames, and its presence alone does not prove coverage or eligible history; the unknown mask and history flags still apply.

Read-only `Draws` retain the exact record reference, zero-based row index and frozen `IdentityCoverageData`. A renderer not fully accounted for by supported submesh records contributes an unknown rectangle for its entire frozen candidate bounds. Incomplete discovery, invalid projection or unexpected exceptions produce a fullscreen unknown mask; this failure does not authorize stopping current GI.

Bit 0 of `flags` permits previous-object reconstruction only when the source history supplies an eligible prior record and `previous * inverse(current)` is a finite affine positive similarity. Computation uses a double-precision affine inverse before storing floats. Squared column lengths may differ by at most `1e-5` of the maximum squared length, normalized pairwise column dot products by at most `1e-5`, and determinant must be positive. This is a numerical tolerance, not arbitrary nonuniform/shear support. A constant reflected, sheared or nonuniform source has identity relative motion and remains eligible. Otherwise a rejected relative transform retains its current key with bit 0 clear.

Unknown rectangles project the eight corners of frozen world bounds, expand the floor/ceil pixel extent by one pixel, and clamp to the full target. Any nonfinite projection or clip W at/below `1e-6` makes the mask fullscreen. `uvStartsAtTop` defaults to true for this DX12 target and applies the same post-projection Y flip as transport `ProjectUV`; the caller passes the real target convention. The supplied GPU view-projection must also account for any viewport-to-full-target transform. Exceeding `maxUnknownRects` (default 1,024) replaces the list with a fullscreen mask instead of dropping domains.

`MovedBounds` pairs each moved renderer's current frozen bounds with the conservative affine transform of those bounds into the prior pose, once per renderer, and retains its exact `SourceRenderer` reference. The extent calculation is equivalent to transforming all eight corners, with outward float padding. A finite relative transform can supply this domain even when its normal-history eligibility is rejected.

`HybridLumenGISdfAtlas.TransformChanges` similarly pairs each qualified pose-domain bounds entry with its captured `SourceRenderer`; the legacy `TransformChangedBounds` list remains synchronized. Old and new SDF snapshots must have the same renderer reference in addition to the existing exact source/pose-receipt checks. Renderer replacement stays a strong geometry change. Null owners remain unowned. Both lists clear on preparation/disposal. A downstream pose-history exemption must match the current receiver's nonzero group to the domain's group, so one moving object cannot exempt another object in overlapping bounds. World lighting caches still invalidate pose domains; carrying an owner does not weaken that rule.

Run `Tests/Validate-ReceiverIdentityFrame.ps1` for the actual builder's layout, indexing, frozen-data, failure, similarity and projection tests. Independent forward-point and interior-projection samples exercise randomized affine sources and perspective bounds. Unity value types and source/history producers are explicit adapters in this suite; it is not a registry, rasterization, engine compilation or GPU test. Full Unity/Player/GPU acceptance and production gates remain required.
