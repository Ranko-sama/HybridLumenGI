# World-space material cards

`HybridLumenGISurfaceCache` captures registered renderers into persistent material textures, independently of the camera attribute pass and irradiance evaluation. It supports baked triangle charts through a variable physical card pool. Objects without a chart asset retain an approximate six-direction first-layer capture. Current finite native integration evidence is indexed in [DevelopmentProgress.md](DevelopmentProgress.md); neither chart assignment nor recorded readiness certifies complete geometric coverage or production rendering.

## Baked triangle charts

Select a readable, undeformed MeshRenderer source and run **Tools > Hybrid Lumen GI > Bake Surface Charts**. `HybridLumenGISurfaceCharts` stores stable chart IDs, source submeshes, triangle ordinals, local projections/bounds, a content fingerprint and a separate capture mesh. The capture mesh preserves source vertex attributes and has one submesh containing only the assigned triangles for each chart. Runtime draws that chart submesh with its original source material, so other triangles in the original renderer cannot hide the chart's interior surface.

The deterministic baker grows connected triangles within a source submesh, limits normal variation and rejects positive-area overlap in the chart projection. It also checks the serialized float projection and splits groups when precision makes the projection invalid. Nondegenerate triangles are retained; a chart-count budget is advisory and does not truncate geometry. Degenerate triangles and unsupported nontriangle topology are reported. A bake that cannot represent a valid triangle fails instead of returning a partial asset.

The asset targets static readable MeshRenderer geometry. Rigid transforms reuse it; skinning, runtime deformation or edits to vertex/index data require a separate update contract or rebaking. The source fingerprint covers vertex streams/layout, indices, submesh descriptors and other mesh content. It is checked on admission and geometry-content revisions, not recomputed every frame. Call `MarkDirty()` after in-place mesh edits that cannot be inferred automatically. Treat the asset and capture mesh as immutable: change them through a new bake/content version. A changed source cannot safely keep using the previous capture mesh.

If a chart asset is assigned but invalid, stale, incompatible with the renderer or references an unsupported chart material, the entire owner is rejected. It does not silently fall back to six views or omit the unsupported chart. Capacity admission is also all-or-nothing per owner. Only an absent asset selects six axis-aligned views; those views cannot cover arbitrary concave interiors.

## Runtime contract

Own one cache per camera. Call `Prepare(scene, config)` before recording work. Import the five public `RTHandle` atlases into Render Graph and declare their use. Call `RecordCapture(command, restoreViewport)` on the graphics queue, before any shader that queries cards. Call `BindCompute(command, compute, kernel)` for each consuming kernel. No camera view/projection matrix is modified. Raster targets are changed internally; the caller binds its subsequent targets.

`CardCount` is physical card-pool capacity. Each card explicitly records its owner scene slot, stable chart ID, layout generation and capture generation. Per-owner ranges index an indirection table of physical card indices; indices need not be contiguous or derived from `sceneSlot`. `CardOwners[card]` is the owner slot or -1. `GetCardCount(slot)`, `GetCardIndex(slot, ordinal)` and `GetLayoutGeneration(slot)` expose the mapping. Replacing an owner/layout invalidates its metadata before page reuse. Capture generations stay within the exactly representable float-integer range because the lighting cache mirrors them in float tags.

`TryGetTriangleBinding(slot, expectedMesh, submesh, primitive, out binding)` maps an original mesh primitive to its verified chart in O(1). The 16-byte binding contains four uints: physical card index, stable chart ID, layout generation and geometry-content revision. An unknown mapping returns `cardIndex = uint.MaxValue`; six-view fallback never manufactures one. The query checks prepared owner identity/revision, mesh and asset identity, geometry version and card metadata, but deliberately leaves readiness to the GPU consumer. `GetGeometryRevision(slot)` exposes the current prepared proxy's geometry version even without resident cards. The 16-byte owner range is now `(first, count, layoutGeneration, geometryRevision)`; shaders compare `range.w` with the hit rather than accepting two matching but stale binding records.

`Prepare` never publishes a new page as GPU-ready. Runtime metadata changes use `CommandBuffer.SetBufferData`: invalidation precedes raster capture, anchor compute follows each capture, and metadata readiness follows both on the same graphics queue. Initial buffer allocation initializes invalid data separately. Do not execute capture and query on different queues without explicit synchronization. `ReadyMask` is CPU scheduling information about recorded readiness, not proof that a GPU fence completed. Resources are ordinary Unity-owned render targets/buffers and are disposed with their camera state. Changing `patchGrid` rebuilds storage, including atlas and anchor buffers, and advances the atlas generation.

If a render fails after recording, the common renderer failure exit calls `InvalidateRecordedCapture()`. It withdraws metadata/CPU readiness and advances the capture generation for every resident tile, including warming or not-yet-captured cards, restores dirty scheduling and the whole-atlas initialization clear, and leaves owner/chart/tile mapping and resources intact. Subsequent frames recapture under the existing budgets; an owner becomes recorded-ready only after all its cards do. The conservative whole-atlas clear requires invalidating all resident cards. [Iteration61](ReviewBrief-SurfaceCacheFailedRenderRecovery01.md) verifies actual CPU state and recorded command order; it does not execute a native discarded command stream or prove GPU completion.

Anchor compute also reduces valid emission-atlas texels into one 32-byte emissive descriptor per card. It uses captured GPU material values rather than a CPU first-material filter; empty or nonemissive pages write zero. `BindEmitters(command, compute, kernel)` exposes these descriptors. The per-camera proposal builder runs after capture/statistics and before transport on the same graphics queue, checks metadata validity and accepts only published owners (`identity.w == 1`). Warming cards can receive lighting but cannot supply proposals. The resulting smooth directional mixture changes sampling probabilities, adds no separate Le term and is not area-light NEE. Details and GPU validation requirements are in [EmissiveSampling.md](EmissiveSampling.md).

`ChangedBounds` is cleared by `Prepare` and accumulates old/new published-owner bounds, material or property-block changes, retirements, and scheduled captures. Warming owners (`identity.w == 2`) can populate and query their pages without adding neighboring reactive regions; their preparation must not erase the still-published HLOD illumination. Retirement of a previously published owner retains its old bounds. The caller can use these regions for neighboring lighting invalidation without a global camera reset.

Cache scheduling retains conservative global lighting dirtiness and all eligible patches. Each camera also reuses the old/new local-light change records: their existing range plus trace influence raises intersecting owners to the existing1000 dirty priority, without adding scores for overlapping ranges. `pendingPriority` retains this event until service, including absent pages and zero update budget. The oldest-service quota is unchanged; optional local bounds only affect the other priority slots. Directional lights retain global handling, and callers that omit the optional bounds retain legacy behavior. This is a scheduling preference, not a boundary on multibounce influence. Iteration48 demonstrates the finite actual-source selection change and persistence/fairness controls; no rendered quality or timing improvement is claimed.

The renderer also supplies the published surface bounds reported by capture, including previous bounds on replacement or retirement. A receiving owner's bounds within the existing surface trace radius get priority 751 for the remaining slots. A dirty source card or local light has priority 1000, and the global lighting backlog has priority 750. This order helps a nearby receiver compete with a distant one when work is scarce. The distance is a scheduling hint and applies at owner granularity. The separate oldest-service allocation still advances other ready patches.

`GetGeneration(cardIndex)` returns the current page generation, or zero for an absent/out-of-range page. A nonzero value does not establish readiness. `IsSlotReady(slot, stableId, revision)` requires a matching resident scene owner, matching CPU metadata and every card in its current mapping with matching owner/layout/identity/revision and recorded ready flags. It establishes recorded material/anchor work, not GPU execution, covered texels, valid irradiance samples or lighting convergence.

The integrated HLOD readback checks the actual irradiance buffer and snapshots the complete card index set, per-card generations, owner layout, `AtlasGeneration`, cache epoch/grid and source state. A baked-chart owner requires at least one covered patch in **every** required chart, and every covered patch must meet the configured initialization count. A legacy six-view owner requires only object-level nonempty coverage; this is explicitly weaker. Tiny or fully alpha-clipped charts can rasterize to no valid pixels and then remain unpublishable. This gate does not measure all triangles' visible area or lighting convergence. Atlas reallocation, changed layouts or sources invalidate old results. Cache buffers normally ping-pong; buffer identity alone is not an invalidation criterion.

Published owners have admission priority ahead of warming owners. Each admitted owner reserves its complete requested chart set, or six fallback cards, within the card/byte budget. Owners that do not fit are skipped as a whole. `WarmupBudgetBlockedCards` reports eligible warming cards omitted by capacity; `RequiredCards`, `ChartedOwners` and `ApproximateOwners` distinguish demand and representation. Within each phase, distance and a retention preference order owners. If published demand alone exceeds capacity, complete material residency is impossible. These counters are not surface-area coverage measurements. Atlas reallocation requires recapture and invalidates pending readback snapshots.

`IsSlotSourceCurrent(slot, stableId, revision)` is a read-only pre-publication guard. It checks all current cards, proxy identity/revision/source renderer, chart asset/content version/capture mesh, source eligibility, material CRC, texture update counts, property blocks, transform and geometry/bounds signatures. A mismatch revokes readiness before `Scene.Prepare` publishes a previous receipt. The guard does not upload data or consume `ChangedBounds`; normal `Prepare` still reports and schedules the change. Its per-frame geometry signature is not a full vertex-buffer hash, so in-place edits require the explicit geometry revision described above. Enabled skinned sources may use the legacy approximate path but do not gain baked-chart or stable HLOD support.

## Storage

| Resource | Format | Meaning |
| --- | --- | --- |
| DiffuseAtlas | RGBA8 UNorm, linear | Diffuse reflectance RGB; material AO in alpha |
| EmissionAtlas | RGBA16 float | Emitted radiance RGB; packed geometric normal plus validity in alpha |
| PositionAtlas | RGBA32 float | Absolute world position XYZ; normalized card depth in alpha |
| NormalAtlas | RGBA16 float | Shading normal XYZ, including normal/detail maps; perceptual roughness in alpha |
| DepthAtlas | D32 | Raster depth used to retain the first captured layer |

Emission alpha is zero for uncovered texels. Values 1–1024 encode two 5-bit octahedral components of the triangle geometric normal; every such integer is exactly representable in FP16. The geometric normal supports ray-origin bias independently of the normal-mapped shading normal, with a deliberate quantization error. A higher-precision geometric-normal format remains a quality option to evaluate.

Per-card metadata is **128 bytes**: a 64-byte `worldToCard` matrix, 16-byte atlas rectangle, 16-byte capture direction/position tolerance, four uints for stable ID/revision/generation/readiness, and four uints for owner slot/chart ID/layout generation/flags. Flag bit 0 marks a real chart; bits 1–2 encode that chart's source-submesh Cull mode. Owner ranges use 16 bytes per scene slot; card indirection uses 4 bytes per pool entry; anchors use 8 bytes per patch; emissive descriptors use 32 bytes per card and enter the surface byte budget. The current allocated surface estimate is:

```text
40 * atlasWidth * atlasHeight
+ cardCapacity * (128 + 4 + grid² * 8 + 32)
+ sceneSlotCapacity * 16
```

The separate double-buffered irradiance cache uses `cardCapacity * grid² * 96 * 2` bytes. Each entry contains six float4 values: total irradiance, identity/generation tag, anchor, normal, guide and emission/environment-origin irradiance. This increases cache storage by 20% from the former 80-byte entry; it is not a 20% increase in total GPU memory. Actual bandwidth and execution-time increments have not been measured. The per-camera emissive proposal table adds 1,056 bytes; defaults are weight 0.5 and the top 16 proposals, capped at 32. At 384 cards, emissive descriptors add 12 KiB. CPU arrays, source/capture meshes and engine/driver allocations are additional. Rounded atlas dimensions include unused tail tiles and a minimal dummy allocation when disabled. At 384 cards and 32-pixel tiles, atlas textures alone occupy 640×640 pixels, about 15.6 MiB; this is an allocation calculation, not a GPU memory measurement.

The CPU primitive map uses 4 bytes per source primitive plus outer-array references, capped at **16 MiB per camera**; CLR array headers are outside that counter. It is built for a newly verified layout/geometry version, reused without rereading vertices or full triangle buffers each frame, and released on retirement/disposal. Exhaustion leaves the binding unknown while preserving valid card capture. `surfaceTriangleMappingCpuBytes` reports this CPU payload separately from GPU allocations. DXR attributes add 128 bytes per submesh instance, 80 bytes per triangle, 16 bytes per triangle binding, and 4 bytes per scene-slot flag; BLAS/TLAS and driver memory are separate. `hardwareBindingUploads` counts binding-buffer uploads, not matched hits or covered surface area.

Each tile has a one-texel cleared border. Captures use their own world-to-card transform and atlas rectangle in the vertex shader. A six-vertex raster quad clears a tile without erasing neighboring pages; a scaled fullscreen triangle or whole-target clear would be unsafe here. HLSL readers use bounded nearest-texel loads rather than filtering material or position across depth discontinuities.

## Material handling

When an analytic or SDF hit has no usable surface sample, its proxy supplies a uniform diffuse and emission estimate. With material reading enabled, an opaque URP Lit MeshRenderer with one material slot and one submesh now takes these constants from the effective property block. A nonempty slot-0 block takes precedence over the renderer block. Missing values come from the material, and emission follows the material's keyword. Removing the slot block restores the renderer override on the next scene preparation. The fallback does not sample texture detail. [Actual emission changes and scope](../LocalComparison/Review/uniform-fallback-mpb-01/result.md)

Each supported source submesh uses an explicit capture-material copy. `CopyPropertiesFromMaterial` preserves source properties, and capture keyword states are set by name. Renderer/per-submesh property blocks for standard Lit textures, colors, UV transforms and scalars enter the copy and change signature. Chart draws select the copy by their original source-submesh index. Source materials are not modified. Texture update counters, material CRC and property blocks trigger recapture; rigid transforms reuse material copies. Legacy skinned captures invalidate each frame and still require a consistent tracing backend.

The capture shader includes URP's `LitInput.hlsl` and `BRDF.hlsl` to evaluate standard opaque `Universal Render Pipeline/Lit` materials: base texture/color, metallic or specular workflow, emission, occlusion, alpha testing, normal maps, detail maps, and parallax UV displacement. Parallax is the view-dependent material approximation used by that card, not a displaced mesh intersection. Missing tangents fall back to the geometric surface normal. Unsupported shader types, transparent materials, nontriangle submeshes and unrendered extra material slots do not become fabricated material coverage. The proxy's authored tint/emission overrides are applied separately to the captured material.

`rawNg` preserves source triangle winding transformed by inverse transpose, without a determinant or face-forward flip. Stock Lit shading normals (`Ns`) retain their authored direction, including on visible Cull Off/Front back faces; this is not an automatic two-sided normal-flipping model. True charts supply their original geometric direction separately from the Cull-adjusted capture direction. Six-view capture reconstructs orientation using derivatives, raster front-face and the CPU object determinant sign under the declared default Unity DX12 raster convention; external code leaving invert-culling enabled is unsupported. Ray-origin bias chooses its side separately with `HLGIOffsetNormal(Ng, toward)`. Screen history may keep camera-facing estimated Ng while gather bias follows the sampled Ns hemisphere, avoiding a back-face self-hit without changing hit identity.

`TryGetHardwareMaterial` is a CPU accessor for the original submesh's constant approximation, even when that owner has no resident cards. A nonempty submesh MPB replaces the renderer MPB; missing fields then use that submesh's material, not the renderer block. Ordinary stock Lit color constants are converted to linear, HDR emission stays linear, and MPB vectors retain shader-space values. This accessor does not sample textures. It is distinct from the current exact software/DXR hit-material path, which uses committed triangle barycentrics, UVs and texture pages to evaluate the supported stock Lit material. Invalid/nonfinite values or unsupported shader/Cull/surface modes remain unknown; a constant approximation cannot turn failed exact material evaluation into known radiance. See [the shared hit-material evaluator](../Runtime/Resources/HybridLumenGI/HybridLumenGIHitMaterials.hlsl) and [material/geometry contracts](GeometryHistoryContracts.md).

Registered MeshRenderer sources on active GameObjects can be disabled or force-hidden while warming. Static cards use [CommandBuffer.DrawMesh](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Rendering.CommandBuffer.DrawMesh.html) with explicit matrices: a baked chart uses `CaptureMesh` and its chart submesh, while fallback views use the source mesh/submesh. Known MPB values are included in the copied material. Local chart projections are transformed into world space; fallback bounds derive from transformed mesh bounds. No native lighting/probe data are required. Inactive GameObjects and disabled proxies remain ineligible. Baked charts reject SkinnedMeshRenderer sources; enabled skins without assets retain only the approximate dynamic DrawRenderer path, and disabled/force-hidden skins are rejected. Camera receiver qualification still excludes disabled renderers.

SDF/analytic visibility remains an approximation and does not acquire texture-hole visibility merely because a card capture uses alpha testing. Exact software and DXR triangle queries separately evaluate source Cull and alpha coverage before accepting a candidate: known holes are skipped; unknown coverage conservatively retains occlusion and cannot supply known radiance. This is implemented in [software triangle traversal](../Runtime/Resources/HybridLumenGI/HybridLumenGISoftwareTriangleBvh.hlsl) and [DXR traversal](../Runtime/Resources/HybridLumenGI/HybridLumenGIHardwareTrace.hlsl), not inferred from card coverage. Shader Graph, terrain, decals, arbitrary vertex deformation and custom passes need additional contracts. Baked charts improve access to concave surfaces but finite resolution, degenerate geometry, alpha coverage and lookup tolerances still prevent a claim of complete interior material coverage.

## Queries and lighting patches

Radiance and cache queries retain `HLGIHit`, including owner, submesh/primitive, geometry revision and any exact chart binding. `HLGITrySurfaceMaterialHit` validates a known triangle's current owner range, chart/layout binding, ready page and captured position/depth/raw Ng, and queries only that card. A missing, stale or uncovered exact binding makes this card lookup fail; it never scans another layer or borrows the owner's first material. In [ProxyRadiance](../Runtime/Resources/HybridLumenGI/HybridLumenGITransport.hlsl), the exact hit's committed UV material owns Ns/rho/Le/AO. Card data locate incoming-irradiance support and do not replace those material values. Failure to resolve the exact hit material remains unknown; a missing card is not repaired by pretending that a constant fallback is an exact textured result.

Signed-SDF/analytic hits remain approximate and use `HLGITrySurfaceMaterial(slot, position, geometricNormal, out sample)` to search compatible owner cards. Unsigned SDFs explicitly lack a stable authored side and perform a lower-confidence two-orientation search. They acquire the current resident owner's geometry revision, never an invented primitive, UV, front-face identity or area PDF. A sample contains position, Ns, Ng, diffuse, emission, AO, roughness, confidence, card index, generation and atlas pixel. Separately, the product implements [triangle-area emission NEE](EmissiveSampling.md) with matching direction-hit Le weights and a shared mixture PDF. That path requires its actual triangle/material qualification; approximate SDF hits do not manufacture an area-sample identity or extend the supported emitter set.

After raster capture, `CSBuildAnchors` partitions the tile interior into nonoverlapping patch cells and scans each cell for a valid captured texel. It chooses the texel nearest the cell center with deterministic tie breaking; an empty cell writes an invalid anchor, including after page reuse. `HLGITrySurfacePatch` uses that stored real texel instead of requiring the exact cell center to be covered. `HLGISurfaceCardUv` supplies coordinates for irradiance interpolation. Exact triangle lookup keeps the selected physical card through cache interpolation; only the software approximation enumerates the owner's range. Missing coverage remains missing; a constant transport fallback does not become a valid chart sample.

Irradiance remains independent of receiver reflectance. Material capture and lookup retain `rho` in `[0,1]` under `D = E/pi`. Direct reflection uses `rho * D_direct`; recursive cache feedback separately uses `min(rho,0.98) * AO * bounceFeedback * D_cache`, consistently for screen and world hits. This feedback cap biases higher-order reflection; it does not reduce the direct source term. See the [bounded consistency fix](../LocalComparison/Review/direct-reflectance-consistency-01/result.md). Bias visibility rays with geometric normals. Lookup and interpolation still require GPU image tests near chart borders, thin layers and disconnected surfaces.

### Cached light-source contributions

Each lighting patch carries both total D and the D originating from material emission and the environment. The second channel is accumulated directly, not obtained by subtracting bright estimates. Both channels use the same traced directions, geometry, material validity, PDFs/MIS weights, AO, bounce feedback and accepted samples. Environment misses and area-emission NEE enter both channels; analytic `DirectIrradiance` enters only total D. The sampling guide remains based on total D. No additional rays are traced.

The two RGB channels share the age in `irradiance.a` and the existing temporal weight. Their commit is atomic: a failed or unknown estimate preserves a still-valid pair without advancing its age; invalid identity, geometry or stored values clear both. The second float4's alpha is not a separate validity or sample count. A cold age-zero entry does not become known merely because the analytic-light table is empty.

When this camera's **currently uploaded analytic-light table is empty** (`_HLGI_LightCount == 0`), shared cache lookup consumes the emission/environment-origin channel. The existing full-pool write also replaces stored total RGB with that channel, including budget-skipped and unknown updates, so later re-enabling lights cannot resurrect the pre-off analytic contribution. Emission and environment light remain. A nonempty table retains the total-D path. This is a two-source-class decomposition, not per-light tracking: an empty uploaded table can also result from supported-light admission or spatial selection and does not establish that every scene light is disabled.

The [four-frame light-off comparison](../LocalComparison/Review/cache-source-separation-01/result.md) shows reduced subsequent image change while retaining visible emissive bounce on receiving surfaces. It does not establish physical color error, a universal convergence time or performance. Screen-history handling and local material/light changes keep their existing contracts; this cache change does not promise immediate removal of every screen-history residual.

For analytic light admission, an effective RGB of exactly `(0, 0, 0)` consumes no slot. This applies after color-space conversion, intensity and optional color temperature. Setting the last contributing light to black therefore permits the same empty-table cache handling as disabling it. Dim nonzero lights remain eligible.

## Required validation

Use `Tests/Validate-Offline.ps1` and its source-hashed report for the exact checks and outcomes of the current candidate. Relevant suites exercise chart partitioning, capture-mesh/source identity, variable residency, source/readiness guards, scheduling/readback and selected shader entries. CPU adapters and numerical or standalone DXC checks do not validate Unity API compatibility, ShaderLab state, native material/MPB binding, raster output, compute hazards, GPU readback ordering or driver behavior. Do not carry a previous six-card build's test totals forward as evidence for this layout.

In Unity, inspect chart captures for a concave room, inner walls hidden by an outer shell, thin parallel layers and distinct textured submeshes. Verify only assigned triangles draw, local projections survive negative/nonuniform transforms, borders do not bleed and selected anchors lie on captured geometry. Exercise tiny and fully alpha-clipped charts, per-submesh MPBs, stale assets, unsupported materials, variable-owner admission, page reuse and HLOD publication under pressure. Separately test six-view fallback and ensure its approximation remains identifiable. Compare material samples with ordinary URP Lit and measure GPU time, memory and bake/import costs. These engine/GPU acceptance checks remain unperformed here.

For exact-hit acceptance, place differently colored thin layers within the old positional tolerance, reverse authored Ns without changing winding, and test Cull Back/Front/Off from both sides with mirrored transforms. Evict/reuse pages and change geometry/layout while observing that stale bindings cannot select a neighboring chart. Test renderer versus submesh MPB replacement and HDR constants. On visible back faces, verify gather rays do not immediately hit their own plane. Use the source-matched unified report for offline results; these Unity/raster/GPU acceptance steps remain unperformed here.
