# Frozen Lit inputs to the GPU material record

`Validate-HitMaterialLayout.ps1` compiles the actual HitMaterialLayout, MaterialSource, HitMaterialData, RayTextureLayout and RayTexturePool runtime classes under .NET 8. It uses the actual Pool.Handle type, not a replacement record. Unity object, texture, command/fence and Color APIs are explicit substitutes held in this directory; the test does not modify the separate pool harness. Current result: **6 scenarios / 6,633 assertions**, using both Windows PowerShell 5.1 and PowerShell 7.

The assertions cover all fifteen 16-byte record fields and their offsets within the 240-byte ABI, the UInt4 component offsets, all ten map slots and paired generation/index ordering, high-bit generations, and metallic/specular map exclusivity. Branch flags come from captured shader keywords; numeric `_AlphaClip`, `_WorkflowMode` or `_ReceiveShadows` do not manufacture variants. Disabled maps keep their presence bits while unused handles are zero. A specified map with an invalid handle stays present, allowing the GPU to report unknown; an absent or explicitly null map selects the shader default. Record construction alone is not proof of texture residency or evaluator support.

The harness captures ordinary Lit inputs through the real MaterialSource class. It checks identity texture transforms and Lit defaults when properties are absent, source-only Cull despite an MPB override, and whole per-material block precedence over renderer-level properties. After capture, source values/keywords/textures are replaced or destroyed and live texture getters are configured to throw. Re-encoding the frozen descriptor still produces the same data without a live read. Changing the caller's handle array cannot mutate a previously encoded value record.

The Color.linear substitute is deliberately identified as an adapter. Its invocation count verifies that raw Material base/spec colors and their defaults are converted once, MPB shader-space values are not converted again, and HDR emission/alpha are retained. An independent double-precision standard sRGB decode oracle checks the resulting origin-selection path over 800 deterministic random samples with RGB in [0,1], plus the low-value branch. Alpha is tested outside [0,1]; negative/HDR emission and MPB values must remain bit-exact. The test does not claim to execute Unity's native gamma function or validate that function outside this numeric domain. The fixed UnityCsReference [Color.cs](https://github.com/Unity-Technologies/UnityCsReference/blob/1c2d7db69c060103b6dc087af725442d1efaef9c/Runtime/Export/Math/Color.cs) delegates RGB conversion to `Mathf.GammaToLinearSpace` and preserves alpha; actual engine color semantics remain part of Unity acceptance.

Random cases also verify independent surface/detail scalar packing and unchanged linear proxy parameters. Invalid generation, handle counts, proxy values, transparent/clear-coat variants, malformed nonfinite frozen values and invalid source Cull must return false with a zero output record. Malformed same-assembly inputs exercise the final publication guard separately from MaterialSource's earlier validation; they are not a public descriptor-construction API.

These are CPU record/source tests. They do not establish texture copy completion, hit-UV evaluation, alpha-candidate skipping, tangent-frame parity, Unity draw semantics, or physical-GPU correctness. The separate material-evaluator WARP tests and later Unity/DXR integration have their own evidence and limits.
