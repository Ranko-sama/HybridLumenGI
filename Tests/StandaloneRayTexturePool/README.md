# Ray texture batch lifecycle and importer recording

Run `Tests/Validate-RayTexturePool.ps1` with Windows PowerShell 5.1 or PowerShell 7. The .NET 8 harness compiles the actual runtime Pool, Importer, Layout, HitMaterialData and MaterialSource classes with explicit Unity API substitutes. The current PowerShell 7 run passed **19 scenarios / 6,222 assertions**. Earlier two-shell evidence belongs to the previous independent-batch implementation. It checks CPU ownership, budgets and command recording. It does not execute Unity, emulate a GPU fence, or prove actual queue synchronization. The separate WARP copy/sampler tests have a different scope.

The pool API includes legacy `TryPrepare(requests, budgetBytes, out lease, out reason)` and precision-aware `TryPrepareRequests(Request[], budgetBytes, out lease, out reason)`, `RecordUploads(command, lease, importer.Record, out reason)`, `GetResources(lease, out metadata, out texels)`, `Bind`, `MarkSubmitted`, `ReleaseUnrecorded`, `Quarantine`, and static `PollRetired`. A lease returns immutable upload and handle values by index; no public array exposes its backing storage. `GetResources` is only a borrow for RenderGraph imports/dependency declarations, not permission to dispose, submit, or read an unready allocation.

Texture pages now share bounded metadata/texel arenas across batches and cameras. Exact frozen Texture2D observations reuse a page only after its first consumer fence and successful GPU metadata readback. Duplicate pending observations return an explicit pending result without another large allocation. A changed source gets a fresh page generation; other resident pages keep their exact handles and data. Old pages remain occupied until every reader and metadata readback has retired. Arena placement uses bounded best-fit holes and reserves at most one largest-page replacement, within the same global budget. It does not compact live arenas or merge independently created arenas; fragmentation or lack of contiguous space can still produce an explicit budget fallback. Initial full logical mip reservation remains conservative when the actual source SRV exposes only a smaller tail.

The 64-byte descriptor and 16-byte buffer-element ABI remain intact. Sampler bit 24 selects two row-aligned RGBA16F texels per integer uint4 element; odd row and mip tails are padded, never paired across boundaries. Only explicitly bounded/16F source formats use this encoding. The copy performs explicit round-to-nearest-even, including signed zero and subnormals, and rejects nonfinite or out-of-half-range input without clamping. Unknown formats and float32/HDR sources retain float32 bits. Half conversion is a stated color precision tradeoff. The actual material Batch requests wide float32 for alpha-test BaseMap and enabled parallax height coverage inputs, so this new encoding does not introduce loss at their cutoff/UV dependencies. It does not promise bit parity with every Unity sampling path. Three noncoverage 2K LDR full mip chains need 134,217,936 bytes including three descriptors; with the normal single-page arena headroom and metadata slots the first arena is 178,957,888 bytes, still below 256 MiB. These figures exclude the separate small material/binding tables.

Null maps give invalid handles and no upload. A constant-only request retains the 80-byte unready dummy binding. A lease exposes UploadCount, UploadByteCount and IsReused. IsReused means an existing arena was borrowed; it does not mean UploadCount is zero. The real material Pass imports only new-page sources and records no source copies on a fully reused frame. It still uploads fresh immutable material/binding tables and fences every consumer.

The byte budget is global across all pool instances, including active, submitted, disposed, quarantined and incomplete-cleanup batches. All cameras must supply a consistent global limit. The count covers requested buffer payload, including metadata; it does not claim to measure driver allocation alignment or CPU heap cost. There are at most 1,024 requests per batch, 32 outstanding batches per pool and 128 consumer leases and 128 physical arenas across all pools. Generations are monotonically allocated across instances, consumed on failed allocation, and never wrap. They are passed as integer bits, including bit 31.

Only the GPU importer publishes ready. The pool initializes referenced metadata rows with `flags=0`; the frame-budget path writes only each new page row, while the legacy unbudgeted first allocation can initialize the whole arena once. It invokes the importer only for new texture pages, passing metadata before texels. It never follows the importer with a CPU ready write. Successful recording and `IsHandleCurrent` establish only CPU identity; consumers must also use the sampler's generation/ready/bounds checks. Unsupported or stale sources can safely retain ready zero. The importer re-observes CPU-visible texture fields before recording, rejects unsupported formats, virtual-texture-only sources and unsupported RT states, and records Begin, every logical mip and Finish in that order. Original Texture2D and supported 2D RenderTexture sources are allowed; an RT's nonreusable history does not prohibit current capture.

The caller must order producer, copy and all consumers on one queue or provide explicit queue waits, declare RenderGraph dependencies, and provide a fence after the **last** consumer of the batch. Do not submit a recorded batch twice or append uses after `MarkSubmitted`. An unrelated fence is not valid evidence. Command API exceptions, missing/invalid completion evidence, disposal during recording, and failure to query a previously accepted fence quarantine the allocation. No CPU age or frame count recycles it. Dispose releases only never-recorded batches immediately, retains outstanding references statically, and allows later proven fences to retire quarantined resources. Call `PollRetired` regularly, including after pool disposal. A pool with unproven resources can exhaust its budget by design.

The tests include an independent iterative mip-size oracle over 600 NPOT layouts; source/full-chain byte accounting; exact budget boundaries across pools; duplicate/null mapping; immutable frozen requests without live texture reads; stale/cross-owner handles; generation exhaustion; all count limits; no-age release; final-consumer completion; default/throwing fences and lost support; partial allocation and cleanup failures; disposal/reentrancy; and explicit 2D RT input. Importer tests cover full/truncated chains, 1×1 and 16,384×1 tails, independently enumerated 8×8 dispatch coverage, bit-31 generations, every captured source field changing after observation, unsupported GPU/format/load/RT states, partial kernel lookup recovery, and an exception at **every** recorded command API boundary. Those failures must retain the actual pool allocation until new final-consumer evidence is supplied.

The APIs were checked against UnityCsReference commit `1c2d7db69c060103b6dc087af725442d1efaef9c`: [GraphicsFence.bindings.cs](https://github.com/Unity-Technologies/UnityCsReference/blob/1c2d7db69c060103b6dc087af725442d1efaef9c/Runtime/Export/Graphics/GraphicsFence.bindings.cs), [GraphicsBuffer.bindings.cs](https://github.com/Unity-Technologies/UnityCsReference/blob/1c2d7db69c060103b6dc087af725442d1efaef9c/Runtime/Export/Graphics/GraphicsBuffer.bindings.cs), [RenderingCommandBuffer.bindings.cs](https://github.com/Unity-Technologies/UnityCsReference/blob/1c2d7db69c060103b6dc087af725442d1efaef9c/Runtime/Export/Graphics/RenderingCommandBuffer.bindings.cs), and [RenderingCommandBuffer.cs](https://github.com/Unity-Technologies/UnityCsReference/blob/1c2d7db69c060103b6dc087af725442d1efaef9c/Runtime/Export/Graphics/RenderingCommandBuffer.cs). The fixed public fence implementation validates an uninitialized fence and checks platform support before reading completion. The pool also explicitly requires `SystemInfo.supportsGraphicsFence`; no substitute result is presented as proof of Unity's native fence behavior. `Texture.updateCount` and mip observations remain CPU observations, not a GPU content hash, frozen pixels, or producer/consumer synchronization.

For asset streaming, call InvalidateSource(texture) before a write or unload and stop new requests. Call the public static PollRetired() even after all camera pools are disposed; IsSourceReferenced(texture) becomes false only after the remaining page references retire. UpdateCount and sampler/mip fields are CPU observations, not a GPU content hash. Normal Texture2D automatically participates under the existing producer IncrementUpdateCount contract; RenderTexture and unknown dynamic source kinds never reuse. The queue producer → copy → consumers ordering remains required.

The added cases exercise independently fenced shared readers, per-page changes with untouched neighbors, partial-row initialization, pending request coalescing, out-of-order consumer completion, canceled graphs, readback failures/unknown requests, explicit source epochs and partial native disposal. The metadata readback is an explicit test adapter; these CPU results do not prove Unity GPU synchronization. The official Unity 6 [SetBufferData range overload](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Rendering.CommandBuffer.SetBufferData.html) and [AsyncGPUReadback Request](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Rendering.AsyncGPUReadback.Request.html) supply the production API contracts.
Request(view, requireFloat32) makes precision part of page matching. Equal observations in one batch promote to their strongest requested precision. A completed wide page may satisfy a narrow request, but a half page never satisfies a coverage-wide request. Actual Batch tests use captured shader keywords, not the _AlphaClip scalar, to select coverage dependencies; the independent 128/255 cutoff example demonstrates why the wide requirement matters.

The production caller now configures the global copy allowance with BeginFrame(engineFrame, maxUploadBytes), minimum 80 bytes. All cameras use the same setting; same-frame calls never replenish the allowance (a larger second value cannot increase it). UploadFrame, UploadBudgetBytes and UploadBytesUsed expose the current accounting. Only actual recording charges new metadata rows (64 bytes each) and physical stored elements (16 bytes each). Prepared/canceled graphs consume no allowance; ambiguous command exceptions retain their conservative charge. The API rejects time reversal and has no runtime reset that could forget in-flight work; fresh player/domain reload is the initialization boundary.

When a stable page exceeds one frame's allowance, the importer appends contiguous physical ranges across frames. The consumer fence must complete between continuations. The GPU sequence cursor rejects duplicate, missing or overlapping ranges, its independent logical-texel counter rejects underdispatch, and Finish publishes ready only after the whole logical allocation schedule. Partial pages are never marked ready. Only the final successful metadata readback enables cached reuse. An uninitialized page deferred by the allowance makes its material row explicitly unknown, so the shader cannot read an uninitialized descriptor. Existing first-readers and copied pages are never overwritten.

An unversioned RenderTexture may change between frames. It therefore requires its entire current copy to fit the frame allowance; otherwise the material stays unknown. Stitching multiple dynamic frames is not supported or silently presented as a valid snapshot. Supporting larger progressive RT captures requires an explicitly frozen producer/source version. The quota counts transfer payload, not GPU milliseconds, dispatch overhead, driver memory or an exact bandwidth guarantee.
