# Hit material RenderGraph adapter validation

Run `pwsh -NoProfile -File Tests/Validate-HitMaterialPass.ps1`, or use Windows PowerShell 5.1 with the same script. The runner compiles the actual `HybridLumenGIHitMaterialPass` together with the seven actual Batch dependencies: Batch, RayTexturePool, RayTextureImporter, RayTextureLayout, HitMaterialLayout, HitMaterialData and MaterialSource. It requires every runtime source SHA-256 to remain unchanged through the run.

The current PowerShell 7 run passed 858 assertions in ten scenarios. They verify:

- Four imported buffers, in material/binding/metadata/texel order, with 240/32/64/16-byte strides. RenderGraph imports retain the default `forceRelease=false`. The actual pass and batch preserve copied source ordinals and the unready constant-only dummy.
- Keyword-dependent texture usage, metallic/specular alternatives, normal/emission/detail/occlusion/parallax maps, shared-reference deduplication, colliding object hashes/instance IDs, and different observations of the same texture reference.
- Explicit `RTHandles.Alloc((Texture)texture)` borrowing, including RenderTexture. A wrapper remains retained while the final consumer fence is pending; releasing or retrying a failed wrapper release does not destroy its external source.
- Before/after failures at each buffer and texture import; wrapper allocation exception/null; all four native buffer allocation failures. Pristine resources are released without pretending that graph construction recorded GPU work.
- Source equality across stable ID, owner revision, geometry revision, submesh, original renderer/material references, frozen material/MPB/texture observations, tint and emission. A supplied geometry revision is compared here; independently validating a mesh against that revision is the hardware backend's responsibility.
- Failures before and after every actual Record/Bind command, including both consumer kernels. The caller is authorized to dispatch only after both bindings succeed. Partial failures remain quarantined until a valid final same-command-buffer fence is supplied.
- Final-consumer ordering, pending/throwing/default/foreign fences, Dispose before execution or between recording and finalization, late callbacks, wrapper cleanup retry, and abandoned graphs. No frame age or CPU completion is used to release GPU references.
- Per-source validation failures producing unknown rows, exact global budgets across passes, and cancellation during source recapture or either kernel's binding.

The test compiles runtime code; it does not replace the pass, source comparisons, batch allocation, upload orchestration, encoding, binding or retirement with a test implementation. Unity objects, native command recording, RenderGraph handles and GraphicsFence observations are explicit CPU adapters. Uploads are deep-copied at record time. The adapter deliberately distinguishes the borrowing Texture overload from the owning RenderTexture overload.

The ownership adapter follows the pinned Graphics source `feb4de2d9a93a4ae10d287d3a6d7003d08ea3e53`: [RTHandleSystem](https://github.com/Unity-Technologies/Graphics/blob/feb4de2d9a93a4ae10d287d3a6d7003d08ea3e53/Packages/com.unity.render-pipelines.core/Runtime/Textures/RTHandleSystem.cs), [RTHandle](https://github.com/Unity-Technologies/Graphics/blob/feb4de2d9a93a4ae10d287d3a6d7003d08ea3e53/Packages/com.unity.render-pipelines.core/Runtime/Textures/RTHandle.cs), and [RenderGraph](https://github.com/Unity-Technologies/Graphics/blob/feb4de2d9a93a4ae10d287d3a6d7003d08ea3e53/Packages/com.unity.render-pipelines.core/Runtime/RenderGraph/RenderGraph.cs). This is an API contract test, not execution of those native APIs.

`Finish` is intentionally one-shot. If its fence append fails, the pass remains retained and budgeted. Tests use reflection to reach its owned real Batch solely to append a valid same-command-buffer fence and clean up injected quarantine between cases. This is not an exposed production recovery path. Without such proven completion, production retains those resources indefinitely.

No Unity editor/player, real RenderGraph execution, real GraphicsFence, shader, RTAS or GPU operation runs in this harness. A newly imported TextureHandle does not itself prove that an external producer wrote the source first. The production caller must establish producer → copy → both consumers → fence ordering on the same command buffer/queue. Texture producer synchronization, Unity import behavior and actual device completion remain separate acceptance work.

The added actual-eight-class case traverses first upload → consumer fence → metadata readback → fully reused pass → one changed texture page → independently fenced old reader. Reused passes import no original source textures and upload only the small material/binding tables. A partial change imports only its new page source and initializes only that metadata row; canceling an unexecuted graph does not clear other resident pages. Generation exposes the current material table generation, while texture handles retain their independent page generations.
