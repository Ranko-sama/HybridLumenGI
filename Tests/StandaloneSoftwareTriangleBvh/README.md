# Exact software triangle traversal

Run `pwsh -NoProfile -File Tests/Validate-SoftwareTriangleBvh.ps1`. The runner compiles the actual `HybridLumenGISoftwareTriangleBvh` C# class with explicit Unity/provider adapters. Its actual node and leaf arrays are written to binary files, uploaded to D3D12 WARP, and queried by the actual geometry functions in `HybridLumenGISoftwareTriangleBvh.hlsl`. A separate double-precision Möller–Trumbore brute-force oracle checks the results. No Unity or physical GPU is executed.

The immutable layout contains 32-byte escape-link nodes and 64-byte leaves holding prepared world positions plus original instance/primitive indices. Capacity or missing-source failure rejects the entire layout. The caller must then retain the SDF/analytic representation for every owner; a partial table must never authorize skipping the corresponding SDF. Both software intersection and the area-emitter distribution use the same prepared world positions. Shared `HybridLumenGIExactMesh.hlsl` retains the material, UV, authored-normal, Cull and source-generation contract used by DXR.

The GPU test covers bounds traversal, nearest primitive, finite advancing links, triangle barycentrics, shared edges, nonuniform geometric scales and grazing rays. It deliberately defines `HLGI_SOFTWARE_GEOMETRY_ONLY`: this harness does **not** execute the product coverage/material/shadow-policy functions. Those remain shared with the independently tested UV-material code; final product shader compilation and engine execution are separate evidence.

The layout holds only CPU arrays. The renderer uploads the complete layout, binds the matching prepared attributes and material batch, and includes node and leaf bytes in the software geometry quota. The builder partitions triangles with a binned surface area heuristic and falls back to median splits when needed. This geometry test measures query correctness. Unity rebuild and driver costs are outside its scope.
