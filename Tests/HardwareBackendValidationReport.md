Validated behavior:

- Original normal/UV attributes remain **80 bytes**, instance records are **128 bytes**, and each triangle's chart binding is **16 bytes**. A parallel **96-byte** surface record stores three raw object-space positions and three source tangents in the same primitive order. Position validity and tangent handedness are explicit; missing, nonfinite, zero or invalid-handedness tangents stay invalid. The instance stores an inverse-transpose matrix, owner/triangle-offset/count/original-submesh, stable ID/owner revision/geometry revision/Cull, and same-submesh diffuse/emission constants. Tests check managed offsets, allocation strides, both bind paths, byte accounting and disposal. Constants remain an approximation; storing attributes alone is not texture evaluation.
- The source-capture method walks retained instance IDs in order and requests the original renderer/material slot, including compressed empty-submesh layouts. It checks the current scene owner/revision, cache geometry revision, proxy/renderer/mesh identity, retained pose and original submesh before publishing a complete frozen source array. Any inconsistency discards the whole array. Current render-texture observations are permitted without misrepresenting them as reusable history. Tests include different MPB slots, late source changes and same-submesh proxy tint/extra emission; this CPU method does not capture GPU texture contents.
- Empty submeshes do not break primitive offsets or instance-ID mapping. Each nonempty submesh has its own retained native handle.
- Rigid transforms update those handles and instance matrices without reading mesh vertices again, uploading triangle attributes, or rebuilding membership. A new RTAS build command is scheduled.
- Effective material/Cull changes update instance constants and identity without a triangle upload or RTAS rebuild. Alpha-test keywords/properties, transparent queues/surface properties, renderer enablement, readability, topology, missing materials and singular transforms are rechecked even without a scene revision change. Missing, invalid or nonfinite effective material/side data rejects hardware membership. A null SurfaceCache disables this preparation instead of silently assuming the owner's first material, and a later valid source can recover.
- Chart layout changes update physical-card/chart/layout/geometry bindings. Retirement invalidates mappings while retaining eligible real geometry and its same-submesh constant approximation. Stale geometry bindings are rejected. Stable layouts and rigid/material-only updates do not walk or reupload the per-triangle map.
- Warming instances are excluded. Stable-slot replacement and manual/topology changes rebuild; manual/topology instances request `dynamicGeometry=true`. An independently changed geometry-content revision also forces a dynamic source refresh even if the dirty-region list was cleared.
- Triangle budgets reject whole meshes while allowing later smaller meshes; increasing the budget reconsiders fallbacks.
- Missing normals/UVs use explicit geometry-normal and UV-availability fallbacks; missing source normals are not labeled as real interpolated Ns. Finite tiny/large normals are rescaled before normalization. Zero/nonfinite face attributes remain zero instead of acquiring an invented axis. Capability/resource gates and native failure paths retain software fallback, with one warning per failed backend.
- Build recording is idempotent while unchanged. Both binding methods supply the existing buffers and the new triangle-surface buffer plus the acceleration structure; memory accounting and disposal include the new resource. Pose-only updates do not reread tangents or reupload either triangle attribute stream.
- A separate 16-byte owner lighting-policy record carries the GameObject layer bit, rendering-layer mask and ShadowCastingMode. Editing these fields refreshes transport identity without replacing retained native mesh handles, reading/reuploading triangle attributes, rescanning chart bindings or scheduling a new RTAS build. Combined material/policy edits still update the same-submesh constants and revision.
- Shadow queries filter Off/On/TwoSided/ShadowsOnly and both 32-bit masks before candidate commitment. TwoSided bypasses material Cull only for shadow queries; it does not change source Ns or make ordinary GI surfaces physically double-sided. The explicit rendering-layer enable flag distinguishes a disabled feature from a valid zero mask. All bit positions, including bit 31, are checked against independent integer expectations.
- A four-candidate fixture has a nearer non-caster, a nearer wrong-layer caster, a farther back-facing TwoSided caster and another farther valid surface. All 24 visit orders are tested for both GameObject-layer and rendering-layer mismatch. Rejected nearer candidates must not hide the valid blocker, while the independent surface query still returns visible non-shadow-casting geometry. Invalid raw normal data does not bypass owner-level exclusions.

The original retained-handle `FallbackCount` regressions remain covered: adding/removing unsupported published instances recomputes that count without unnecessary geometry rebuilds.

The C# tests establish managed layout and state-machine behavior against recording adapters. They do **not** establish Unity Editor API binding, shader import, native acceleration-structure update semantics, actual driver refit, GPU memory usage, image correctness or performance. The separate real-header DXC check does not execute a RayQuery. The original 4,665-assertion backend snapshot, followed by the 4,666-assertion source-contract update against the same runtime source, retained the original conservative alpha-test eligibility gate; new candidate admission and texture integration require their own validation. The new policy tests also do not verify Unity's actual shadow-layer synchronization, instanced receiver mask upload, software/hardware pixel agreement, or native candidate order on a device. Current visibility uses a binary occlusion sample blended by shadow strength; it is not filtered soft shadows, cookies, per-material receiveShadows or a complete mixed-lighting/shadowmask implementation. Those require separate engine and rendered-image acceptance.
