# Material source observation tests

`Validate-MaterialSource.ps1` compiles the complete runtime class with .NET 8 and explicit Unity API substitutes. It checks CPU source identity and equality, not Unity native property lookup, actual RendererList contents, material draw parity, or GPU pixel contents. Windows PowerShell 5.1 and PowerShell 7 use the same unchanged runtime file.

The current standalone harness includes the actual `HybridLumenGIHitMaterialData` runtime class: **10 scenarios / 4,366 assertions**, passed in both shells. The accompanying unchanged SurfaceCache scenarios also pass with this new source dependency: **13 scenarios / 19,992 assertions**. These are module results, not a new unified acceptance report.

`Snapshot.HitMaterial` exposes immutable raw Lit inputs and all ten captured map references. `HybridLumenGIFrozenColor` retains raw RGBA and its Material, renderer-MPB, or material-slot-MPB origin. `HybridLumenGIFrozenTextureView` retains reference, origin, dimensions, format, mip count, sampler settings, data color space, update count, and observed Texture2D mip state. Scalar/color/vector convenience accessors return zero for an absent property; source Cull alone defaults to Back. Consumers use `TryGetFloat`, `TryGetVector`, or texture `Origin` when absence matters. An explicit null texture remains distinguishable from an absent property. Disabled-map references and the complete keyword set remain available; they do not imply that a hit shader supports those branches.

Descriptor construction and access read only the snapshot's captured arrays. Tests mutate and destroy source objects, then make every live texture getter throw: old descriptor access and equality still succeed without touching those getters. Other cases verify all ten maps, raw negative/HDR color values, color origin, independent sampler/mip state, null and disabled maps, and defensive copying of arrays. Public descriptor access exposes neither mutable arrays nor setters. A retained Texture reference identifies a mutable resource; it does not freeze its pixels.

The current material contract follows Unity Graphics commit `feb4de2d9a93a4ae10d287d3a6d7003d08ea3e53` [Lit.shader](https://github.com/Unity-Technologies/Graphics/blob/feb4de2d9a93a4ae10d287d3a6d7003d08ea3e53/Packages/com.unity.render-pipelines.universal/Shaders/Lit.shader) and [LitInput.hlsl](https://github.com/Unity-Technologies/Graphics/blob/feb4de2d9a93a4ae10d287d3a6d7003d08ea3e53/Packages/com.unity.render-pipelines.universal/Shaders/LitInput.hlsl). The snapshot retains the existing SurfaceCache material fields, the ordinary Lit toggles, source raster state, keyword set, pass state, and texture transform/sampler metadata. Clear Coat fields are retained conservatively; ordinary Lit does not implement Clear Coat. This does not broaden rendering support to custom shaders, transparent materials, DOTS, BRG, shader debugging/streaming overlays, or arbitrary global properties.

The tests exercise all supported property categories, same-value changes under different property names, forced equal hash codes, material/shader reference replacement, per-material block priority, unknown-only blocks, missing versus explicit overrides, color origin, texture replacement/counters/samplers, pass and queue changes, destroyed objects, invalid data, and repeated late changes. Public snapshots expose neither arrays nor setters. Each observation allocates a snapshot and owned value/keyword/pass arrays and re-reads the material slot; no throttled or frame-cached validation is used. This is a correctness-first CPU cost that still needs profiling on target scenes.

Unity's [SetPropertyBlock contract](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Renderer.SetPropertyBlock.html) specifies that a per-material block takes precedence over the complete per-renderer block. [GetPropertyBlock](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Renderer.GetPropertyBlock.html) completely replaces the caller's scratch block. The reader chooses that effective block before filtering supported properties; it never merges two blocks. Color values retain their Material-authoring or MPB shader-value origin without conversion during identity construction.

[MaterialPropertyBlock does not support render-state changes](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/MaterialPropertyBlock.html). Therefore the source Material supplies Cull, blending and depth-write state. An MPB `_Cull`, including an invalid value, does not override that state. The accompanying SurfaceCache regression verifies capture-material Cull, card metadata, and hardware fallback constants against the source Material. SurfaceCache retains a compact signature including property IDs and presence as a fast change hint; equal hashes no longer prove unchanged material. Each owner also retains exact material snapshots, and publication validation and recapture decisions compare live observations. Tests force a constant Material CRC and change effective scalar/sampler state to verify rejection and recapture. Geometry signatures and other external content epochs remain separate contracts.

[Texture.updateCount](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Texture-updateCount.html) requires producers to increment the counter themselves for GPU-side updates. `CanReuseHistory` is consequently false for RenderTexture and CustomRenderTexture sources. SurfaceCache still captures these materials in the current frame, dirties their pages on the next Prepare, and refuses to reuse an old HLOD publication ticket as stable content evidence. An unreported native/GPU write to a Texture2D is also unknowable from this CPU API; its producer must call `IncrementUpdateCount` and the owning pipeline must invalidate history where necessary. Snapshot equality is not a texture-content hash or GPU fence. Shader hot reload, global keywords/uniforms, renderer lightmaps/probes, geometry, and changes after observation remain separate caller-owned epochs or revalidation points. Ordinary Lit declarations and the API documentation support the contract; the substitutes are not evidence that Unity executed it.

The added public API declarations were checked against UnityCsReference commit `1c2d7db69c060103b6dc087af725442d1efaef9c`, [Texture.bindings.cs](https://github.com/Unity-Technologies/UnityCsReference/blob/1c2d7db69c060103b6dc087af725442d1efaef9c/Runtime/Export/Graphics/Texture.bindings.cs): `Texture.isDataSRGB`, and Texture2D `streamingMipmaps`, `activeMipmapLimit`, `loadedMipmapLevel`, and `loadingMipmapLevel`. They are frozen during source observation and participate independently in exact snapshot equality. Non-Texture2D sources expose `HasTexture2DMipState=false` and mip-state indices `-1`. Unity's [activeMipmapLimit documentation](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Texture2D-activeMipmapLimit.html) defines the limit relative to mip levels included in the build; this layer preserves the reported values and does not add the active limit to a streaming level or infer resource-copy coordinates. Tests change each field without changing `updateCount` and verify invalidation. These observations still do not establish upload completion or producer/copy/consumer ordering.

This is an input contract for subsequent GPU residency and hit-UV evaluation. It does not implement texture copies, sampling, ray footprints, material support classification, or alpha-candidate traversal. No Unity raster execution or physical-GPU behavior is validated here.
