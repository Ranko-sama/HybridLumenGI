# Actual hardware-material bridge on WARP

Run `powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Validate-HardwareMaterials.ps1` or the same command with `pwsh`. An installed VS2022 x64 C++ toolchain, Windows SDK DXC, Node, and the existing pinned Unity Graphics include cache are required; the script installs nothing.

The runner extracts the actual `HLGIHardwareInstance` and `HLGITriangleNormals` declarations from the current HardwareTrace source, then includes the actual HardwareMaterials bridge, HardwareSurface/Normals, HitMaterials and RayTextures helpers. It does not include UnityRayQuery. DXIL listing checks bind the 128/80-byte source types, the 320-byte input/112-byte output and real structured SRVs: 64-byte texture metadata, 16-byte texels, 240-byte materials, 32-byte bindings and 96-byte triangle surfaces. SRV register assignments are checked before execution.

The independent oracle uses double precision image sampling and Lit material equations. For geometric LOD it projects a circle perpendicular to the ray onto the triangle plane, solves barycentric coordinates with a Gram system, and searches 2,048 angles for the largest texel diameter. It does not reproduce the shader's analytic gradient/eigenvalue formula. TBN expectations transform and normalize each vertex's N/T before interpolation, and parallax uses three separately transformed outgoing view directions. Invalid fixture expectations are explicit rather than inferred by copying the bridge's guards.

Each encoding variant (`rgag`, `rgb`, `ag`) exercises 549 fixtures: 248 full-material, 149 surface-coverage and 152 shadow-coverage fixtures. Three actual entry points pass compile-time constant purpose arguments to the runtime bridge, matching its production call sites; nine selected DXIL entry/encoding combinations are compiled with default optimization. Cases cover absent maps and irrelevant stale maps, multiple original submesh identities, stale binding/material/texture generations, owner/geometry revisions, invalid UV/barycentric/position/tangent inputs, primitive offsets, mirrored/nonuniform transforms, tiny and zero scales, texture-size/UV-scale/cone-radius LOD changes and deterministic randomized affine cases. Every unknown result must retain conservative `covered=true`. Full material evaluation and alpha coverage are distinct calls; a full result's covered value is not an alpha acceptance test.

Point views use `materialView.w=1`; orthographic views use a constant direction toward the viewer with `w=0`. Tests include different vertex normals/tangents on a shared plane, mirrored transforms and orthographic translation invariance. Shadow coverage ignores ForwardLit parallax and remains valid without a height texture, tangent frame or material-view observation. Corresponding surface coverage stays unknown. Four independently constructed midpoint-cutoff pairs require the same material to produce opposite surface/shadow alpha decisions. Shadow coverage still requires valid base UV/texture/LOD dependencies. This does not validate Unity LOD crossfade, raster alpha-to-coverage, shadow bias or filtered soft shadows.

The generated report binds runtime/template/script hashes before and after the run, the extracted declarations, cached include hashes, the actual DXC/C++ command logs, DXIL/listings, binary fixtures/readbacks, executable and oracle results. Every run uses a new TEMP directory. Unavailable WARP exits 2 and is not a pass. The software-adapter fence wait limit is 180 seconds; PSO creation and completion timing are logged separately. Earlier 30-second runs timed out, including a dynamic-coverage entry with one fixture; their evidence is retained in separate TEMP directories. A single dynamic coverage diagnostic later completed under the longer bound, but the dynamic full/coverage suite has not passed. Neither raising this bound nor specializing the calls establishes a runtime performance improvement or identifies the cause of the delay.

This is execution of the actual bridge and material helpers on D3D12 WARP, a software adapter. It does **not** execute DXR traversal, Unity resource binding or texture import/copy, test real shader import, establish physical GPU performance, or claim that runtime integration is complete. The earlier integration-13 report does not cover these newly added sources.
