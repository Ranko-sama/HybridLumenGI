# Validation v2 source export draft

The three source files are isolated drafts. They do not change the live project or existing validation evidence. The Editor exporter registers the optional `HybridLumenGIValidationSourceState.EditorExporter` delegate; the Runtime assembly has no Editor dependency.

`Export(scene, camera, feature, runDirectory)` returns `{file, sha256}` for `source.json`. File paths, including `assets[].path`, are relative to the run/manifest directory. Original asset paths and roles are metadata; archived bytes use content-addressed names. The exporter does not save scenes, mutate importers, toggle lighting, evaluate GI, or adjust exposure. Source files and live inputs are checked again after export.

Physical `source.assets` is selected from actual mesh/material/texture/shader/probe inputs and their physical dependencies, plus installed URP/Core semantic source. Product/observer/harness code, raw scenes, mixed renderer/pipeline assets, project configuration, and SDF/chart approximation assets are archived in a separate `source-provenance.json` with `{artifacts:[{file,sha256,role}]}`. The provenance index and its entries are included only in candidate provenance, never in the physical source hash. The original scene still describes export origin; its product component settings do not invalidate an otherwise unchanged physical reference. A mixed physical asset that cannot safely be separated is explicitly unsupported. Camera `m_TargetTexture` is an output reference and is omitted from generic reference traversal; actual material/sky/cookie render textures remain unsupported physical inputs.

The active URP pipeline, selected renderer, and camera settings are independently normalized into literal named scalar/enum/vector settings, including light/shadow modes, masks, cascades, bias, HDR/MSAA, scale, depth formats, and stencil. Renderer selection follows the actual camera/default index. HLGI renderer feature settings and object references are excluded; active other renderer features are explicitly unsupported. This is the bounded ordinary UniversalRenderer scope, not a generic custom-renderer interpreter. The installed URP source defines missing additional-light-component defaults and is part of physical semantic dependencies.

`Begin(runDirectory, source, camera, feature)` verifies the source descriptor and every asset hash/length before opening a `Session`. Player callers must provide a package explicitly; `CopySourcePackage` verifies and copies the physical package, provenance index, and every provenance entry without generating a new source. Origin evidence is not a certificate for the current Player implementation. The candidate manifest separately hashes the index and all entries. No configured package means no source certificate. `CaptureBeforeRender(logicalFrame)` returns a `PendingFrame` containing independently captured physical inputs. `WriteFrame(pending, actualCamera)` rejects changed physical inputs across the render, attaches the actual URP camera-input descriptor supplied by the capture ticket, and writes a hash-bound state file. It does not claim to have observed shader camera globals. `SourceStatus` and `Unsupported` expose unsupported input reasons. A pending frame is owned by one session and may be written once.

Persistent keys are saved scene path + hierarchy sibling indices + component index. Names are descriptive only. No engine frame, instance ID, wall-clock time, or product RGB/history/identity result enters source or frame-state identity. Feature enable/settings are not physical per-frame inputs; product configuration has its own capture provenance. Geometry uses row-major object matrices, local vertex/normal/tangent/color arrays, all eight UV channels, and explicit per-submesh topology/indices/base vertex. Material properties preserve their literal Unity getter values. Indexed property blocks replace the renderer-level block as a whole; a property records whether it came from the selected block or material. No implicit `.linear`, metallic-to-diffuse, or emission/exposure conversion is applied. Texture sampler state and CPU data representation are recorded; shader source bytes define shader defaults for null texture bindings.

The environment is an explicit exception to algorithm-only Feature settings: the current `environmentRadiance` and `environmentCubemap` define escape-ray incident radiance. Their actual runtime values are included in the static source, every frame, and the before/after check. The constant's authored value and its `Color.linear` upload convention are recorded separately; a cube is archived as a source reference and marked unsupported until its GPU/sample representation can be certified. A missing Feature/settings source is unsupported, never assumed black.

The bounded supported input representation is ordinary URP Lit, readable triangle meshes, and arbitrary counts of realtime Directional/Point/Spot lights. The source byte closure is not a claim that a physical reference renderer implements every exported property. Unknown shaders, unavailable mesh data, extra vertex streams, static batching, skinning/deformation systems, terrain, LOD switching, volumes/decals, probe interpolation, baked/mixed lighting, skyboxes, reflections, and fog are explicitly unsupported where relevant. Texture bytes are archived when readable, but arbitrary GPU/native texture writes are not inferred from CPU bytes or `updateCount`; any bound texture is currently marked unsupported for a physical verdict. Original texture/importer and bake bytes remain available for a later explicitly implemented decoder. The exporter never substitutes an approximate or blank decode.

The before/after snapshot check covers observable state changes across the render. It is not a general proof against callbacks that temporarily modify and restore GPU state inside the render. The intended fixed validation scene has no such producer. Invalid/nonfinite values, conflicting evidence paths, broken hashes, unsafe package paths, and mid-export edits fail rather than produce a partial certificate. Unsupported data produces an explicit top-level `unsupported[]`; the v2 adapter classifies it as unsupported-source.

`source-compile-01` and `source-compile-02` preserve the initial API compile failures (unneeded module type references, Light rendering-layer signed type, and ambiguous Editor PackageInfo). `source-compile-06` passed separate Runtime and Editor compilations after provenance separation. These are development compiler checks, not a full-product or Unity-native validation. Later source changes require a fresh numbered check or the root's integrated two-assembly preflight.
