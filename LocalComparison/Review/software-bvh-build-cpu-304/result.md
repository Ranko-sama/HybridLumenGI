# 精确软件 BVH 的跨相机建树准入

几何变化会使精确软件追踪重新构建整棵 BVH。同一 Renderer Feature 内的多个相机原来各自按三角数和缓冲字节准入，可以在同一引擎帧连续建树。新增可选的 CPU 时间额度后，超过额度的下一次建树保留等待轮次。实际追踪沿已有 SDF／解析回退，匹配当前几何的树照常使用。[设置与范围](../../../Documentation/GpuBudget.md#精确软件-bvh-的-cpu-准入)

复用精确软件几何宿主，在两个独立相机状态上执行当前 Feature 的建树准入、实际几何属性准备和实际 BVH 构建。两台相机看到同一份逐帧平移的 4,096 三角输入。Unity Mesh、RenderGraph 和缓冲由已有适配器提供。使用 `0.001 ms` 触发延后，衡量的是准入行为。

| 受控引擎帧 | 观察 |
| --- | --- |
| 10 | 默认额度 0，两台相机都构建当前布局 |
| 11 | A 建树后同帧复用，B 两次尝试都延期，未读取三角或返回旧布局 |
| 12、13 | A 在 B 预计返回前可推进。到 B 的轮次时 A 让出，B 构建最新位姿 |
| 14 | A 的受控三角读取失败仍计时，后续 B 继续延期 |
| 15 | 撤回 B 的等待请求后，A 在当帧获得建树资格 |

采用范围是这一段整树 CPU 准入及回退入口。已开始的建树可以超过额度。原生 CPU 收益、图像稳定性、GPU 25 ms 和完整 G4／G5 放行各自验收。复用宿主在第一次数据执行前补齐了列表引用和缓冲命令适配。
