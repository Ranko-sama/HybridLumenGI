# Astra independent candidate gate

Reviewed 2026-10-28 before the candidate Unity build. This review read the current product diff, finite HLSL comparison and optimized compilation artifacts; it did not run Unity, WARP, a compiler or another test. Only this requested review document was written.

No concrete correctness or scope blocker was found. The candidate may enter the one planned build and native window once the already-running checks of the other affected CSTrace entry points succeed. This is permission to measure the single candidate, not a retention decision.

The normalized product diff is restricted to preparing receiver `dx/dy/valid` before the ray loop and replacing the two receiver footprint calls. The original helper and its use by receiver world matching and TraceScreen remain unchanged. Position, depth and matrices are invariant during this dispatch; the new preparation has only texture reads and local outputs. Each direction still executes the original `position, position+dx, position+dy` projection expression. RNG, sample weights, query ordering, accumulation and the measured/unknown contract are unchanged. Failed preparation produces a zeroed footprint; it does not bypass the subsequent query or substitute `hasGeometry` for validity. Partially populated derivatives are not consumed when preparation fails.

The finite comparison has the appropriate scope. `check-receiver-footprint-reuse.py` extracts the old function from the frozen baseline, verifies its shared functions are unchanged, and extracts the new preparation/projection functions from the candidate. Both variants use the same existing 192-byte input / 48-byte output WARP runner. The only depth-fetch adapter supplies the requested eight neighbors; all three product footprint fields (`radius`, `slope`, `valid`) and the function result are recorded. Independent reading of the saved binaries found 2,880 bytes on each side, identical across all 60 outputs. The 30 cases include invalid depth/support/direction and edges as well as 12 receiver neighborhoods from the archived full-resolution Unity depth. Thirty-eight outputs are valid. Their exact inverse projection is archived; View is reconstructed from the recorded camera pose, as explicitly disclosed. This establishes the tested helper equivalence, not full-CSTrace or whole-frame Unity image identity.

The compiler artifacts support the intended change. Both optimized CSTrace compilations succeeded with the same pinned compiler and RayQuery adapter. Candidate DXIL SHA256 is `558a7feed06ee4fd54fcbc3aea53f3373aeb4338ea282a3cbb7bf0b42326743a`. The saved inspection changes receiver depth-load instruction sites from 16 inside the ray loop to eight before it and zero inside. The geometric-normal, world-match and both TraceScreen groups remain represented. These are static DXIL instruction sites, not unconditional memory transactions, driver ISA, physical register counts or a measured speedup.

The tested/compiled Kernels source used CRLF, SHA256 `ee22fda79a465d1f63026be1e9383cb50303d8be26fdfe8768a6e1daf10c7f1d`. The current LF source is `bef8f03231190ba7c2ab6ee275b96f5beeccec6275ffd1fe93e94d52692ed4c7`. Independent byte comparison after CRLF-to-LF normalization is exactly equal; `source-newline-normalization.json` preserves this mapping. No new compilation or WARP run is needed for that formatting change. Build evidence must keep the actual LF input hash rather than claim raw-byte identity with the earlier source snapshot.

The unresolved question is performance: six derivative floats and validity now remain live across the large loop, and preparation can execute on paths that previously terminated before reaching a footprint call. Neither is a demonstrated defect; the one native comparison is the appropriate remaining gate. The frozen comparator requires identical diagnostic wiring, only Kernels differing in build inputs, complete valid windows and matching workload. Its Gather saving must exceed the larger of the two four-block median ranges, while Transport and FormalSum must not worsen beyond their own block variation. This is a descriptive finite decision rule, not a statistical confidence guarantee.

Keep the existing stop rule: a failed native/contract gate, inconclusive saving or regression means restore the product candidate and return the retained evidence to Pro. Do not add samples, another candidate, new timing scopes or an image-quality investigation to rescue this optimization.
