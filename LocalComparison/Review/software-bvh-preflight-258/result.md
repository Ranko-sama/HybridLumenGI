# 软件 BVH 在额度可用后再构建

相机 A 被逐出后，在旧分配尚待栅栏完成时重新进入。1 MiB 额度可以容纳旧分配与返回 A 的新三角属性，共 1,024,864 B。此时另需 255,968 B 的 BVH 缓冲，因此 BVH 暂缓准入。Release213 在拒绝之前已用当前几何构建出完整 CPU 布局。

修复用已准备的三角数、原二叉树节点数和节点／叶 stride 计算同一份缓冲需求。额度检查先于 CPU 构建。只有准入后成功构建的布局才记录当前几何代次，旧分配沿用原安全退休票据。

| 同一 A → B → A 场景 | Release213 | 修复版 |
| --- | ---: | ---: |
| 返回 A 的预算等待帧生成的 CPU 布局叶数 | 2,000 | 0 |
| 等待帧新 BVH 缓冲分配数 | 0 | 0 |
| 等待帧软件几何计账 | 1,024,864 B | 1,024,864 B |
| 确认退休后 A 的完整布局叶数 | 2,000 | 2,000 |
| 恢复后 A 的软件几何计账 | 640,416 B | 640,416 B |

独立相机 B 在 A 仍有退休占用时正常准入。对照复用 168 的 C# 宿主，编译实际 Feature 准入、精确属性和 BVH 源码，以受控缓冲与完成票据驱动原状态切换。结论限于取消必定拒绝的 CPU 构建，并保留原恢复和计账。原生 GPU p95、全阶段 CPU 时间预算和完整 G4／G5 仍待验收。 [原预算夹具与范围](../camera-software-geometry-budget-168/result.md) · [现行准入](../../../Runtime/HybridLumenGIRendererFeature.cs)
