# 分段裁剪贴图的阴影刷新

T3／G3 的具体缺口已关闭。静态裁剪贴图分段上传时，远处接收面现在会在最终写入命令使阴影覆盖可用时收到局部照明反应。若页在验证读回期间暂时无法绑定，同页重新可用时也会通知一次。稳定可用的后续帧保持安静。

Unity 6000.0.85f1／DX12，实际后端为 DXR。固定点灯距地板中心 20 单位，范围 30。无图卡的裁剪板距地板约 12 单位。光线和阴影基础距离分别为 4 和 5 单位。两版都先用标量 alpha 形成遮挡，随后一次换入 512×512 透明 RGBA32 BaseMap，以每帧 1 MiB 上传。探针在该相机的实际批次、同一 GPU 命令中读取阴影和地板中心变化域。

| 事件 | 实际阴影 | 地板软反应，基线 → 修复 | 调度优先级，基线 → 修复 |
| --- | --- | --- | --- |
| 换贴图并开始分段写入 | 未知 | 1 → 1 | 1000 → 1000 |
| 最后一段写入 | 已知，无遮挡 | 0 → 1 | 0 → 1000 |
| 验证读回期间暂时省略该页 | 未知 | 0 → 0 | 0 → 0 |
| 同页经验证后恢复绑定 | 已知，无遮挡 | 0 → 1 | 0 → 1000 |
| 稳定保持 | 已知，无遮挡 | 0 → 0 | 0 → 0 |

新增事件沿用半径 34 的照明软域，地板硬拒绝为 0，照明 epoch 为 5。相机、冻结源、页代次及实际遮挡序列一致。新逻辑只跟踪参与裁剪阴影的 BaseMap。最终写入命令排在当帧消费者前，GPU 继续判定覆盖是否可采样。

两版此小场景每帧均调度地板的 24 个 patch。对照确认的是软反应和调度优先级。像素残留、拖影幅度、收敛时间及生产负载继续按原 G3 范围验收。[原始同条件读数](comparison.json)
