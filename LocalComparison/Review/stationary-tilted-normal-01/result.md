# 静止斜面能保留已积累的间接光

一个静止接收面的当前到前帧变换为恒等矩阵。旧路径仍对已解码的着色法线做了一次归一化，足以改变浮点分量的末位。面没有移动，原本要求法线逐分量相等的静止历史判定却失败了，随后把成熟历史裁到了当帧黑色样本附近。

Release109 在身份和运动行已通过原校验后，逐元素检查变换矩阵的全部四行。仅当矩阵恰好为恒等时，前帧预期位置与两条法线直接采用当前的已解码值。非恒等变换继续计算原重投影。接收面图元、前帧几何与材质、相机与像素位置、历史长度、动作和光照变化仍分别参与历史资格判断。[时间重建实现](../../../Runtime/Resources/HybridLumenGI/HybridLumenGIKernels.hlsl)

| 同一固定输入下的输出 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 重建后的历史 R、G、B（每通道） | 0.0368000 | 0.9200000 |
| 历史置信分量 | 1 | 1 |
| 亮度一阶矩 | 0.9200000 | 0.9200000 |
| 历史长度 | 32 | 32 |

对照来自 D3D12 WARP 上的实际身份时间重建内核与几何编解码函数，每版各一次派发。固定输入是一个像素、成熟白色历史、一次已知黑色测量，当前测量权重 0.08。相机矩阵与编码几何一致。解码着色法线为 `(-0.530923843, -0.535582006, 0.656712830)`，原运动行归一化得到 `(-0.530923903, -0.535582066, 0.656712890)`，身份行及法线校验都通过。旧路径先把白色历史裁到 0.04，再混入这次黑色测量。修改后保留白色历史，以同一权重得到 0.92。

该数值回答的是上述一个接收点是否误裁成熟历史，不能据此估算实际场景的平均亮度变化、颜色误差或运动拖影。既有场景画面对照仍按各自采集版本解读。[离线画面对照与采集条件](../picture-comparison.html)

Release109 已用产品提交 `e5ecdbb` 构建为 Unity 6000.0.85f1 普通 Windows x64／Mono／D3D12 版本。统一场景为 `NeutralThreeRooms.unity`，Release/None 构建记录 0 个错误、19 个警告。
