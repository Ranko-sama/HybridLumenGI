# 无图卡墙体贴图恢复后的局部照明刷新

Release227 在无图卡墙体换色当帧通知附近接收面。分段上传期间，GPU 仍无法读取新材质。最后一段写入和验证后重新绑定都能让蓝色重新可采样，旧版漏掉了这两次刷新机会。修复在同一可复用材质来源的全部必需贴图从未完成转为已录制时，补发原近域软反应并提高接收面更新优先级。GPU 仍负责验证采样数据。

Unity 6000.0.85f1，DX12，实际 DXR。沿用固定墙和地板场景，相机看到六张图卡的地板，无图卡不透明墙在画外且关闭投影。地板中心到墙的查询距离约 2.685 世界单位。一次将红色 BaseMap 换为 512×512 线性蓝色 BaseMap，上传上限为每帧 1 MiB。探针在真实传输命令中查询墙面材质与地板变化域，并记录当帧调度。

| 事件 | GPU 墙面材质 | 地板软反应，旧版 → 修复 | 地板调度优先级，旧版 → 修复 |
| --- | --- | --- | --- |
| 换色前 | 已知红色 | 0 → 0 | 0 → 0 |
| 换色与开始上传 | 未知 | 1 → 1 | 751 → 751 |
| 分段上传尚未完成 | 未知 | 0 → 0 | 0 → 0 |
| 最后一段写入 | 已知蓝色 | 0 → 1 | 0 → 751 |
| 验证读回期间暂时省略页 | 未知 | 0 → 0 | 0 → 0 |
| 同页恢复绑定 | 已知蓝色 | 0 → 1 | 0 → 751 |
| 稳定保持 | 已知蓝色 | 0 → 0 | 0 → 0 |

两个恢复点的墙面线性漫反射都是 `(0, 0, 0.96)`，新软域沿用墙体边界和半径 4。两版的地板硬拒绝始终为 0，照明 epoch 为 5，几何、材质来源和页代次一致。每帧实际调度地板的 24 个 patch，实测收益限刷新信号和优先级。屏幕换色残留、关灯残留、运动拖影和收敛时间继续按原范围验收。[逐帧同条件读数](comparison.json)
