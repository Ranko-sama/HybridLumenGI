# Release178 共享 RTAS 零构建额度

原 Backend 对必须新建或更新位姿的 RTAS 检查三角与实例突发上限，随后预留显存、准备属性。共享构建次数为零时，大小合格的计划仍进入这条路径，到录制阶段才无法消费名额。Release178 在现有预检处提前拒绝这类计划。录制也复核共享额度，处理同一引擎帧内在准备后收紧的情形。已建且几何和位姿匹配的 RTAS 可以继续使用。[Backend](../../../Runtime/HybridLumenGIHardwareBackend.cs) · [共享预算](../../../Runtime/HybridLumenGIRtasBudget.cs)

实际 C# Backend 与 RtasBudget 用现有 Unity 命令和受控退休宿主执行。零构建次数下，三角突发上限和积分仍足以容纳冷请求。

| 条件 | 候选观察 |
| --- | --- |
| 冷请求与延后工作登记 | 读取顶点、构造 RTAS、分配属性、增加预留、排队和录制构建均为零 |
| 已建 RTAS 仍匹配 | 可提交原 RTAS，构建数不增加 |
| 位姿改变后仍为零 | 没有更新旧结构。旧资源进入退休，受控完成后释放 |
| 恢复正额度 | 使用当前位姿录制一次构建 |
| 同帧准备后共享额度降为零 | 录制拒绝，撤下计划及其队列请求，已准备资源经受控完成释放 |

现有正额度的等待顺序、突发上限和已建资源复用控制一同通过。采用范围为 CPU 准入、命令录制和受控退休。驱动实际释放、实体 GPU 和生产负载继续按原条件验收。[宿主用例](../../../Tests/StandaloneHardwareBackend/Program.cs.txt)
