# 让已确认的空格释放照明更新名额

原调度按已捕获图卡列出全部 patch。实际 `CSUpdateCache` 遇到无覆盖的格子时，会在读取更新掩码和追踪射线之前写零并返回。因此，一个被选中的空格仍会消耗 CPU 分配的逻辑更新名额。

候选沿用现有 HLOD 回读。完整的当前结果需要匹配图集、网格、图卡身份和代次，同一图卡还须有至少一条当前覆盖标签，才可将其全零格记为空。后续调度跳过这些格子。图卡来源、布局或代次变化后撤销已有判断，未知覆盖继续参与原调度。样本年龄、覆盖条件和回读频率沿用原合同。

## 同额度功能对照

在现有 HLOD 回读宿主中编译实际 `HybridLumenGIHlodReadback` 和 `HybridLumenGICacheScheduler`。固定单图卡 `2×2`，每次允许两格。两个调度器具有相同的初始服务记录，回读数据由宿主提供。格 0 和 2 是显式全零，格 1 有当前覆盖及年龄 1，格 3 有当前覆盖及年龄 0。

| 阶段 | 实际 C# 结果 |
| --- | --- |
| 两边均未收到回读 | 首次选格 0、1 |
| 下一次，保留无覆盖证据的原准入 | 选格 2、3，其中格 2 为空 |
| 下一次，接收当前回读的候选 | 选格 1、3，两格均有覆盖，公平份额相同 |
| 就绪门 | 仍报告格 1 样本不足。两处覆盖格达到原年龄 2 后才接受票据 |
| 捕获代次变化 | 四格重新具备资格。迟到旧回调、整卡全零和截短结果均无排除资格 |

Astra Max 同意按此调度范围采用。该项关闭了已确认空格占逻辑配额的问题。同一配额可以执行更多有效照明工作，实际 GPU 时间和 Release110 的高速冷入首显仍待分别验收。Release110 的记录仍无法把样本不足归因于这一机制。[高速路线及其边界](../cold-aggregate-prefetch-01/result.md)
