# 共享网格的蒙皮快照撤回

停用一件蒙皮对象的形变组件时，Release154 会误把实例快照撤回当成共享源网格编辑。共用网格的另一件对象在正常来源复核时因此丢失快照。修复让撤回只更新所属实例的几何与传输修订，并刷新该实例的来源签名。[旧版记录](baseline.json) · [修复版记录](fixed.json)

在同一隔离 Unity 6000.0.85f1 工程中，以 Null 图形设备执行两次同输入 Play。两个 `SkinnedMeshRenderer` 共用同一三角形 `sharedMesh`，各自通过实际 `BakeMesh` 和组件发布路径取得一份独立快照。观察器直接调用产品的捕获边界。初次发布后，只关闭 A 的形变组件，保留 Renderer 和 Proxy，网格顶点和索引保持相同。

| 观察 | Release154 | 修复版 |
| --- | --- | --- |
| A 回退至作者网格，几何修订推进 | 成立 | 成立 |
| A 的旧快照进入原退休队列 | 1 条 | 1 条 |
| 共享来源内容版本 | 被推进 | 保持 |
| B 的 Mesh、SDF、图卡和修订 | 来源复核撤回快照 | 原快照及修订保留 |
| 重新启用 A 后，实际编辑共享顶点并发出内容通知 | 两件均撤回，随后自动发布新几何 | 两件均撤回，随后自动发布新几何 |

两次 Unity 退出码均为 0。Astra Max 按实例撤回、共享源更新及退休入账的范围采用。实体 GPU 栅栏、形变后射线命中、画面和时延分别验收。[旧版日志](<I:/Unity test/Logs/SharedSkinWithdrawal177Baseline.log>) · [修复版日志](<I:/Unity test/Logs/SharedSkinWithdrawal177Fixed.log>)
