# 软件 BVH 重建和录制的托管分配

T6 的精确软件 BVH 现在直接填充最终节点数组。录制把私有布局的节点和叶传给现有 `SetBufferData`，保留 GPU 缓冲布局和公开复制接口。[Unity 6 命令接口](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/rendering/commandbuffer/setbufferdata)

复用现有 C# 几何宿主，使用同一批 4,096 个三角的平移输入。实际构建器和 Feature 的录制方法在 Release239 与 Release240 间逐字节给出相同的 8,191 个节点和 4,096 个叶。再次建树后，旧布局及其录制载荷仍匹配原内容。修改公开复制接口的返回数组也不影响布局或命令输入。

该宿主同线程建树及录制的托管分配由 **1,574,976 B** 降至 **788,504 B**。其中 786,368 B 对应省去的整表数组内容。按默认上限 250,000 个三角计算，一次完整重建并录制可省 47,999,936 B 的数组容量，约 **45.8 MiB**。上限数值按节点和叶尺寸计算。采用范围限托管构建与命令录制输入，Unity 原生耗时、进程显存和软件 GI 的 25 ms 门槛继续验收。
