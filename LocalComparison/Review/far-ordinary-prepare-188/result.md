# 域外普通代理的相机准备

Release163 会在每份相机场景准备中刷新域外普通代理的实例输入，把它们加入候选表和查找表，最后才在普通代理准入时按距离丢弃。现版本先保留共享几何及延迟接源检查，再按当前驻留边界过滤普通未流式代理。域外时可跳过本相机无需消费的材质、位姿和 Shadowmask 实例刷新。组关系、历史 HLOD 根与活跃的流式绑定沿用原准入。

Unity 6000.0.85f1、DX12 Editor。测试直接调用真实 `HybridLumenGIScene.Prepare`，使用两份独立场景状态和两个视点。场景包含七件活动代理，远界为 10，普通对象位于 40 单位处。无相机渲染，HLOD 根的准备回执为受控输入。[Release163 读数](baseline.json) · [修复版读数](fixed.json)

| 观察 | Release163 | 修复版 |
| --- | --- | --- |
| 初始候选表／查找表 | 7／7 | 3／3 |
| 域外变更普通材质和 Shadowmask | 代理版本 4→6，读取新 mask | 代理版本保持 3，未读取 mask |
| 第二视点当前需要该对象 | 发布，线性漫反射绿色通道约 0.96，采用当前 mask | 相同 |
| 第一视点随后进入，期间再次换色 | 当次发布，线性漫反射蓝色通道约 0.96，采用当前 mask | 相同 |
| 两个域外代理共享网格边界变化 | 两个几何版本都推进 | 两个几何版本都推进 |
| 最后一件细节停用后，粗根离域再返场 | 按原规则进入预热 | 按原规则进入预热 |

旧版的附加延迟 Collider 夹具两次没有接上来源，位置仍为 55，末尾断言未通过。候选控制在加入同对象 Collider 后明确确认 CLR 空引用，再触发待校验。一次场景准备就接上来源，世界中心为 2，代理立即发布。该控制覆盖候选的延迟接源分支，其末尾夹具与旧版不同。表中的其余共同输入与状态均已观察。

后续用普通序列化校验入口复现 Unity 假空 Collider 的接源失败，Release165 已修复该入口。[独立同输入对照](../pending-collider-validation-189/result.md)

证据覆盖域外普通代理在相机准备中的无效刷新和入队减少，以及所述状态的一致性。对象生命周期仍执行原刷新，场景仍遍历活动代理以判断范围和共享几何变化。毫秒收益、其他场景规模和完整 CPU 准备预算继续按原条件验收。
