# Global SDF 禁用后的准备与资源回收

关闭 Renderer Feature 的 Global SDF 后，原实现仍每次准备两级、每级 4³ 页的裁剪图，枚举对象与变化范围，排序等待的砖页。该路径的更新预算为零，查询也已关闭，因而这些准备无法服务当前相机。

修复让关闭模式只绑定三个有正确元素布局的占位 SRV，逻辑大小合计 68 B。CPU 不进入裁剪图准备，传输阶段使用实际准备模式决定是否更新和查询。由启用切到关闭时，旧裁剪图在原安全退休门后释放，完成前仍计入 `AllocatedBytes`。重新启用会从未知页建立当前裁剪图。

复用 `Tests/Validate-GlobalSdf.ps1 -CpuOnly` 执行实际 C# 调度器。冷关闭只绑定单元素占位，记录中没有数据上传或调度。启用后按七砖预算推进。关闭时旧缓冲保持计账，立即重开仍得到新裁剪图及未知页。模拟完成后仅释放旧缓冲，新裁剪图按原预算继续推进。[定向回归](../../../Tests/StandaloneGlobalSdf/Program.cs.txt)

此项关闭 T6 的 Global SDF 禁用路径预算缺口。验证采用 Unity 缓冲与完成信号替身，68 B 用于逻辑账目。默认启用配置的 GPU 时间、实际进程显存和整体 G4／G5 按各自证据验收。[资源与执行合同](../../../Documentation/GlobalSdf.md)
