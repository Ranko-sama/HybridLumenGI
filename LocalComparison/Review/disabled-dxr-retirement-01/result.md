# 切换到软件追踪后，硬件资源会归还

此前示例从 DXR 切回精确软件时，只撤销了这台相机的加速结构构建请求。旧统一示例的远景实机记录显示，切换前和切换后都占用 132,096 字节的 RTAS 全局预约和 50,176 字节的硬件几何属性。继续以软件后端回到近景、再移出加载范围，这两项仍未进入退休队列。[原切换记录](<I:/Unity test/Comparison/UnifiedSample02/stage-03-far-aggregate-software-return.json>)

Release113 在用户明确选择软件追踪后，把硬件几何交给既有的 GPU 栅栏退休流程。等待最后读者期间，原预约继续计账。销毁成功后才归还额度。相机再次请求 DXR 时，常规准入流程重新预约和构建。

| 普通 Win64 Player，同一近景机位 | 硬件网格 | RTAS 全局计账 | 硬件属性缓冲 |
| --- | ---: | ---: | ---: |
| 初始 DXR | 20 | 132,096 B | 50,176 B |
| 切到精确软件，退休已完成 | 0 | 0 B | 0 B |
| 切回 DXR | 20 | 132,096 B | 50,176 B |

三个端点的近景细节均完整可见，场景均有 20 个已发布对象。每个端点的待退休数、失败数和 RTAS 退休字节均为零。切回 DXR 后，重建计数从 4 增到 5。Player 正常退出。[普通 F2 端点和完整账目](result.json)

**测量范围**　这次核对的是单相机在固定位置显式切换，以及栅栏完成后的逻辑额度。切到软件期间窗口曾暂时显示未响应，随后自行恢复。采集没有计量切换延迟，也没有测量驱动显存下降、另一台相机的准入或瞬时预算回退。
