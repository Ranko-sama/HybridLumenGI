# 首次从域外连续进入近场并折返

Release103 在零驻留起点以 20 世界单位／秒向近场移动，到达后立即原路返回。**转向时仍没有可提交的流式表示**，虽然 13 个页和 4 个成员已绑定。第一个完整细节组在回程的相机回调结束时发布，下一次相机开始时才可提交。全程可提交的组合只有空、单个完整聚合体或全部三个细节。最终离场时页、引用、绑定、在途 I/O 和退休租约均归零。

| 时点 | 到组包围盒的距离 | 相机回调记录 |
| --- | ---: | --- |
| 起点 | 62.22 | 未请求，零绑定、零引用 |
| 首次聚合体请求 | 44.98 | 尚无表示 |
| 聚合体已绑定 | 14.30 | 已开始请求细节，尚无组回执 |
| 首次当帧 HLOD 回执 | 12.99 | 聚合体预热，尚未发布 |
| 最近点 | 8.29 | 细节预热，尚无表示 |
| 回程首次完整发布 | 9.56 | 回调结束时整组细节可用；下一帧开始时距离 9.82 |
| 终点 | 62.22 | 页、引用和渲染成员排空 |

首次需求与近场折返之间的采样并不均匀，最长相邻相机开始间隔为 1.346 秒。此窗口没有测量该间隔由哪一环节造成。整条路线有需求的 297 个回调中，98 个回调结束时尚无可用组，其中包含域外预取区。它们不能直接解释为屏幕上的 98 个空洞帧。

沿首次根已绑定却无组票据的一段，定位到了另一种可稳定触发的缺陷：冷启动只进入远场时，细节按策略一直不加载，因此旧代码一直没有可识别的 HLOD 组根。该缺陷已在 Release104 修复。高速路线的数据保留其 Release103 来源，不能据此推算修复后的高速首显时间。[冷远场产品修复](../cold-far-root-01/result.md)

本机 Win64 Release/None、960×540、半分辨率 GI、2 射线、4 级滤波。单程 53.944 世界单位，计划运动时间 5.394 秒。观察使用 CPU 侧普通 Renderer 开始提交资格、当帧 HLOD 发布身份和资源账目，没有采集像素或 GPU 成本。冷指该进程的 GI 页未驻留。[位置、页和完整组身份摘要](result.json) · [逐帧原始账目](<I:/Unity test/Comparison/ColdCrossing01/run.json>)
