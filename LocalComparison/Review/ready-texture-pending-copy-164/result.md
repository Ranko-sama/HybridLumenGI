# 待定副本并存时复用已就绪贴图

原计划 T2／T3 要求精确材质沿当前来源使用已确认的贴图。普通 Lit 批次已上传并确认一张 BaseMap 后，另一批次同时需要该图和一张放不进原缓冲区的大贴图。该批次在第二个缓冲区准备一份副本。Release146 在副本回读期间，会把稍后只需要第一张贴图的批次写成指定贴图、零代次，即使第一份原页仍可用。

修复先检查完整请求能否在同一个现有缓冲区内满足。其他缓冲区仍有匹配副本等待时，相关请求只能借用当前、同源、符合精度的就绪页。完整计划或预算不满足时，沿用原待定处理。

实际 `HybridLumenGIHitMaterialBatch` 与贴图池的受控对照中，原页代次为 1。第二份回读尚未完成时，后续普通批次在旧版写出代次 0，修复后写入原代次 1，并借用原元数据与纹素缓冲。此次复用没有新上传或新缓冲。收紧额度到只够在途缓冲区和原待定描述表时，候选沿用待定的零代次和原记账。

图形调用、围栏及回读由现有宿主提供。结论覆盖材质批次的资源选择和句柄发布，实际 GPU 颜色、变化收敛与性能继续验收。[定向回归](../../../Tests/StandaloneHitMaterialBatch/Program.cs.txt) · [贴图页实现](../../../Runtime/HybridLumenGIRayTexturePool.cs)
