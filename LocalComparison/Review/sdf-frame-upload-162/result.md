# 对象 SDF 跨相机逐帧上传额度

原计划 G4／T6 要求上传受帧预算约束。Release144 的对象 SDF 只限制每次准备。两台相机同帧各准备一份冷的 64³ RFloat 图集时，体素上传请求合计 2 MiB。

普通 Renderer Feature 现在按引擎帧共享 262,144 体素（1 MiB），沿用原单次准备上限，仍可容纳一份最大的受支持卷。相机各自保留原图集和就绪条件。最早延期的整卷预留下一次可用份额，避免固定相机顺序长期抢占额度。来源撤回、图集释放或连续两帧缺席后移出等待。独立调用 `Prepare` 仍用自己的单次额度。

| 情形 | 实际 C# 对照 |
| --- | --- |
| 两份冷图集同帧准备并重复调用 | Release144 的 `SetData` 请求合计 2 MiB。修复后为 1 MiB，后准备的图集留在解析回退。 |
| 首台先调用且已有卷需要更新 | 首台的旧体素失去就绪资格，等待中的第二台先完成上传。下一帧首台完成，第二台的就绪体素直接复用。 |
| `SetData` 抛错 | 本帧保留已尝试额度。该失败版本继续回退，另一台下一帧完成上传。 |

使用实际 atlas 源码和既有 C# 宿主，帧号、场景和 `SetData` 由受控输入提供。结论覆盖对象体素提交的逻辑额度、就绪和等待顺序。实体多相机上传带宽、全应用性能、高速首显及其他上传阶段仍分别验收。[既有回归入口](../../../Tests/StandaloneSdfAtlas/Program.cs.txt) · [实际准入](../../../Runtime/HybridLumenGISdfAtlas.cs)
