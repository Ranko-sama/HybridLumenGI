# 多份形变快照的主线程发布时间准入

多个形变作业在同一引擎帧完成时，原发布入口仅按上传字节筛选。只要字节装得下，纹理创建和 `Apply`、捕获网格生成、SDF 与图卡提交就会连续在主线程发生。现有捕获时间额度从发布循环之后开始，应用无法单独控制何时推迟下一份发布。

`HybridLumenGIDeformedMesh.PublicationBudgetMillisecondsPerFrame` 增加一项按引擎帧共享的可选设置，默认关闭。每次获准的同步发布保持原子性。累计经过时间达到额度后，只延后尚未开始的完整发布。捕获顺序、原上传字节、来源复核、已完成取消项清理和栅栏退休照旧执行。[设置与使用边界](../../../Documentation/DeformedGeometry.md)

现有 `Tests/Validate-DeformedMesh.ps1` 用实际形变组件和退休代码。两份可发布快照同时就绪，受控首份发布超过本用例的 0.1 ms 设置。首份 Mesh、SDF 和图卡完整发布，第二份保留原作业、捕获帧和预留，取消的第三份同帧清理。同引擎帧再次进入渲染上下文时第二份仍等待，下帧完整发布。默认关闭的原有组件用例同时通过。[定向回归](../../../Tests/StandaloneDeformedMesh/Program.cs.txt)

关闭原计划 T6／G4 中形变快照缺少独立主线程发布时间准入的能力缺口。时间门只决定能否开始下一份同步发布，单次已开始的操作会执行到完成。组件对照使用受控 Unity 接口、实际任务与经过时间，实际 Unity 和 GPU 耗时、当前门运动画质及全阶段预算仍待各自验收。
