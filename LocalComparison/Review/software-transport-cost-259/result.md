# 精确软件近景的 Gather 成本定位

Release214 同源普通 Win64 观察版在统一三室的固定近景中，Gather 的队列时间中位为 **39.612 ms**，占同源 Transport 时间的中位比例为 **89.65%**。最低观测值为 **38.096 ms**。在这个窗口里，即使省去其余全部正式计时区间，也需要缩短 Gather 才能达到原 25 ms 目标。

| 区间 | 中位 ms | p95 ms |
| --- | ---: | ---: |
| 正式三段逐源合计 | 44.441 | 45.874 |
| Transport | 44.220 | 45.653 |
| 世界缓存 `CSUpdateCache` | 4.274 | 4.729 |
| Gather `CSTrace` | 39.612 | 41.160 |
| 重建，从 Temporal 到最后一次 Atrous | 0.155 | 0.157 |
| Transport 内其余命令及间隔 | 0.154 | 0.157 |

每源先用整数时间戳计算区间，再计算正式三段之和和 Transport 余项。表中各行分位数独立计算。Gather 的四个连续块中位分别为 40.339、39.637、39.506 和 39.464 ms，分项排序在四块中一致。

使用保存的统一三室、960×540 背缓冲、480×270 GI、2 射线、4 级滤波、20 个实际精确软件网格、近景 3 件完整细节及原静态更新额度。Unity 6000.0.85f1、RTX 2080 Ti、DX12，原生计时开启，预算反馈关闭。首次负载检查因 20% 峰值推迟启动，正式启动前四次 GPU 占用采样均为 5%。

隔离工程复用了 `TransportCostProbe` 和原 NativeDX12 ABI，正式父区间仍按原入口记录。源帧 159–222 全部取得父子票据，逐源匹配设备、代次、时钟并确认三个子段嵌在同一父 Transport 内。Player 正常退出。数据适用范围为这次固定负载的队列区间，包含区间内屏障及等待。
