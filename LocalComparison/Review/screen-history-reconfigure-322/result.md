# 屏幕历史换代与分配失败恢复

原计划 T3／G3 的相机重配缺口。实际相机入口按当帧预算选定 GI 尺寸及是否使用接收面身份。Release255 先释放旧历史并写入新尺寸，再逐张分配。中途异常会让同参数准备跳过分配。本机固定版 Core 的 `RTHandleSystem` 还可能在 `RenderTexture.Create()` 未成功时返回句柄，原路径会继续把它交给图。[相机入口](../../../Runtime/HybridLumenGIRendererFeature.cs) · [实际预算](../../../Runtime/HybridLumenGIScreenBudget.cs)

新代完整创建后再切换活动纹理和尺寸。分配失败释放私有暂存，保留当前完整代。该次准备沿原普通渲染入口继续，下一次相机准备可重试。成功换代时撤销旧历史票据，旧纹理通过现有完成流程退休，期间纳入屏幕纹理逻辑字节估计。

受控宿主编译了实际 `CameraState` 的纹理准备、释放和历史失效方法，以及原屏幕预算。先准备 **480×270** 基础历史，再请求 **640×360** 含身份历史。第十张句柄模拟返回未创建纹理，全部暂存句柄各释放一次，初始八张纹理和活动尺寸保留。同参数重试取得完整新代并撤销两类旧历史。相同配置直接复用。随后在 **640×360** 关闭身份，两份旧代等待各自的完成回调，依次归还 **11,404,800 B** 和 **27,648,000 B**，当前代保持可用。

修复已进入 Release256。采用限尺寸和身份模式更换的托管所有权、失败重试及逻辑账目。验收使用受控分配与完成信号。原生 GPU 完成时序、实际显存峰值和尺寸变化后的画面仍各自验收。[同源交付](delivery.json) · [原成功 resize 观察及其边界](../resize-history-136/result.md)
