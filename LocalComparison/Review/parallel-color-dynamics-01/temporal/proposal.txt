Temporal lane proposal: retain one-frame lighting reactivity during unknown current GI
Prepared against product HEAD 06d24a6; no product edit or verification execution yet.

Current-source causal finding
- HybridLumenGIChangeRegions.cs:27 clears global/local reaction state each Begin.
- HybridLumenGILights.cs:74 clears changes; :104-114 reports only old/new unmatched
  light records. A one-time light edit followed by an unchanged light need not
  reissue the lighting-change domain on the following frame.
- RendererFeature.cs:1201-1203 and :1254-1259 add these domains for this frame.
  Pure lighting does not cause the scene full-invalidation branch at :697-698.
- Changes.hlsl gives pure lighting change.x=0/change.y=1. Receiver, geometry,
  identity, material and history-validity gates can all remain valid.
- Kernels.hlsl:468-472 returns an unknown-current estimate through the actual
  HLGIResolveUnknownHistory helper with the complete old moments, bypassing the
  reactive length cap at :526. Therefore the sole reactive event can be lost.
- The statistic-failure fallback at :518-522 has the same omission. Ordinary
  finite RGBA16F input cannot overflow a nine-value float32 sum, so this second
  branch is not claimed as a demonstrated normal-format trigger.

Proposed exact product change, only after the unified Pro65 plan permits it:
After each of the two HLGIResolveUnknownHistory calls in Kernels.hlsl, add:
    if(change.y>0.5) retainedMoments.z=min(retainedMoments.z,2);
Preserve retained RGB, confidence and moments.x/y/w. Do not increment an unknown
sample; no invalid history is resurrected. Nonreactive exact retention and all
known-current paths remain unchanged. No change to RadianceValidity, filter
sigma, geometry/identity gates, exposure, transport, formats or C# code.
