# 部分绑定的超槽 HLOD 组保留粗根

默认独立分页场景可以先绑定粗根，再分批绑定细节。Release201 在完整细节目标生成后才判断硬槽容量。已声明的近景细节若超过容量，首个细节绑定时却仍未形成完整目标。此时正在预热的粗根会被撤出，后续完整粗根回执也无法提交。[原组选择入口](../../../Runtime/HybridLumenGIScene.cs)

修复用已绑定细节和已声明未绑定叶的总数判断近景硬槽容量。超槽且当前为空或保留粗根的组沿用原粗根预热和发布。未绑定的叶只贡献数量。它的几何、材质和照明仍须取得各自的真实就绪资格。真正离开组的绑定按现有声明规则移除。

| 同输入 C# 场景对照 | Release201 | 修复版 |
| --- | --- | --- |
| 33 片有效声明，32 个槽，仅首叶绑定 | 根从预热撤出，场景无表示，容量阻塞数为 0 | 原槽中的粗根继续预热，容量阻塞数为 1 |
| 粗根的完整回执到达 | 回执被拒绝 | 接受回执，只发布粗根 |
| 停用其余声明，留下两片叶 | 采用范围为上面的失效复现 | 第一片叶单独绑定时保留根。两片都绑定并各自取得完整回执后原子接替 |

两侧使用实际 `HybridLumenGIScene`、BVH 和就绪表源码。绑定到达、声明退出和完成回执采用受控输入。观察使用同一个相机位置与原场景硬槽限，根仍经过原几何、材质及照明门。[对照入口](../../../Tests/Validate-HlodTransactions.ps1) · [具体回归](../../../Tests/StandaloneBvh/HlodProgram.cs.txt)

另外确认了宽组中远叶按逐件范围可能始终没有分页需求。扩展整根距离的候选在冷远场会让细节争用根的容量。按近场发短效提示的候选也可能在部分绑定时扩大上述容量问题。两项候选都已撤回。原生资源 I/O、宽组页需求和统一示例高速冷入首显继续分别验收。Astra Max 同意采用范围仅为已声明超槽组的粗根回退。
