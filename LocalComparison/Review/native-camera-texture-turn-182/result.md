# 双 Base 相机共享上传额度的原生观察

Release153 用实际 Batch 和 Pool 源码配受控栅栏、回读，验证后置相机可以取得一轮共享贴图上传额度。本次在 Release159 同源工程复用有限墙 DXR 场景，以两个空间分离的墙和两台 Game Base 相机隔离材质来源。同一引擎帧按 A、B 顺序显式提交，各自为 128×64，公用 1 MiB 帧上传额度。A 使用每次提交前更新的 516×127 RGBAFloat RenderTexture，B 使用稳定的 2×2 RGBAFloat Texture2D。两台相机每次均实际录制 DXR。[原受控回归](../cross-camera-texture-turn-172/delivery.json) · [实机读数](result.json)

| 引擎帧 | A 录制上传 | B 录制上传 | B 贴图资格 |
| ---: | ---: | ---: | --- |
| 5 | 1,048,576 B | 0 B | 未取得有效句柄 |
| 6 | 0 B | 128 B | 录制完整复制，代次 4，尚未 Ready |
| 7 | 1,048,576 B | 0 B | 未取得有效句柄 |
| 8 | 1,048,576 B | 0 B | 原生回读确认 Ready，复用同一页和代次 4 |

复制取生产导入器的实际录制记录，额度取共享 Pool。就绪取原生围栏后实际元数据回读，复用同时要求同一页对象、有效同代句柄且本次零复制。帧 8 的两台相机均保有各自材质来源，A 继续推进，B 未重复上传。

观察使用 Windows DX12 Editor、Unity 6000.0.85f1、URP 17.0.4、RTX 2080 Ti，Unity 正常退出 0。采用范围是固定顺序双 Base 的上传公平、原生完成及同代复用。逐像素采样颜色、普通 Player、多消费者同时在飞时的撤回和正式性能预算各自验收。此项复用现有 Release159 产品源码。
