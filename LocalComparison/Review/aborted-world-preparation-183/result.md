# 渲染图中止后的世界缓存恢复

旧版在准备阶段读取并保存新灯状态，同时提前切换世界缓存读指针。若整图在 GI 传输回调前被拒绝，下一次准备已经看不到这次换灯，仍能接受旧代世界缓存。修复让世界缓存只在当前传输成功录制后切换。下一次准备发现上一次未完成时，沿用原失败恢复，更新世界缓存代次并撤销旧的就绪回执。

复用有限墙／地板及 128×64 Game Base 手动请求。使用 Unity 6000.0.85f1、URP 17.0.4、RTX 2080 Ti 和 DX12 Editor，确认两个缓存池各有有效红光后，将唯一的方向灯从红改蓝。测试 Feature 只在该次图加入一个旧式 RenderGraph pass，触发 Unity 原生编译器拒绝。两版都确认只发生这一次预期拒绝，GI 已准备并记录蓝灯和变化标记，传输回调未执行。之后用原 pass、管线及相机状态恢复，实际记录 DXR。[旧版读回](baseline.json) · [修复版读回](fixed.json)

恢复及保持帧两版各读到两个当前 owner、revision、图卡代次和 epoch 匹配且年龄为正的 GPU 缓存条目。候选在旧标签失配后重新取得有效条目，并在下一帧按原顺序换池。着色器对失配条目先清除年龄，只有已知有效估计可以重新写出正年龄。[缓存更新](../../../Runtime/Resources/HybridLumenGI/HybridLumenGITransport.hlsl) · [样本提交资格](../../../Runtime/Resources/HybridLumenGI/HybridLumenGIRadianceValidity.hlsl)

采用限同一相机的传输未执行后拒绝旧照明，并恢复有效世界缓存推进。两个固定恢复帧在两版都没有取得正蓝分量，因此完整夹具结果和退出码保留为 insufficient／1。首次夹具在恢复 guard 失败前漏存该行，保留原始记录。更正先保存恢复读数、分开检查录制和颜色条件，并在原有的恢复与保持两帧内检查蓝分量，沿用相同输入和故障。新色建立时间、最终画面、普通 Player 与执行后提交异常继续各自验收。[首次记录](initial-insufficient.json)
