# 对象 SDF 整卷上传的共享 CPU 时间准入

此前各相机可在每引擎帧 1 MiB 的共享体素额度内连续启动整卷 `GetPixelData` 和 `SetData`。小卷即使占用较多同步时间，剩余字节仍允许下一卷启动。Renderer Feature 增加 `objectSdfUploadCpuBudgetMilliseconds`，在现有队列上累计两次调用所占的时间。零关闭时间限制，后置相机可收紧同帧额度，已执行的上传仍计入。

| 实际 Atlas 宿主，两个 16³ 卷 | 结果 |
| --- | --- |
| A 先在零设置下上传，B 随后给 0.1 ms 并同帧再改为零 | A 卷就绪，B 仍待上传，未读取 B 的源体素 |
| 下一引擎帧 A 更新来源、仍先调用 | A 先回退，B 获得完整的 4,096 体素上传，A 再下一帧恢复 |
| A 一次 `SetData` 抛出，B 同帧请求新版本 | A 未就绪，失败时间已占满额度，B 退回解析并在下一帧完整恢复 |

受控适配器让实际 `SetData` 尝试耗时超过 0.1 ms。每卷为 16 KiB，字节额度足以容纳两卷。测试使用实际 Atlas 和来源判断，受控代替 Unity 资源调用。既有跨相机 1 MiB、周期等待、来源撤销及元数据回收用例继续通过。准备中的整卷可以执行完，元数据撤销仍在本次准备处理。[实际宿主](../../../Tests/StandaloneSdfAtlas/Program.cs.txt) · [配置与驻留约定](../../../Documentation/SdfAtlasResidency.md)

关闭 G4／T6 中对象 SDF 上传阶段缺少可配置共享 CPU 时间准入的缺口。耗时包含读取源卷与上传调用，源扫描、元数据、驱动执行和 GPU 成本分别处理。实际生产负载和其他阶段时间预算继续验收。
