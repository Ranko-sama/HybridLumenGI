同一公开工程分别构建原版和只替换 BVH 建树的候选。沿用保存机位、960×540、GI480×270、2 射线、4 级滤波及原光照与材质设置。Unity 6000.0.85f1、RTX 2080 Ti、DX12 普通 Win64 Player。两窗各有 512 个匹配源帧，始终为 20 个精确软件实例、0 个未表示实例、120 张就绪图卡和 3 个完整近景成员。合计中位相差 8.394 ms，超过两窗分块中位极差的较大值 0.161 ms。两次运行正常退出，采集前单次 GPU 占用分别为 1% 和 0%。[原始窗口](<I:/Unity test/Comparison/SoftwareFullRange277/run>) · [候选窗口](<I:/Unity test/Comparison/SoftwareBvhSah291Fixed/run>)

构建器在质心跨度最长的轴上分 12 桶，用子集数量乘包围盒表面积选分组。要求两侧保留足够三角，无法取得有效切分时走原中位划分。新分组增加构建时的桶扫描和少量临时存储。原三角顶点、叶身份、缓冲布局、GPU 查询及完整提交资格继续使用。保存场景的面积模型估计内节点面积总和减少约 43%。该估计使用场景文件中的同值次序，实测窗口没有把收益再分解到包围盒、三角求交或其他 Gather 内部操作。[构建器](../../../Runtime/HybridLumenGISoftwareTriangleBvh.cs) · [表面积启发式的代价模型](https://www.pbr-book.org/4ed/Primitives_and_Intersection_Acceleration/Bounding_Volume_Hierarchies)

成本合格后复用已有 C# 建树与 D3D12 WARP 几何查询回归。实际候选节点、叶和逃逸链接通过原独立最近命中参考。材质覆盖、Cull、阴影及未知结果仍走原着色器，几何回归未执行这些材质分支。本轮采用范围为固定静止近景的 GPU 成本和几何查询回归。动态重建的 CPU 成本、其他场景、应用 Present 和完整 G5 继续验收。
