# 周期相机取得对象 SDF 上传额度

两台相机各需上传一份 64³ RFloat 对象 SDF。第一台每帧先准备且每帧有新版本，第二台每隔三个引擎帧才调用同一 Feature 准备入口。旧队列在第二台返回时刚好清掉等待记录，第一台再次用完整帧额度。第二台一直保留解析回退，缺席的中间帧仍可能保留整卷额度。

修复沿用现有等候队列。同一图集两次实际准备的间隔超过原两帧宽限时，待上传整卷只在下一预计调用帧参与预留。若该帧缺席，次帧过期。实际相机仍在自己的 Prepare 中复核来源并上传。首次等待和短间隔继续使用原宽限。

| 同一实际 Atlas 宿主 | Release220 旧行为 | 修复后 |
| --- | --- | --- |
| 周期相机在相对帧 0、3、6、9 返回 | 四次均未就绪 | 在帧 6 上传整卷并取得当前元数据就绪 |
| 高频相机在帧 4、5、7、10、11 | 均未取得新版本 | 五帧均上传并就绪 |
| 周期相机帧 9 请求新版本，此后不再返回 | 原等待过期 | 预计帧 12 过去后，高频相机在帧 13 恢复 |
| 每引擎帧体素上传尝试 | 至多 262,144 | 至多 262,144，周期相机缺席帧不读取其体素 |

使用实际 `HybridLumenGISdfAtlas`、`HybridLumenGIMeshSdf` 和 `HybridLumenGIMeshSource` 源码，场景、帧序及 Unity 资源 API 由既有 C# 宿主提供。首次旧版宿主等待超时，复用该次生成的旧源码直接执行后，得到上述序列及周期相机饥饿断言。候选通过同一对照及原共享额度、同帧重复、失败尝试计费与失败范围归还回归。[实际源码宿主](../../../Tests/StandaloneSdfAtlas/Program.cs.txt) · [上传准入](../../../Runtime/HybridLumenGISdfAtlas.cs)

关闭 T6／G4 固定周期相机因回合过期持续失去整卷上传的路径。采用范围为受控同一进程的上传准入与元数据就绪。调用间隔变化可能错过预测帧，原生上传带宽、GPU 完成时间和冷高速首显继续各自验收。[对象 SDF 驻留合同](../../../Documentation/SdfAtlasResidency.md)
