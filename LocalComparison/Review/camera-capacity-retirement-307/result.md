# 双 Base 相机容量驱逐后的资源退休

两个 Base 相机共用 Renderer Feature 且 `maxCameras=1` 时，第二台进入可立即逐出第一台。Release246 的容量驱逐会同步调用旧状态的 `Dispose`，而已录制工作仍可能使用它的纹理和缓冲。现在驱逐和销毁／改派共用退休入口。活动列表即时更新，软件 BVH 的旧等待请求撤回，旧资源由已有完成门归还。[实际入口](../../../Runtime/HybridLumenGIRendererFeature.cs)

同一受控序列编译实际 `GetCameraState`、`Evict`、软件 BVH 轮次、缓冲退休和相机几何账代码。适配器承接已录制历史、Unity 缓冲与完成回调。Release246 在 B 首次驱逐 A 时立即执行 A 的销毁回调，违反退休门。

| 事件 | 修复后 |
| --- | --- |
| 引擎帧 10，B 驱逐已录制的 A | 只有 B 活跃。旧 A 保有历史与分配，等待完成 |
| 引擎帧 11，B 申请建树，然后 A 返回 | 旧 A 的等待已撤回。返回的 A 建立新状态与新历史，活动数为 1 |
| 原完成回调依次到达 | 每次只销毁对应旧状态。A 的共享软件 BVH 账从两代 **512 B** 回到当前代 **256 B**，B 的账归零 |

采用限容量驱逐入口的所有权和跨状态账目。`maxCameras` 约束活动状态数，退休期间允许新旧资源共存。原生双相机 GPU 成本、进程显存与完整 G4／G5 继续验收。
