# Release173 减少 Global SDF 的 CPU 脏砖准备

Global SDF 会立即使受几何变化影响的距离页失效，重建再按更新名额逐帧进行。Release172 对每块保留砖逐一检查脏区，重复计算扩张范围。Release173 每层将扩张范围映射成逻辑砖行，以每行的位标记查询受影响砖。范围端点使用原有浮点砖边界和含边界比较。物理页仍通过同一个环形地址计算，失效、代次、等待年龄和录制顺序沿用原路径。[实现](../../../Runtime/HybridLumenGIGlobalSdf.cs) · [Global SDF 合同](../../../Documentation/GlobalSdf.md)

使用同一个 `Tests/Validate-GlobalSdf.ps1 -CpuOnly` 宿主分别运行 Release172 源码和候选源码。固定输入为两层、每轴四砖，含新旧几何范围与一处重叠脏区。该区域同时覆盖相接边界和越过边界的下一个浮点值。Unity 资源和命令由原记录替身承接。

| 观察 | Release172 与 Release173 |
| --- | --- |
| 零重建名额 | 55 块受影响砖立即失效，73 块保留原页 |
| 下一帧给三个名额 | 物理页 0、3、48 依次进入第 0 层重建，随后录制合并与发布 |
| 整页对照 | 物理页代次、就绪位、年龄、作业和录制序列逐项相同 |
| 脏范围扩张读取 | 固定输入中由 348 次降为 6 次，即三个范围分别处理两个层级 |

采用范围为局部变化的 CPU 准备，现有滚动、重建名额和关闭后再开启的控制通过。读取次数衡量这段重复工作。完整 CPU 时间预算、GPU 时间及高速冷入停顿各自验收。[实际源码对照入口](../../../Tests/Validate-GlobalSdf.ps1)
