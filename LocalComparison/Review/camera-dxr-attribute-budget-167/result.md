# 相机状态重建时的 DXR 属性额度

同一 Feature 在 `maxCameras=1` 时会逐出当前状态，为下一台 Base 相机创建状态。旧 DXR 属性缓冲仍需等待退休围栏。相机再被选中时，旧版以新后端的局部账目准入，可能同时留下同一相机的两代属性。 [相机驱逐与创建](../../../Runtime/HybridLumenGIRendererFeature.cs) · [属性计费与释放](../../../Runtime/HybridLumenGIHardwareBackend.cs)

修复将属性账目保留在 Feature 的实际相机引用上。新旧后端为同一相机分配的属性都占用这份额度，释放成功后归还对应字节。另一台相机使用自己的属性账。RTAS 使用独立的共享预留。

## 同输入对照

现有 C# 宿主使用实际 DXR Backend 的准备、构建记录和 Dispose 入口。按 A、B、A 顺序模拟 Feature 驱逐，使用同一 3,000 三角输入和每相机 1 MiB 上限。退休票据的完成时机由宿主控制。

| 观察 | Release149 源码 | 修复后源码 |
| --- | --- | --- |
| 旧 A 尚在退休 | 576,196 B | 576,196 B |
| B 在 A 未完成时申请 | 独立准入 | 独立准入 |
| 返回 A，旧票据尚未完成 | 新分配 6 个缓冲，两代共 1,152,392 B | 拒绝精确 DXR 属性准入，零新分配，保留旧账 |
| 完成并释放旧缓冲后 | A 单代 576,196 B | A 恢复准入，单代 576,196 B |

对照支持 DXR 属性预算跨相机状态代次的托管准入。Feature 的相机身份接线经源码核对，围栏完成使用受控输入。实际双相机 GPU 成本、进程总显存及精确软件 BVH 的旧代额度各自验收。
