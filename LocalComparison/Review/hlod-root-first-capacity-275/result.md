# 冷近场根先绑定时的完整细节准入

一个独立分页 HLOD 组声明 32 个健康细节，场景容量为 32 槽。相机在近场，先只有粗根绑定，随后细节全部到达。Release225 允许根先通过原回执发布。细节到达后，准备流程先保留已发布根，剩余 31 槽无法容纳完整目标。在同一配置下，整组一直无法接替。

| 相同到达顺序 | Release225 | 修复后 |
| --- | --- | --- |
| 冷近场只有根绑定 | 根预热，完整回执后发布 1 个根 | 等待完整细节，0 个发布 |
| 32 个叶绑定，尚无叶就绪回执 | 1 个发布根，0 叶预热，`PendingCapacity` 为 1 | 0 个发布，32 叶预热，`PendingCapacity` 为 0 |
| 完整的当前细节回执 | 细节无法进入准备 | 32 叶一起发布，BVH 为 63 个节点 |

沿用现有实际 Scene／BVH／就绪表 C# 宿主，流式到达和回执由夹具控制。现有远场根、已发布组的原子接替、超总容量粗根回退、终止失败及过期回执均通过原用例。[实际宿主](../../../Tests/StandaloneBvh/HlodProgram.cs.txt) · [原发布条件](../../../Documentation/HlodStreaming.md#atomic-hlod-transactions)

关闭 T5／G4 中冷近场先到的根让恰好满槽的健康细节无法进入准备的路径。此顺序的首次显示可能延至叶齐并就绪。已发布远根转入满槽近景时仍受原共驻条件约束。其他资源容量、实际渲染及高速路线首显各自验收。[高速路线的原有范围](../cold-crossing-143/result.md)
