# 独立分页 HLOD 双相机普通画面对照

同一作者输入经默认独立导出器生成真实 AssetBundle。一个粗根和两个细节各占不同画面位置。两台 URP Base 相机用显式 `StandardRequest` 依次渲染 128×64 目标，显式观察点共同请求资源。两台相机先处于远侧，一台随后进入近侧，另一台保持远侧。画面按三个固定物体内部点与同帧灰背景的对比判定覆盖。使用 Unity 6000.0.85f1、URP 17.0.4、DX12 Editor 和软件 GI 路径。

| 阶段 | Release133 普通画面 | 最终候选普通画面 |
| --- | --- | --- |
| 两台相机起初都在远侧 | 两台都只画粗根 | 两台都只画粗根 |
| 近相机两片细节都已绑定，仍在预热 | 粗根和两片细节同画 | 只画粗根 |
| 稳定后同一引擎帧的近、远相机 | 两台都画粗根和两片细节 | 近相机只画两片细节，远相机只画粗根 |
| 停用一片细节后的下一次提交 | 此步用于候选的撤回检查 | 近相机撤回整个旧细节组，远相机仍画粗根 |

稳定帧的 GI 发布在两版中都是近相机两片细节、远相机一件粗根。最终候选在第 20 帧用粗根等待，在第 26 帧采到分歧的完整表示，在第 27 帧采到停叶后的整组撤回。帧号用于定位同次观察。准备中的对象定位失败与黑背景下无法判定覆盖的记录保留，采用的是灰背景控制有效的结果。[Release133 实录](<I:/Unity test/Comparison/IndependentRaster151Baseline/visible-result.json>) · [最终候选实录](<I:/Unity test/Comparison/IndependentRaster151Baseline/final-result.json>)

实际 Scene 的 CPU 回归另外覆盖相机错过一次完整解绑重绑、粗根不可用时拒绝细节走普通显隐回退，以及主动取消父级后的普通发布。同一输入下，首个候选会借旧代进入发布，并会显示仍有父级的单件细节。最终候选要求新代重新取得回执，拒绝该单件回退，同绑定的普通材质或姿态修订可保留可见性。原 Scene 组就绪和容量控制及分页绑定生命周期回归通过。[组事务验证入口](../../../Tests/Validate-HlodTransactions.ps1)

该结果覆盖实际分页、逐相机普通画面和受控位置的完整组切换。两台相机使用显式请求并由观察点保留需求。普通 Player、双相机并行需求撤回与原生退休、冷高速首显和性能预算分别验收。
