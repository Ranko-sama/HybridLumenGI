# 长条场景的 Far 书签落在实际可见远带

统一示例原先用 AABB 半对角计算 Far 机位。组沿横向很长而相机从短边看过去时，半对角远大于这个方向上的组边界。按 Far 会越过远景可见界，甚至越过加载界，粗根无法得到该机位的正常请求。

| 沿原观察方向的书签 | Release211 距实际包围盒 | 修复后 |
| --- | ---: | ---: |
| 合法长条组，半尺寸 `(30,1,1)`，near 12／far 40 | 47.033，越过 40 可见界及 45 加载界 | 18.000，超过 16.8 的细节请求退出阈值并位于可见带 |
| 随包 `NeutralThreeRooms` | 20.222 | 原位置逐分量一致 |

新生成的书签和使用 `GoFar` 的旧保存场景共用同一距离规则。越界时沿保存方向选带内位置，朝向组中心。已经在有效范围内的三室书签直接沿用保存的位置与朝向。比较用实际 C# 书签算式和等价向量／包围盒算术。采用范围为远景书签位置及请求资格。实际页到达、冷入首显和原高速路线继续验收。 [样例入口](../../../Runtime/HybridLumenGIUnifiedSample.cs) · [生成条件](../../../Editor/HybridLumenGIUnifiedSampleBuilder.cs)
