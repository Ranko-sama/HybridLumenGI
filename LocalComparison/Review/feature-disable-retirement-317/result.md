# 持续停用 Renderer Feature 后归还共享 RTAS 额度

原计划 T6／G4 的共享准入缺口。公开 `SetActive(false)` 后，URP 停止调度该 Feature。其页读者撤回，但同一 Renderer 上仍存活的相机不再进入原有的过期检查。旧相机的 RTAS 预约因此可持续占用全局额度，阻塞其他 Renderer 的合格请求。[相机管理](../../../Runtime/HybridLumenGIRendererFeature.cs) · [共享额度](../../../Runtime/HybridLumenGIRtasBudget.cs)

闲时检查现在也让已停用 Feature 的相机按原 **120 帧**保留期到期，使用现有相机和后端退休流程。实际注册、退休和共享预算代码在两个 Feature 的受控序列中运行，RTAS 额度设为 **1 MiB**，两边的请求各需 **642,560 B**。

| 事件 | 受控对照结果 |
| --- | --- |
| 短暂停用后重新启用 | 复用原相机状态和历史。 |
| 停用且距最后使用 120 帧 | 原状态仍在缓存，另一 Feature 的请求因共享额度不足而拒绝。 |
| 第 121 帧闲时检查 | 停用 Feature 的旧状态从活动列表撤出。旧相机资源及预约继续保留，另一 Feature 仍被拒绝。 |
| 相机状态退休完成 | 进入后端退休，原生预约仍在账上。 |
| 后端退休完成 | 归还 **642,560 B**。另一 Feature 的同一请求得到准入。重新启用后的新相机状态不受旧回调影响。 |

采用范围为停用后的缓存到期、受控完成与共享内存准入。原生 GPU 完成时序、真实进程显存和生产负载继续各自验收。本项是 Release253 之后的源码修复。
