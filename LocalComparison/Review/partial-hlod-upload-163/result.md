# 几何上传延后时的 HLOD 整组撤回

原计划 G4 要求 HLOD 始终按完整表示提交。一个已发布的三件近景组在同一帧有两件发生刚性位移。当几何额度只够重传一件时，Release145 在 `Scene.Prepare` 返回后仍让两件进入 GI 的实例表及 BVH。完整组查询已经无法返回原来的三件，追踪仍可消费部分表示。

修复按实际上传结果复核已发布组。若仍有缺件，在提交缓冲和 BVH 前撤回整组并使旧范围失效。仍属于当前目标的成员保留已经准备好的几何，作为预热成员等待当前回执。额度足够、全部修订能在本帧上传时，保持原来的完整发布和运动事件。

| 同一受控场景 | 实际 Scene／BVH 输出 |
| --- | --- |
| 两件位移，额度 1，Release145 | 两件可追踪，BVH 三节点。一件待上传。 |
| 两件位移，额度 1，修复后 | 可追踪成员归零。两件预热，一件待上传。旧三件范围均撤回。 |
| 等待的几何完成 | 单件新回执仍不足。完整组取得当前回执后三件一起重新发布。 |
| 两件位移，额度 2，修复后 | 三件一直完整发布。两处原姿态变更保留。 |

宿主编译真实 Scene、BVH 与就绪逻辑，代理、图形资源和回执由适配器提供。结论覆盖预算执行后的 CPU 发布及追踪资格。实际普通 Player 的画面、GPU 缓存完成和原高速冷入首显分别验收。[现有事务回归](../../../Tests/StandaloneBvh/HlodProgram.cs.txt) · [实际 Scene](../../../Runtime/HybridLumenGIScene.cs)
