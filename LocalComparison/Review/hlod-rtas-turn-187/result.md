# HLOD 接替等待共享 RTAS 构建名额

Release162 的两台 Base 相机在设置固定且每帧只有一个 RTAS 构建名额时，可以先撤下粗根，再因名额耗尽回退到软件追踪。两件新细节已经在世界 BVH，但新缓存代次的照明年龄各为 1，低于原就绪门 2。[旧版实机反例](../hlod-backend-handoff-186/result.md)

在已经录制 DXR 的相机中，如果当前接替会移除实际精确成员，目标已就绪且至少一件仍符合后端的精确几何资格和三角预算，那么耗尽的正构建额度会延后接替。相机保留旧组并成功录制当前 DXR 后才进入原队列，实际构建时仍按原规则计算次数、三角和实例工作量。目标取消、预热资源失效或当前 DXR 丢失时，撤销该等待意图。只支持图卡预热、无法进入精确几何计划的目标不会用这个等待入口。

Unity 6000.0.85f1、URP 17.0.4、DX12 Editor，继续使用原反例的主相机场景、两台手动 Base 和一个共享名额。扩展序列给竞争相机增加一个独立远处对象，使它可以在后续帧提出真正的新构建需求。该对象始终在主相机的常驻范围外。[最终版实机读回](fixed.json)

| 引擎帧 | 顺序与观察 |
| ---: | --- |
| 13 | 竞争相机用完名额。主相机保持粗根在世界 BVH 和实际 DXR，缓存代次仍为 5。两件细节继续预热，原卡的当前缓存年龄各为 4，队列中有一个待建意图。 |
| 14 | 主相机先取消接替，待建意图归零，粗根保持原 DXR。竞争相机随后使用当帧唯一名额。 |
| 17 | 主相机重新取得两件细节的真实回执，竞争相机再次用完名额。粗根保持，主相机进入队列。 |
| 18 | 竞争相机仍先提交，按原年龄规则让出名额。主相机录制当帧唯一构建，两件细节一起接替。实际 DXR 和缓存代次 5 保持，两张原卡各满足当前照明年龄 2。 |

采用范围是具有可准入精确目标的完整接替在正共享构建次数耗尽时的连续覆盖、等待进展和取消。原队列沿用相邻帧需求的年龄规则。其他后端回退原因、混合近似接替、高速冷入首显、普通光栅和生产负载继续按各自条件验收。
