# 撤回分页需求后停止启动仅为保留而标记的依赖

材质包文件先启动，依赖纹理尚未读取。调用 `RemoveRequests` 撤回材质需求后，已启动的文件仍须等实际完成。Release212 把为此保留的依赖也当作新加载需求，纹理占用当步唯一启动名额，另一页继续等待。

修复先记录实时请求及其传递依赖，再合并在途操作、租约和包保留。新文件读取与资产加载只依照前者准入。已有操作继续轮询，父页和依赖沿用原完成门退休。

| 撤回后的同一步 | Release212 | 修复版 |
| --- | --- | --- |
| 原材质包 | 文件仍在途 | 文件仍在途，代次保留 |
| 无人请求的依赖纹理 | 开始读取 | 保持未加载 |
| 仍有需求的健康页 | 等待 | 开始读取 |

修复版还确认原材质包在释放确认前继续占用额度，确认后归还。再次请求可取得新代次，材质、依赖纹理及健康页均就绪。原夹具的共用依赖与失败包释放路径继续通过。

对照使用实际分页 Driver 和调度器，文件、资产与释放回执由 C# 夹具控制。结论限于新加载准入和已有退休行为。原生 I/O 延迟、高速冷入首显和完整流式负载仍待验收。 [同输入夹具](../../../Tests/StandaloneStreamedRepresentation/Program.cs.txt) · [分页调度](../../../Runtime/HybridLumenGIAssetPageStreaming.cs)
