# 精确命中的足迹依赖与资源页准入

## 足迹缺失时的精确命中

在 Unity 6000.0.85f1、DX12、RTX 2080 Ti 上复用原二值裁剪观察入口。三个并排的普通 Lit 前板共用真实 Ready 的 Point／Clamp 无 mip 棋盘纹理，后方是无贴图蓝面。两个标量覆盖前板启用 Albedo Alpha 平滑度，`_BaseColor.a` 分别为 0.25 和 0.75，cutoff 都是 0.5。第三块前板使用普通纹理裁剪。旧版与候选共用同一份几何、材质和纹理批次，在一个实际命令中各经精确软件 BVH 和 DXR 遍历。射线起点和足迹由观察器给定。

| 固定输入 | Release137，两个后端各自结果 | 修复后，两个后端各自结果 |
| --- | --- | --- |
| 无足迹，标量透明 | 前板 t=1，未知遮挡 | 蓝后面 t=2，材质已知，蓝色漫反射 0.96 |
| 无足迹，标量实心，只查可见性 | 前板 t=1，覆盖未知 | 前板 t=1，覆盖已知 |
| 起点足迹无效，裁剪需要纹理 | 前板 t=1，覆盖未知 | 前板 t=1，仍保守阻挡 |
| 同一纹理透明点，足迹有效 | 蓝后面 t=2，材质已知 | 蓝后面 t=2，材质已知 |

第三行使用会让数值半径在传播后变正的斜率，确认无效起点仍不能参与采样。原始记录保存了每条射线的来源身份、距离、UV 和命中标志。此对照覆盖受控足迹输入、已准备好的 Lit 材质及双后端实际候选遍历。真实窄接收面的屏幕足迹生成、后层 SDF／解析、普通 Player 画面和正式性能仍分别验收。[实机读回](<I:/Unity test/Comparison/ExactFootprint155/result.json>)

## 收紧启动预算后的资源页准入

实际页调度器使用既有异步 Provider 替身。共享页已为 Ready 且由原组持有租约，收紧每步文件和上传额度后，请求复用该页的新组。旧版按共享页历史成本拒绝新组，新组的小页持续未加载。修复后只检查仍需启动的小页，顺利取得 Ready，共享页沿用原租约且只加载过一次。包、驻留、在途的模型字节分别为 11、22、0。

另一输入在文件读取已经结束后将文件额度降为零。旧版仍要求文件准入，修复后 `BundleReady` 只使用剩余上传额度，上传与重新准入的门槛按实际阶段生效。总容量、真正的在途记账和退休后重新加载的保护继续成立。此项证据限于实际 CPU 调度与受控 I/O 完成。[定向回归](../../../Tests/StandaloneBvh/AssetPageStreamingChecks.cs.txt)
