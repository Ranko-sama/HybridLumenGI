# 两骨门的 SDF 烘焙去除重复计算

已有普通 Player 的并发门运动记录中，194 份新快照能配对捕获源、仍等待同一作业的末源及首个完整 CPU 观察。捕获源到完整观察的中位为 176.80 ms，p95 为 202.20 ms。这个间隔包含后台调度、执行和相机观察边界，构成缩短形变准备的依据。[原实际负载](../combined-update-cost-285/result.md) · [本机逐源记录](<I:/Unity test/Comparison/CombinedUpdateCost285/run/frames.jsonl>)

本次用 Release235 保存三室的真实示例门与 `BakeMesh(false)`，将上骨固定在 15°。两侧共享同一份 24 顶点、12 三角的复制数组，在同一 Unity Editor 进程的一个 Task 工作线程上依次执行 SDF32 核。计时从进入 Bake 到返回，覆盖 BVH 构建、闭合判断和全部体素计算。每侧各预热一次，随后交替执行五组同输入旧版和候选。[原始结果](result.json)

| 固定输入 | 旧版 | 修复后 |
| --- | ---: | ---: |
| 完整 SDF 烘焙中位 | 135.317 ms | 99.627 ms |
| 组内极差 | 8.782 ms | 1.090 ms |
| 闭合与边界 | 闭合，原边界 | 逐值一致 |
| 全部 32,768 个体素 | 7,020 个内部样本 | 逐位一致 |

配对中位节省 **35.732 ms**，中位耗时降低 **26.38%**。达到事前保留线，即同对中位至少节省 33.333 ms、相对中位至少降低 20%，且绝对收益超过两侧组内极差。

最近距离遍历复用同一点已算出的子包围盒距离，沿用原裁剪和访问顺序。三角边在冻结几何时计算一次。闭合网格在叶顺序确定后为三个原判内方向各保存一次交点不变量，后续体素继续执行原重心和距离检查。闭合烘焙会增加这部分临时三角数据。采样点、SDF 分辨率和 Mesh／SDF／图卡的完整发布规则继续按原合同执行。[烘焙实现](../../../Runtime/HybridLumenGIMeshSdfBake.cs)
