# 低额度开帧时保留材质贴图的有效等待

原计划 T6／G4 的材质上传公平性修复。高额度帧按固定顺序渲染 A、B，两台相机各需一次 2 MiB 的动态贴图整页复制。A 录满后，B 取得下一预计帧的等待。周期相机 C 在下一帧首先将共享额度设为 1 MiB，并录制自己的小页。Release256 在低额度开帧时丢掉 B 的等待。B 本帧整页装不下，也无法登记新等待。交替运行时每个高额度帧都由 A 抢先录满。[普通相机录制入口](../../../Runtime/HybridLumenGIRendererFeature.cs) · [历史同帧收紧对照](../texture-quota-tightening-254/result.md)

修复让超出当帧上限的已登记等待暂留至预计返回帧结束，期间占用零字节。只有同一来源和消费者实际重新请求整页才携原顺位进入下一预计返回帧。缺席会过期，能装入额度的普通等待仍可独立竞争。[实际准入](../../../Runtime/HybridLumenGIRayTexturePool.cs)

| 同输入的 Batch／Pool 命令录制 | Release256 | 修复后 |
| --- | --- | --- |
| 首个高额度帧 | A 复制 2 MiB，B 等待 | 相同 |
| 首调用为 1 MiB 的低帧 | C 复制 1 MiB，A／B 均延期 | 相同，B 的活跃等待续期 |
| 回到 2 MiB 的高帧 | A 再复制 2 MiB，B 仍无当前贴图句柄 | B 复制完整 2 MiB 并得到当前句柄 |
| B 在预计低额度帧缺席 | — | 其等待过期，恢复高帧时 A 可复制整页 |

同一 C# 夹具执行生产 Batch 和 Pool 源码。旧版在恢复高帧按预期触发回归断言，候选通过。既有同帧收紧、录制时间准入、周期回返及读者在飞续期用例通过。采用限实际准入与命令录制决定，完成栅栏与贴图回读由夹具控制。原生多相机图像、执行成本和完整生产负载仍待验收。[定向回归](../../../Tests/StandaloneHitMaterialBatch/Program.cs.txt) · [旧版输出](baseline.txt) · [候选输出](candidate.txt)
