# 形变工作槽的失败隔离

T3／T6 的实际组件对照使用一个共享工作槽和两个可读网格。先停用正在烘焙的网格，第二个网格等待它实际结束。完成后，在普通 `BeginContext` 中注入一次私有快照销毁异常。

Release238 保留失败快照，同时堵住唯一工作槽。第二个网格一直无法开始捕获。Release239 在作业结束前仍遵守单槽上限，清理失败后，第二个网格在剩余配额内取得工作槽并一起发布 Mesh、SDF 和图卡。失败作业保留同一所有者，原对象重新启用后仍受在途约束。另一快照安全退休后，账面剩余字节等于失败快照原预留。跨会话总共尝试销毁一次。

对照使用实际 C# 组件、受控 `Task.Run` 完成和模拟 Unity 接口。结果覆盖调度与保留状态。实际引擎的形变画质、原生退休和消费延迟继续按原计划验收。[定向对照入口](../../../Tests/StandaloneDeformedMesh/Program.cs.txt)
