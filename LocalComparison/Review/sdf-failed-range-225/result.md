# 对象 SDF 上传失败后的区间回收

默认对象 SDF 图集可容纳八个 64³ 体素卷。用实际 `PrepareForFrame` 逐帧装满后更新其中一个卷的纹理版本。受控提供器让该卷的 `SetData` 和随后的元数据撤销各失败一次。其他卷的来源保持有效。失败版本仍有需求时，引入第九个健康卷。

| 同一输入 | 失败后的元数据提交 | 撤销重试后占用 | 下一帧健康卷 |
| --- | --- | ---: | --- |
| Release192 | CPU 镜像已更新，跳过重传 | 2,097,152 体素 | 仍回退，上传 0 |
| Release193 | 重传成功后归还失败区间 | 1,835,008 体素 | 上传 262,144 体素并就绪 |

体素写入尝试仍扣当帧共享额度。元数据写入返回成功后才提交 CPU 镜像。遇到元数据写入异常时，下一次准备重传完整表，待撤销的区间保留到提交成功。已失败的纹理版本保持解析回退。健康卷撤回后，原失败纹理的新版本从原准入入口重新取得可用区间并完成上传。

实际源码对照使用受控的纹理和缓冲 API。七个持续有效卷均保留就绪资格，图集分配容量相同。Astra Max 同意按逻辑区间与提交状态采用。活卷导致的一般碎片化仍受连续区间条件约束，真实驱动异常与进程显存继续按原范围验收。[定向对照](../../../Tests/StandaloneSdfAtlas/Program.cs.txt) · [驻留与上传合同](../../../Documentation/SdfAtlasResidency.md)
