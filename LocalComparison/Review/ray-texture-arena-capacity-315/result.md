# 精确材质贴图池在 arena 数量上限下继续推进

原计划 T6／G4 的资源准入缺口。精确材质批只在一个物理 arena 内借用贴图页。旧版找不到可复用布局时只按字节回收，随后检查物理 arena 数量。缓存达到 128 个后，即使有安全可回收的 arena，新材质也可能一直被拒绝。实际 Renderer Feature 在材质准备失败时走已有 SDF／解析后备。[池准入](../../../Runtime/HybridLumenGIRayTexturePool.cs) · [后端入口](../../../Runtime/HybridLumenGIRendererFeature.cs)

复用既有实际 Pool 源码宿主。每批两张不同的 1×1 稳定纹理，已有 arena 只剩一页预留。128 个 arena 的逻辑计账为 **104,448 B**，低于 **1 MiB** 设置。消费栅栏、上传录制和元数据回读使用原受控适配器。

| 同一批请求 | Release251 | 修复后 |
| --- | --- | --- |
| 所有 arena 仍有待定读回 | 拒绝新批 | 拒绝新批 |
| 唯一完成读回的 arena 正被匹配批借用 | 匹配批无复制，额外新批拒绝 | 相同 |
| 匹配批释放读者后再次请求同一新批 | 报 arena 数量或代次空间耗尽 | 释放唯一空闲 arena，保留其余 127 份读回，新批取得原有额度 |
| 新批录制并完成回读 | 先前已拒绝 | 数量和字节仍为 128／104,448 B。旧句柄拒绝，新页可复用 |

新 arena 准入使用原回收顺序同时预留数量和字节。只有读者和回读均完成且成功销毁的 arena 才归还账目，继续使用原 generation 检查。采用范围限受控资源生命周期和数量压力下的推进。进程显存、真实 GPU 传输、实际后端画面和冷高速首显继续各自验收。[定向组件用例](../../../Tests/StandaloneRayTexturePool/Program.cs.txt)
