# 周期相机取得 RTAS 构建机会

两台相机都可准备合格的精确几何。每引擎帧只有一个共享 RTAS 构建名额，第一台每帧先准备新的位姿，第二台每两个引擎帧提交一次。旧版在第二台缺席的帧仍为它保留顺位，却在它返回前移除请求。第二台在五次实际准备后均未录制构建，第一台也在中间帧因等待而没有录制。

等待顺序现在使用后端最近两次合格准备的间隔。请求在实际调用帧及下一预计返回帧参与准入。预计帧过去后，缺席请求从队列过期。实际录制仍复核来源、内存、突发上限和工作余额。

| 同一实际 Backend 宿主 | Release221 旧行为 | 修复后 |
| --- | --- | --- |
| 两帧周期相机的首次构建 | 帧 0、2、4、6、8 都延期，构建调用为 0 | 帧 4 首次录制并可供当前后端派发 |
| 高频相机在帧 3、5、7、9 | 帧 3、5、7 因旧顺位延期 | 四帧都录制当前位姿 |
| 周期相机在帧 6 申请新位姿，随后缺席 | — | 帧 8 等待，帧 9 高频相机恢复构建 |
| 每帧实际录制与计费 | 构建次数至多 1 | 构建次数至多 1，每次计 2 三角、1 实例，无录制帧计费为 0 |

对照使用实际 `HybridLumenGIHardwareBackend` 与 `HybridLumenGIRtasBudget`，Unity 资源和命令 API 由现有 C# 宿主提供。原 HLOD 等候、撤回、额度复核和安全退休的宿主回归通过。帧号为受控序列相对帧。[实际 Backend 对照](../../../Tests/StandaloneHardwareBackend/Program.cs.txt) · [原 HLOD 等候与撤回依据](../hlod-rtas-turn-187/result.md)
