# 软件三角 BVH 同轴排序候选

精确软件后端的网格位姿更新会推进几何代次，Feature 随后同步重建整份三角 BVH。候选仅在一次完整构建内复用父节点的排序。子树沿相同轴分割时，它已经处于按中心和唯一叶索引确定的顺序。分割轴变化时仍调用原排序。源码路径为当前 [Feature 准备](../../../Runtime/HybridLumenGIRendererFeature.cs)和[三角 BVH](../../../Runtime/HybridLumenGISoftwareTriangleBvh.cs)。

采用线预先定为比较调用至少减少三分之一，并要求完整节点和叶一致。复用相机软件额度的 C# 宿主，通过实际 Feature 准入和精确属性准备，从两张有各自姿态的网格取得 4,096 个三角，再把同一准备好的来源交给 Release215 和候选 builder。Unity 网格及缓冲使用原受控适配器。首个位姿的 8,191 个节点与 4,096 个叶完成逐字段对照，顺序、包围盒、逃逸链接、坐标和来源索引一致。

| 首个位姿的实际排序工作 | Release215 | 候选 |
| --- | ---: | ---: |
| `Array.Sort` 调用 | 4,095 | 2,595 |
| 中心与叶索引比较调用 | 294,637 | 246,121 |

比较调用减少 **16.47%**，低于采用线。原运行在该条件处停止，计划中的移动位姿没有执行。候选已撤回。这个结果限于受控输入的 CPU 排序工作量。高更新下的完整同步重建、实机 CPU 耗时和精确软件 GPU 的 25 ms 时间门继续按原计划处理。
