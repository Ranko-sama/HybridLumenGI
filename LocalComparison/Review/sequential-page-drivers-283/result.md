# 流式场景组停用后的预算接管

官方导出可生成各自带页驱动的独立场景组，正常使用时每次只启用一套。旧驱动即使随场景组停用，仍保留进程的全局 I/O 所有权，直到组件被销毁。第二套驱动因此在正常启用时被拒绝。

修复后，停用的驱动暂停新页准入，继续处理已经发出的操作和读者退休。包、驻留、在途操作和退休租约全部排空后，等待的驱动才取得全局所有权。先前停用的驱动可在下次启用时重新取得所有权并加载新页代次。活动驱动持有期间仍独占准入。

| 同一组件对照 | 实际结果 |
| --- | --- |
| A 活动时尝试启用 B | 拒绝 B，A 保持准入 |
| A 停用时有一个包读取和两份租约 | B 等待，旧 I/O 和租约继续计账 |
| 读取完成，读者仍在使用旧页 | B 继续等待，两份租约仍保留 |
| 原票据完成且 A 的账目排空 | B 取得准入并把自己的页加载到 Ready |
| 停用 B，再启用 A | B 释放页，A 重新取得准入并开始新几何页代次 |

采用范围为原 G4 的独立导出场景组顺序接管。对照由现有 `Validate-ChunkStreaming.ps1 -RepresentationOnly` 宿主执行实际驱动、表示和页调度，使用受控 Unity 对象、I/O 和读者完成。旧 Runtime 在 A 停用后仍报单驱动冲突，失败宿主报错后由主线程关闭。候选宿主返回 0，包含原销毁后清理路径。原生 AssetBundle I/O、GPU 退休与高速首显继续按原条件验收。[定向回归](../../../Tests/StandaloneStreamedRepresentation/Program.cs.txt)
