# 统一示例在当前 HLOD 发布撤回后的显隐

统一示例根据上次相机结束时接受的完整发布设置普通 Renderer 的显隐。Release160 收到当前相机的 Warming 回执后只更新说明文字。同一批流式绑定仍然有效时，已被 GI 撤回的细节组继续具备普通绘制资格。修复在当前准备没有完整可用发布时清除整组显隐，下一次相机使用更新后的资格。当前仍有效的完整旧组可以继续等待替换，未取得当前准备时沿用原等待规则。

用 Release160 保存的统一示例做同输入前后对照。固定近景机位，以单 Game Base 相机显式提交 128×64 目标，使用 Unity 6000.0.85f1、URP 17.0.4 和 DX12 Editor。三件细节已经实际发布后，将实例容量由 64 改为 63，场景重新初始化。粗根和三个细节的绑定始终有效，代次均为 1。观察端点均实际记录 DXR，使用真实页和照明回执。[Release160 读数](baseline.json) · [候选读数](fixed.json)

| GI 工作帧 | 当前发布细节数 | Release160 相机开始／结束可提交数 | 候选相机开始／结束可提交数 |
| ---: | ---: | ---: | ---: |
| 18，完整发布 | 3 | 3／3 | 3／3 |
| 19，调整容量后撤回 | 0 | 3／3 | 3／0 |
| 20，下一相机仍在预热 | 0 | 3／3 | 0／0 |
| 36，重新完整发布 | 3 | 3／3 | 0／3 |
| 37，下一相机 | 3 | 3／3 | 3／3 |

候选在重新发布前的其余观察帧也保持整组隐藏。状态取实际 Renderer 的启用、对象活动和 forceRenderingOff，反映普通绘制资格。撤回当帧仍按相机开始时已接受的完整集合裁剪，显隐变化在该相机结束时生效。两次 Unity 均正常退出 0。结果限统一示例单相机、同绑定容量重置后的整组隐藏与恢复。像素覆盖、普通 Player 和高速冷入首显分别验收。[几何上传超额时的 Scene 整组撤回](../partial-hlod-upload-163/result.md)
