# Global SDF 复用已录制的页和层数据

原计划第 5 节／T6 的上传工作。旧版每次 `RecordUpdate` 都录制页表、层和对象 bounds 的全量上传，即使页面没有变化且没有砖作业。统一示例保存配置为 4 层、每层 8³ 个砖和 64 个场景槽位。稳定无作业时省去 `2048 × 32 + 4 × 32 + 64 × 32 = 67,712 B` 的录制载荷，每台相机各自复用。原软件近景实测的两个端点均为 2,048 个就绪砖和 0 个待处理或更新砖。[已有近景窗口](../software-bvh-sah-291/result.md)

页失效、滑移或缓冲换代仍在原命令流记录页和层数据。对象 bounds 供合并使用，与砖作业一起录制。已有 GPU 发布步骤会更新持久页表的 ready 位，失效后的重录沿用原失败出口和代次规则。

| 现有 Global SDF 组件入口 | 实际录制结果 |
| --- | --- |
| 首次及缓冲换代 | 建立有效初始页表，原命令顺序和退休条件通过 |
| 无变更的积压 | 录制当前 bounds、作业、合并和发布，沿用页表与层数据 |
| 无变更且无作业 | 录制事件为空 |
| 滑移后两次准备、重建额度为零 | 页和层照常上传，重叠砖保留原代次及就绪 |
| 现有失败出口丢弃命令流 | 128 个砖推进代次，按原额度完整重录，之后稳定 |

执行 `Tests/Validate-GlobalSdf.ps1 -CpuOnly -FailureRecovery -ExpectRecovery`。首次编译发现既有失败适配器缺少图卡撤销依赖，补齐替身后通过。采用范围为实际 C# 录制行为和逻辑载荷。驱动传输量、原生耗时以及软件 GI 的 25 ms 放行仍各自验收。[组件入口](../../../Tests/Validate-GlobalSdf.ps1)
